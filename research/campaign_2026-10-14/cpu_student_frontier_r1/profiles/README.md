# Student shape profile artifacts

This folder holds bounded profile contracts, preflights, GPU receipts, and copied controller attempt records. The first admitted H192×2 profile used one real clean-F0 sequence, copied only the H256 control's fitting-derived 211-feature mean/std, and made one FP32 update over rows 0–1999. A source-qualification bug invalidated its claimed sampler-order linkage; see the [correction](PROFILE_SOURCE_QUALIFICATION_CORRECTION_R1.md). That run remains a one-sequence resource/finite-update check only.

- [H192×2 one-sequence profile contract](PROFILE_H192L2_B1_C2000_FP32_CONTRACT_R1.json) and frozen [profile harness](../../../../scripts/profile_student_frontier.py) preserve the original single-sequence probe's source and settings. The contract's exact-order claim is superseded by the [source-qualification correction](PROFILE_SOURCE_QUALIFICATION_CORRECTION_R1.md); the original cache's historical H256×2/B16/C2000/six-epoch contract remains unchanged.
- [CPU-only producer preflight](PROFILE_H192L2_B1_C2000_FP32_PREFLIGHT_R1.json) checked the actual F0 train group 37 (`seq_ix=7598721`) as one clean fitting row and recorded an unqualified sampler-group list. It did not verify source-qualified sampler membership; no CUDA update or quality evaluation was performed. Its peak process RSS was 1.599 GB. The [correction](PROFILE_SOURCE_QUALIFICATION_CORRECTION_R1.md) retracts the exact-order interpretation.
- [GPU one-sequence result](PROFILE_H192L2_B1_C2000_FP32_GPU_R1.json) records a successful finite FP32 AdamW update in 1.86 s on an RTX 3060 Laptop GPU. Parameters changed and remained finite. Harness CUDA peak allocation/reservation was 117/145 MB, while the worker's peak host charge was 2.092 GB. `nvidia-smi` read 75.9 MB before and 416.9 MB after the update; this is the single-sequence probe only, not the full fitting batch or an architecture-capacity bound.
- [Durable controller attempt receipt](PROFILE_H192L2_B1_C2000_FP32_ATTEMPT_R1.json) is copied from the shared campaign runtime; it records terminal exit 0, a 3 GB memory maximum, a 1 CPU quota, zero swap, 2.092 GB peak host charge and 76 MiB sampled peak observed VRAM. [Worker log](PROFILE_H192L2_B1_C2000_FP32_ATTEMPT_R1.log) contains the completion record. Root admitted and launched this probe; the actor did not launch it.

The profile does not recompute the 1.69 GB target array's whole-file hash. It binds the producer metadata's expected file SHA, validates its exact ordered fitting row-group list and hashes the sampled target row. The later fit path must still call the unchanged strict cache validator and require its `verified_files` payload hashes. The input contract caps cache-metadata reads at 512,000 bytes before parsing. A source split manifest is currently read through the existing unbounded split loader (pinned file is 1.39 MB); the independent reviewer recorded this as a nonblocking residual for the resource smoke.

The [corrected batch-16 profile packet](PROFILE_B16_LADDER_R1_README.md) now passes its CPU preflight: all first-16 `(source, row_group, seq_ix)` positions, every cache row under its source-local key, and the unchanged strict producer validator are checked. Its B16 CUDA profile remains unlaunched because the largest shapes still need a measured resource envelope. The [staged H640×1/H448×3 B1 packet](PROFILE_H640L1_H448L3_B1_C2000_FP32_RESOURCE_R1_README.md) binds the first source-qualified row and is ready for root admission; it is resource evidence only. The earlier [H640×1-only CPU preflight](PROFILE_H640L1_B1_C2000_FP32_RESOURCE_R1_PREFLIGHT.json) is retained as a successful narrower precursor to the two-shape packet.
