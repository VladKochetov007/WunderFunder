# Seed-3 complete-component initializer screen

This packet freezes a bounded initializer-only subset screen after the H256×2 seed-3 control. It compares the frozen zero-state parent with learned constant, first-row and prefix initializers on the same fixed F0 fitting membership and sample order. The screen is proposal/recipe evidence only: no subset fit, prediction or grade has run, and F0's 468-group panel is already exposed development evidence.

The canonical [subset manifest](FIT_COMPONENTS_TARGET256_SEED3_R1.json) was selected from the 3,148 eligible components in the source-qualified F0 split (`09263ad4fe2b18e2b2f3b79f4562678dce801b067b868134ddc79279f9316a3d`). `numpy.random.default_rng(3)` permutes sorted eligible component IDs; the shortest prefix reaching 256 fitting sequences yields 82 complete components and 258 sequences: 228 train-source and 30 fit-valid-source groups. Each group is a complete 20,000-row sequence. The subset covers 2.16% of the 11,940 fit groups; all selected members and the per-arm update order are explicitly listed and hashed. The builder and the pinned producer subset validator both check whole-component membership and disjointness from the fixed 468-group evaluation components.

The first builder output [is preserved as a noncanonical draft](FIT_COMPONENTS_384_SEED3_R1.json). Its metadata declared a 384-sequence target but the implementation stopped at the 256-sequence floor and selected 258; [the repair receipt](BUILD_THRESHOLD_MISMATCH_R1.json) binds the builder/output hashes and marks it ineligible for fitting. The canonical contract instead names 256 as its target, keeps the same seed-3 membership, and records the corrected stopping rule. No file was overwritten.

All learned arms start from the same audited H256×2 seed-3 `model_ep0.pt` (SHA256 `1baa583573089da3eec02bee9256c32e3caeae59e15f77c7475eea0717f006e6`) and copy only its 211-feature mean/std; normalization hashes are `bb85c72b87656979f97c1786400aec6bc9e43acd337078000eb482c09c5a2da8` and `b730600851e52e246fc638230844d6e4f2828e4972b45db1f0128cce4e4454c5`. The clean homogeneous target cache, source-qualified F0 group sets and three clean teacher checkpoints are pinned through the [R2 actual-data profile contract](../../profiles/INITIALIZER_COMPLETE_SEQUENCE_B1_R2_CONTRACT.json) and its strict B8 cache/order validator. The teacher saw the full F0 fitting pool, while its clean ancestry excludes the fixed evaluation components; therefore this student subset does not test limiting teacher training membership or represent a from-scratch small-data run.

The proposed update is one AdamW update per selected complete sequence for each learned arm: 258 attempted and completed FP32 updates, batch 1, ten C2000 chunks with checkpointed recurrent graph, no hidden-state detach, no AMP/TF32, constant LR `1e-4`, betas `(0.9, 0.999)`, epsilon `1e-8`, weight decay `0.01`, global gradient clip `1.0`, and no scheduler. For each sequence the fixed target is `0.1*clamp(label,-2,2) + 0.9*clamp(clean homogeneous teacher,-2,2)`; weights are `abs(clamp(label,-2,2))` times production `main_row_weights` using the pinned propensity cache (`p² + 0.03`, true-mask epsilon `0.03`). Rows 0–98 are processed causally with zero loss. `initializer_sequence_loss` normalizes by that sequence's total weight, so each sequence contributes one update. Zero remains the unmodified CP0 backbone. No model, learning rate, checkpoint or arm is selected from validation during fitting.

Before any subset fit, root must admit and collect the R2 one-sequence resource profile, and the profile's actual learned initializer exports must pass an additional [C++ native-consumer gate](NATIVE_PROFILE_GATE_R1.md). The gate checks the concrete exported constant/first-row/prefix payloads and reset/trace parity on the source-qualified profile sequence; synthetic parser tests alone are not the gate. Each subset fit must retain a finite terminal checkpoint and native initializer payload. Predictions then cover `cache/valid_targets.npz` row order, while scoring uses only the frozen 468 evaluation groups and component bootstrap against the zero parent. The five fixed position bins are rows 99–199, 200–999, 1,000–4,999, 5,000–9,999 and 10,000–19,999. These are diagnostic exposures, not separate selection gates.

The recipe uses the existing official `global_wp_clip2_v1` scorer and paired component-bootstrap machinery. It records source-qualified fit membership, one common fit-order digest, direct/teacher/propensity ancestry, profile/native gate identities, every completed update, finite final tensors, reset/reload checks, full native payload parsing and full-panel prediction hashes. The proposed resource envelope is 5 GB host reservation, 3.5 GB PyTorch allocator cap and a 5 GB observed-VRAM ceiling. The actual R2 resource profile is still pending; root must compare its terminal measurements with these bounds before admitting any fit or prediction. A subset score is a low-fidelity screen conditioned on the full-data teacher/backbone and exposed F0 evaluation panel, not a full-fit ranking or clean holdout.
