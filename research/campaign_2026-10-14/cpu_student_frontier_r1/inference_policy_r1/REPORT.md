# xteam_h4 CPU policies — measured report R1

This implementation compares four serving policies for the original four-member xteam_h4 Q8 package. The source archive is the unchanged `artifacts/team_models_20261013/xteam_h4.zip` (SHA-256 `f1635d14c0e1b47848b5caeb2ec4ad9362a85800f1b2e2df80702127d3867b27`). It contains four ordered, separately weighted members at coefficient 0.25 each, using `q8vnni`. All package derivatives retain member order and bytes, coefficients, GRU/head dimensions, preprocessing, callback, Q8 codes and scales, and activation quantization. The only policy changes are native execution and a package-level assertion that the chosen precision is the one recorded in `precision.txt`.

Policy A is the frozen shipped q8vnni control. B dispatches to an EVEX256 AVX-512 VNNI kernel and refuses ISA fallback; the disassembly has `vpdpbusd ymm` instructions. C uses a four-accumulator register-blocked AVX-512 VNNI matrix schedule. D fuses the paired input/recurrent projections while retaining their separate Q8 scales and bias terms and reading the old recurrent state for both projections. D is currently restricted to GRU policies. `native/src/vnni.rs` contains the kernels and bounded parity tests; `native/src/rnn_fast.rs` contains strict policy dispatch and recurrent integration; `native/src/python.rs` exposes policy selection to the package callback.

The native library was built on top of source revision `7800d30473e3810e12d9ba22596f9fd6df5626ca`, using rustc/cargo 1.94.0, one Cargo job, one CPU, 1.5 GB memory maximum and no swap. The shared library is 1,123,456 bytes, SHA-256 `cd8b9692d102e5173fbe3b89a15373dcccb63382892f7621c0b2a1382f0ba362`. `cargo check --lib --features extension-module`, the release extension build, and the release `bench_int8` profile build passed. `cargo test --manifest-path native/Cargo.toml --lib` passed 58 tests, with one ignored and no failures (45.43 s); the captured output is in `probes/CARGO_TEST_R1.log`. Ruff format/check passed for the three Python scripts. `rustfmt --check` reports formatting differences in the four touched Rust files, and the same check also reports existing differences in the unmodified base-revision versions; no broad formatting rewrite was applied. The `RESULTS_R1.json` and `PACKAGE_MANIFEST_R1.json` bind native-source, campaign-script, archive and library hashes.

The bounded matrix probe tested all 24 matrices in the four original members. With `--reps 3`, the alternating-order harness collected six timed samples per policy and matrix and required bitwise equality to the integer reference on every run. For the 16 recurrent 768×256 matrices, median kernel time was 1.2495 μs for A's VNNI512, 3.081 μs for B's VNNI256 and 1.7595 μs for C's blocked schedule. Including the eight head matrices, the corresponding medians were 1.2295, 3.0250 and 1.7355 μs. The raw timings and exactness assertions are in `probes/MATRIX_R1.log`.

The cell probe ran one warm whole sequence followed by one instrumented 20,000-row sequence with all four original weights. It reported 114.05 μs/row for A, 178.65 for B, 138.27 for C and 115.54 for D. D merges the paired recurrent projection slots: the measured pair fell from 94,612 to 94,520 TSC/row in layer one and from 92,621 to 92,482 in layer two, a roughly 0.1% change within the noise of this single profile. This probe does not establish a cell-level speed win. Full logs are `probes/CELL_{A,B,C,D}_R1.log`.

The complete callback probe used Python 3.11.16 on one pinned logical CPU of an Intel Core i9-11900H, with the official xteam_h4 feature/sequence replay and both 20,000-row validation sequences (row groups 0 and 1). It ran in A→B→C→D→A order; every variant also replayed each sequence from a fresh model. Selected-policy assertions passed. All four predictions were bitwise equal to A on both sequences, and every fresh-reset replay was bitwise equal. The final A callback reproduced the first A prediction arrays bit for bit. Separately, a rebuilt-A package using the newly compiled native library and the same package policy assertions matched original A bit for bit on both complete sequences and passed the fresh-reset checks. This supports exact prediction parity for the tested complete sequences; it is not an all-input proof or a competition-host timing claim.

Mean measured callback seconds per 20,000-row sequence were 2.039 for the first A, 3.056 for B, 2.422 for C, 2.177 for D and 2.098 for the final A. The A/A control mean is 2.068 s. These are one local, sequential sample per sequence and policy. B and C are slower on this host; D is about 5.3% slower than the combined A control mean. The local evidence therefore does not select a faster policy. Peak process RSS was 606,916 KiB. Callback receipts and prediction hashes are in `probes/callback_{A,B,C,D,A2}/RESULT.json`; prediction arrays are retained locally but ignored by Git.

Assembly evidence is in `probes/ASSEMBLY_R1.vpdpbusd.txt`: it contains three YMM and 44 ZMM `vpdpbusd` instructions from the release extension. This establishes that the compiled binary contains both 256-bit EVEX and 512-bit VNNI code paths; the B callback receipt separately proves that the package selected `q8vnni256` on the tested VNNI-capable host.

The submission-order package set is A(original), B(`q8vnni256`), C(`q8vnni_blocked`), D(`q8vnni_fused`), then A(original) again for the requested A/B/C/D/A comparison sequence. A separately labeled rebuilt-A control is provided only to compare the original callback against the newly written ZIP/native build. Python 3.11 `zipfile.testzip()` returned no CRC errors for all four new ZIPs; each retained the exact source member inventory and all original weight bytes. Rebuilt A is 16,464,822 bytes; B/C/D are 16,464,825, 16,464,830 and 16,464,828 bytes. All hashes and the null submission-order marker for rebuilt A are recorded in the package manifest. The archives are generated under the ignored `packages/` directory in this worktree, not uploaded. The environment's competition callback image, remote score, and AMD-host runtime were not tested.

The first package-builder attempt failed while reading `precision.txt` for policy C under Python 3.13.9 with `BadZipFile: Overlapped entries`. The original archive passed `unzip -t` and Python 3.11 CRC/inventory validation; its entry bounds abutted exactly. The builder had reused a mutable source `ZipInfo` object for output writes, which changed its size metadata before the next source read. `BUILDER_FAILURE_R1.json` preserves that failed command and diagnosis. A later rebuilt-A attempt exposed an unnecessary builder check for a literal `q8vnni` in `solution.py`; the original callback instead reads the fixed `precision.txt`. `BUILDER_FAILURE_R2.json` preserves that failure. The builder now verifies the original precision member and clones each `ZipInfo` before writing; rebuilt A and B/C/D pass Python 3.11 CRC/inventory checks, and B/C/D retain their deterministic hashes.

All validation sequences used here are previously exposed campaign data and support runtime/parity checks only. No quality score, public-transfer result, AMD runtime result or speed improvement is claimed. A and all derivative outputs are ready for root-owned review and any later user-controlled upload.
