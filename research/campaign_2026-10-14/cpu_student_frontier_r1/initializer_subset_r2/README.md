# R3-profile-bound initializer subset recipe R2

This successor keeps the frozen 258-sequence initializer-only screen from `initializer_subset_r1`, but binds it to the successful, device-canonicalized R3 actual-data resource smoke. The original R1 packet and R2 profile failure remain unchanged. The [R2 machine-readable contract](INITIALIZER_SUBSET_FIT_R2_CONTRACT.json) pins the source-qualified subset, objective, source and teacher ancestry, R3 profile/controller hashes, native gate, fit/prediction/grade commands, and resource envelopes. The CPU preflight is [PREFLIGHT_R3_BOUND_R2_R2.json](PREFLIGHT_R3_BOUND_R2_R2.json); its exact bounded command is in the contract.

The [R3 profile evidence index](../profiles/terminal_r3_r1/README.md) records the one-sequence actual-data smoke: three finite one-update learned arms; host peak 3.719 GB; observed VRAM peak 0.875 GB; zero OOM deltas. The profile used the real `(valid,37,44,346,154)` sample and the H256×2 seed-3 epoch-0 control. The `.pt` and `.npz` files remain in the ignored physical directory under `/home/vlad/development/wunder/worktrees/student-initializer-profile-r3-20261015`; the contract pins each hash. Their concrete C++ native-consumer check is still required. It must complete before any fit, and it verifies the native parser/callback and reset replay on the full 20,000-row source-qualified sequence. This is an execution gate, not a quality result.

The fit subset is the frozen seed-3 shortest component-order prefix reaching 256 sequences: 82 complete F0 fitting components and 258 complete 20,000-row sequences (228 `train`, 30 fit-`valid`). The order and `(source,row_group,seq_ix,component)` members are in [the original subset manifest](../initializer_subset_r1/FIT_COMPONENTS_TARGET256_SEED3_R1.json), which remains the sole canonical copy. Fit components are disjoint from all 468 fixed F0 evaluation groups. The teachers saw the full F0 fitting pool, so this is a low-fidelity initializer screen conditioned on a full-data teacher and student backbone, not a from-scratch small-data comparison.

The four fixed arms are zero-state H256×2 CP0, learned constant state, first-row-conditioned state, and causal prefix-conditioned state. All learned arms start from the same audited epoch-0 parent and install only its common 211-feature mean/std; recurrent and prediction-head weights stay frozen. Each learned arm receives one FP32 AdamW update for each selected complete sequence (258 attempted and required completed updates), using the same source-qualified order. One update spans all ten C2000 chunks with a retained recurrent graph and no hidden-state detach. The complete-sequence global weight denominator, constant learning rate `1e-4`, no scheduler, and one-update-per-sequence budget are explicit initializer-screen choices; the profile's one update is only resource evidence. The fixed target is `0.1*clip(label,-2,2) + 0.9*clip(clean homogeneous teacher,-2,2)`. Production `main_row_weights` multiplies `abs(clipped label)` using the pinned propensity cache (`p² + 0.03`, true-mask epsilon `0.03`); rows 0–98 are causal context with zero loss.

After each separately root-admitted fit, the R2 fit worker checks the terminal fixed checkpoint, complete-sequence membership/order, the strict producer cache validator and full target hashes, common normalization and source ancestry, 258 completed finite-gradient updates with zero skips, and finite terminal tensors. It emits the trained initializer checkpoint and native arrays. The corresponding full-valid prediction worker checks fresh sequence resets and the native callback before exporting FP32 predictions in the exact `valid_targets.npz` row order, shape `[1873,20000,2]`. Then the unchanged official `global_wp_clip2_v1` scorer evaluates the fixed 468-group F0 panel against the zero parent. The five fixed position buckets are rows 99–199, 200–999, 1,000–4,999, 5,000–9,999, and 10,000–19,999; component-paired resampling is diagnostic, with no bucket-based adaptation or checkpoint selection. F0 has prior exposure and is not a fresh holdout.

The contract provides the standard-library no-fit preflight, actual R3 native-gate command, and worker argument templates for each learned arm's fit, full-panel export, official grade and position-bucket report. Fits use a 5 GB host reservation; full-valid exports use 6 GB; both retain the 3.5 GB PyTorch allocator cap and 5 GB observed-VRAM ceiling. The native gate has a 900 MB, one-CPU, 120-second bound. Root owns all durable admissions and the GPU lock. No subset fit, panel prediction or quality grade is included in this recipe packet or authorized by the profile result.

The copied R3 JSON metadata in `profile_artifacts_r3/` is hash-identical to the source evidence commit. The profile's learned binary payloads are intentionally not copied or committed; native validation and later fit admission use the original hash-bound files in the frozen profile worktree. No result is claimed until the native gate, fits, predictions and fixed-panel grades are collected.
