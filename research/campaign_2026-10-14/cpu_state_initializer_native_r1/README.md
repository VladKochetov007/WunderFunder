# Native causal state initialization R1

This isolated implementation extends the Rust `EnsemblePredictor` callback with optional per-member causal state initialization, preserving the existing GRU, preprocessing, quantization and output weights. The Python exporter transports learned constants and first-row/prefix MLP tensors as contiguous FP32 arrays. Omitting `state_initializers` preserves the old path; zero is bitwise equivalent to omission. Prefix statistics are reset with recurrent state and the bounded residual is injected once before row 99.

The code was based on MAIN commit `25bb064fac1c0befa0ab7ffd3f467d6d0a872e4e` in the isolated worktree `/home/vlad/development/wunder/worktrees/cpu-state-initializer-native-r1`. Related records are H-STATE-INIT-20261014 and E-STATE-INIT-IMPLEMENTATION-20261014-R1. No checked xteam package or original native binary was modified. This implementation does not train an initializer or change any model weights.

[PARITY_REPORT_R1.md](PARITY_REPORT_R1.md) describes the API and synthetic-fixture measurements. The Python wrapper/native exact-activation comparison covers all four modes, full/chunk execution, callback reset and prefix causality; 25 focused tests pass. Prediction error is at most `2.98e-8`, and final-state error at most `5.96e-8`. Portable Q8 VNNI, Q8x and Q16x each exercise constant, first-row and prefix injection with exact reset replay; this is state-transport coverage, not a quantized Python-parity claim.

The [actual-weight native callback comparison](ACTUAL_NATIVE_CALLBACK_PARITY_20K_R1.json) exercises all four modes on the same 211-feature sequence. Full/chunk Python wrapper delta at the row-99 cuts is at most `1.15e-5`. All modes remain within the recorded tolerance and native reset replay is bitwise exact. The 59.29-second bounded run used one CPU, 1.608 GB max RSS, and no visible CUDA device; deterministic initializer tensors were not fitted.
