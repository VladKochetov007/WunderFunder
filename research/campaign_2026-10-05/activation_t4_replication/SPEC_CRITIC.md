# Blind E482 design critique

## Decision

This is a valid six-cell portability study if its remote wrapper is independently bounded and if the provider actually allocates two separate T4 devices with current usable quota. Keep all six E481 seed-271828 recipes. Do not use the still-running local E481 result to remove or select remote cells. A cross-device difference is a transport/runtime sensitivity observation, not an independent market replicate.

## Implementation invariants and fail cases

- Reuse the frozen E481 `seed_states`, `initialize_arm`, `make_optimizer`, `run_fit`, causal features and equations by content hash. The wrapper must invoke only the exact six `(seed=271828, optimizer, shape)` keys, bind its own six-arm receipt, and avoid mutating E481 globals, artifacts or 18-arm receipts. Verify the six recipes are exactly baseline/sine/cubic crossed with AdamW/MuonAdamW, each from the same seed-specific baseline weights and seed-specific fit-order permutation.
- Keep the E481 reset-after GRU equation, r/z/n gate order, hidden candidate bias placement, state initialization, identity model buffers, external fit-only normalization, output head and parameter names intact. All arms must retain 61,058 trainable parameters. The maps must use the same formulas: `u`, `u + .1 sin(pi*u)`, and `u + .1 pi*u*(1-u*u)`. Any shape-specific data, optimizer, schedule or initialization change confounds hardware portability.
- The remote fit must consume exactly the sealed 24 fit row groups from the authorized private dataset, never load test-role rows or test targets before completion, and run B4 × 256 with 79 carried-state chunks per batch, reset per batch, one detached-state boundary per chunk and exactly 474 updates. Bind the local dataset/cohort identity without bundling duplicate data. Reject any missing, duplicated, reordered or role-mismatched cohort rows.
- Run parity on the actual remote T4 runtime before fit admission: candidate baseline versus native reset-after `nn.GRU` outputs, final state and input/parameter gradients; then clipped AdamW and Muon optimizer-step parity. Use training mode for any cuDNN recurrent backward comparison; eval-mode cuDNN backward can fail independently of numerical correctness. Apply the same full FP32 IEEE controls to reference and candidate. Preserve original tolerances; do not widen them after seeing a T4 discrepancy. Probe every one of six recipes at actual B4 × 256, check raw inputs, outputs, states, loss, gradients and parameters for finiteness, prove each cell changed parameters, and record teardown and per-device peak allocation. Any failed cell blocks the full run.
- Keep Muon selection exactly on the four two-layer GRU input/hidden weight matrices with three gate blocks each; all other parameters remain AdamW. Check exact disjoint coverage, shared LR and WD/betas, global clipping, and the inherited CUDA BF16 Muon orthogonalization path. Record its actual software policy and runtime, not a name-only assertion.

## Transport and resource admission

- Require observed provider metadata showing two T4 devices, stable distinct device identities and enough current free quota before transport. Each worker must bind to exactly one distinct device (`CUDA_VISIBLE_DEVICES` or equivalent verified inside that worker); reject accidental sharing or an unassigned device. If two distinct devices or quota are unavailable, do not submit.
- Independently measure host RAM and available CPU before launch. Two workers each capped at one CPU and 6 GiB plus monitor/runtime/support must remain below the specified 80% host budget; require at least three available CPUs. Enforce each allocator cap of 2 GiB and observed GPU stop of 3 GB, plus whole-host and per-GPU monitors with stop below 90% usage. Record initial and final worker and parent OOM counters. An OOM or monitor stop is a preserved failed attempt, not a reason to relax caps or relaunch blindly.
- Review the entire archive closure before private upload: exact allowlisted files and hashes, no credentials/secrets, no redundant dataset copy, safe extraction with path traversal rejection, no symlinks/hardlinks escaping the staging root, exact mounted dataset identity, and no internet/network fallback. The worker must verify source and data mount hashes before loading features, log bounded diagnostics, and write a complete receipt even on exceptions when possible.
- Bound the whole private kernel to 3,600 seconds and account for actual T4 use against the campaign's 80-device-hour budget and provider quota. The two-GPU schedule is at most two device-hours, but retries consume the same budget and require new receipts. Respect the stated admission cutoff; already admitted work drains only under its existing bound.

## Scoring and interpretation

The nine within-device contrasts are six shape pairs (three pairs under each optimizer) and three Muon-minus-AdamW effects (one per shape). Additionally report all six paired local-versus-T4 arm score differences, without treating those as extra independent evidence. Retain all contrasts and arms; do not choose a winner. The scorer must independently reconstruct the exact local/T4 recipes, verify fit receipts and checkpoint keys, check raw target and prediction finiteness before official clipping, use the exact shared official mask, and export raw selected labels/predictions, IDs, counts and component provenance. For paired local/T4 summaries, use the same numeric-sorted component multiplicity draws for corresponding arms; seed and device outputs remain separate. State explicitly that the same 16 components have prior exposure, intervals condition on fitted weights, and device contrasts measure portability rather than scientific replication.

## Admission gate

Before any remote publish/submit, the bundle closure, provider allocation/quota and mount fixture must pass independently; the first operation on each actual T4 is the sealed six-cell probe. Only after all six cells pass with verified resources and teardown can the separately bounded six-fit wrapper be considered. This design review authorizes neither upload nor kernel launch.
