# E483 blind design critique

**Reviewed before implementation.** The registered design is `E483_DESIGN.md`, SHA256 `fa5aa9ec2a7f897f7ed31f7a99d9ee0b8a681cce73146ebd367d729f6a1e8288`. I have not inspected an E483 implementation or score output.

The 18-cell design isolates the intended factor if and only if the beta change is confined to the single Muon recurrent-matrix group. `MuonAdamW` stores its beta pair on each parameter group; an optimizer-wide beta override would also change AdamW updates for input/head/bias parameters and confound the question. Freeze every non-Muon group at `(0.9, 0.999)`, set only the `muon=True` recurrent group to `(0.8|0.9|0.95, 0.999)`, and retain its `blocks=3`. Assert the exact four names `gru.weight_ih_l0`, `gru.weight_hh_l0`, `gru.weight_ih_l1`, `gru.weight_hh_l1`, exact disjoint coverage of all 61,058 trainable parameters, and identical LR `0.001`, weight decay `0.01`, Newton–Schulz steps `5`, and scale `0.2` in every arm. The non-Muon group’s actual effective betas should be recorded and tested, not inferred from constructor defaults.

The registered contrast count is 27, not 24: each seed has three sine-minus-baseline effects (one at each beta), four momentum contrasts (`0.8−0.9` and `0.95−0.9` for both shapes), and two difference-in-differences interactions, for nine per seed and 27 total. For each seed and alternate beta `b`, define the interaction as `(WP(sine,b)−WP(baseline,b))−(WP(sine,0.9)−WP(baseline,0.9))`. Keep the three seeds’ intervals separate. Each contrast must use the same 2,000 component-resampling index draws across its arms, with sorted/aligned identities for the exposed 16 components; report global and both target WPs. This is conditional uncertainty for fitted models, not fresh market validation or a public-score estimate. Keep all registered arms and contrasts, with no selection on this panel.

Use one identical initial state per seed across all six arms, with the three initialization seeds `271831/271832/271833` demonstrably distinct. Reuse the E481 fit-only loader and exact 24 fit components; bind parent code/data/cohort hashes and preserve the E481 architecture, state-dict keys, normalization buffers, causal features, row traversal, sequence carry/detach, and candidate equations. The 24-sequence traversal should be the seed-shuffled permutation of canonical fit nodes; telemetry at updates `0, 46, 236, 473` must identify the corresponding four-row batch and `chunk_start=(step % 79)*256`. All arms receive exactly 474 updates at fixed LR with the same batch/chunk budget. No checkpoint selection or held-out inspection is part of the fit phase.

Muon beta may be numerically invisible on the first update: its zero-initialized momentum buffer and the first gradient are collinear, and subsequent orthogonalization normalizes scale. Therefore first-step finite/change checks alone cannot demonstrate that beta is wired correctly. Before real-data probe admission, add a synthetic two-step test with non-collinear successive gradients that proves the three Muon beta settings create the expected distinct second effective updates, while identical gradients keep the AdamW-group updates exactly equal for all configurations. Independently compute that two-step reference from the frozen optimizer equation. Also check the isolated modified-group optimizer’s baseline step against the immutable E474/E481 `(0.9, 0.999)` reference on CPU and actual CUDA, including output/state/gradient parity and clipped optimizer-step parity. Do not mutate or monkeypatch the parent factory.

The custom fit path must count clipping over all 474 updates from the actual pre-clip total norm (for example, the detached norm returned by the fixed `clip_grad_norm_` call), and fail on nonfinite loss, state, gradients, norm, or parameters. Four sampled telemetry rows are not a clipping-frequency estimate. Retain the fixed telemetry RMS fields, finite loss, state bounds, and row-group/chunk provenance without using them to choose a recipe. Compare candidate-specific Adam/Muon group receipts and update checks before training so an optimizer-family leak fails closed.

The actual B4×256 CUDA probe should exercise every `(beta, shape)` cell on the assigned worker, confirm finite loss/state/gradient and changed parameters, and pass the same FP32 precision-policy parity controls used by E481. A probe failure blocks the matrix. Keep the single-GPU, one-worker limits, 6 GiB host worker cap, 2 GiB allocator cap, 3 GB observed-GPU stop, and controller’s actual RAM/CPU/no-swap limits. The 7,200-second reservation covers the whole 18-fit matrix but not retries; preserve partial artifacts and failure receipts if the watchdog ends the run. Start only after the prior worker has torn down, verify measured headroom and the remaining device-hour budget, and stop new admissions at the registered cutoff.

**Admission:** the specification is suitable for implementation with the checks above as hard gates. Passing this design review is not implementation approval or fit authorization; an independent source review and the real CUDA probe are still required.
