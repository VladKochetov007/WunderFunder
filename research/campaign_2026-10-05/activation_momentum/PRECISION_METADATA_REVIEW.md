# E483 probe precision metadata addendum

The probe's model forward/backward and cuDNN/matmul work runs under the intended IEEE FP32 backend policy with autocast disabled, but its serialized precision snapshot is taken after that policy is restored. This does not mean every operation is FP32: the unchanged CUDA Muon Newton–Schulz orthogonalization deliberately converts its input to BF16 and converts the result back to the gradient dtype. Do not treat the probe receipt's backend flag values as evidence of the precision used by its parity/update calculations.

In `fit_momentum.py`, `run_probe()` enters `e474.full_ieee_float32()` before `run_native_and_optimizer_parity()` and holds that context over all 18 B4×256 updates. The context sets `torch.backends.fp32_precision`, CUDA matmul, cuDNN, and cuDNN RNN controls to `ieee`, disables autocast, then restores each prior setting in `finally`. The unchanged Muon implementation still performs its documented BF16 CUDA Newton–Schulz path. The probe result dictionary is constructed after leaving the context and calls `e474.precision_metadata()` there. That function reads the current backend attributes, while its `device_math` label is fixed to `FP32 IEEE`; therefore the saved dictionary can report default values such as `none` and `tf32` alongside the hard-coded IEEE label.

This is a receipt-field timing defect, not evidence that the forward/backward/cuDNN/matmul gate ran in TF32. The successful parity and update code is lexically inside the context. The source and probe result still need to be judged from the independently supervised CUDA attempt and native parity checks, not from the post-context `precision` fields. The full-fit matrix also executes its model updates inside `full_ieee_float32()` and uses the same intentionally BF16 Muon orthogonalizer; its fit receipt does not claim backend flags.

For future probes, capture `precision_metadata()` while still inside the context, retain the source hash and backend values together, and keep the receipt field name tied to that captured policy. This addendum does not change or unseal any E483 numerical source, probe, or attempt.
