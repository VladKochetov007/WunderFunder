# NLL child terminal checker V1

This packet prepares a bounded terminal checker for the single already-started NLL fit, `fg19_child_nll_f0_s1001_fit_v1`, on `computer-vision-homework-fg19-child-nll-fit-v1.service`. It is local preparation only. The checker has not been invoked, and this packet contains no NLL terminal evidence or acceptance.

The fixed recipe uses source commit `68ff682977b822f38351aac0f621146f5f13b440` with its accepted 167-file manifest, the fold-0 split, the parent checkpoint at `@ep3`, inherited preprocessing, the shared accepted dictionary artifact, and the T3 cache. The representation mode is `base`, the mean/variance head has one layer, and its objective is `nll`; the source CLI still requires the compatibility flags `--loss wmse --loss-norm chunk`. It keeps the seeded 16-example batches, 2,000-row chunks, six fixed epochs selecting epoch 5, AdamW FP32, gradient statistics, saved training state, and no evaluation during fitting. The accepted dictionary child is checked as a stopped sequential predecessor only. It is never an initializer; the initializer remains the parent `@ep3` checkpoint.

The checker requires typed evidence with schema `fg19.child-nll-fit-native-terminal-evidence.v1`, exact run/unit/invocation identity, `ActiveState=active`, `SubState=exited`, and strict integer `MainPID=0`, `ExecMainCode=1`, and `ExecMainStatus=0`, plus a nonempty raw capture path, positive byte count, SHA-256, and timezone-qualified capture/exit timestamps. It does not require the NLL unit to have been separately stopped before terminal verification; root records that stop as a later operation. The checker accepts no quality score and does not evaluate predictions.

The checker composes five frozen pure-helper modules from an exact six-file private closure. The wrapper must validate and stage all five helper byte pins before starting Python; after import, the checker rechecks the helper sibling paths and hashes. The checker uses the source-parsed NLL CLI and the generic continuation-contract helper, while retaining NLL-specific guards for objective and representation mode. It reuses the base-mode auxiliary/provenance check, parent-normalizer inheritance check, restricted `weights_only=True` training-state decoder, and the exact approved one-path `PosixPath` exception with `O_NOFOLLOW`. The learned-dictionary artifact record is checked in its original shape, with no fabricated `mtime_ns` field. The dictionary-child acceptance is bound to its original launch-acceptance SHA and separate exact-stop receipt.

`test_child_nll_terminal_check_v1.py` contains five focused local checks. They exercise strict native evidence identity/types, the base/NLL recipe and parent initializer, sibling helper byte/origin checks in a temporary six-file closure, actual NLL admission/launch/root-acceptance metadata bindings, and the exact dictionary-child predecessor acceptance/stop pins. They do not invoke `verify_terminal` or `main`, parse model/state/cache/dataset payloads, or run source, model, profile, fit, or evaluation suites. The actual receipt tests read only the NLL launch metadata and the accepted dictionary-child acceptance/stop JSON. Ruff and these five focused checks passed; the exact checker, helper, receipt, fixture, and result pins are in [DEPENDENCY_MANIFEST.json](DEPENDENCY_MANIFEST.json) and [LOCAL_CHECKS.json](LOCAL_CHECKS.json). [HELPER_REFERENCE_AUDIT.json](HELPER_REFERENCE_AUDIT.json) records an AST-only check that every directly referenced helper symbol exists in its pinned helper.

The worker runtime, fresh source/data/cache/predecessor identities, current native terminal evidence, and output integrity remain runtime gates for root's later operation. Local helper imports do not prove the worker's required Torch `2.14.0+cu130` runtime. No remote actions, B staging, payload reads, fits, or checker execution occurred in preparing this packet.
