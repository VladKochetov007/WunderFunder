# Focused NLL checker import-boundary proof

This is a narrow local CPU proof for importing the exact six-file private NLL terminal-checker closure. The harness copied the frozen checker and five pinned helpers into a fresh temporary directory, verified all six byte counts and SHA-256 pins before import, then verified each imported module resolved from that directory and all six bytes still matched after import. The checker’s private `_check_helper_closure` was the only checker function called. `main`, `verify_terminal`, training, and evaluation were not called.

A Python open audit hook denied and counted attempts to open the known worker and B roots, local B/data/research-temporary/split roots, and model, state, dictionary, cache, and data payload paths. It recorded zero protected-open attempts. The hook is scoped to Python `open` audit events and the path classes listed in [IMPORT_BOUNDARY_PROOF.json](IMPORT_BOUNDARY_PROOF.json); it is not an exhaustive operating-system syscall monitor. Seventeen allowed opens were reads of the six private code files.

The child process set `CUDA_VISIBLE_DEVICES` to empty, used one BLAS thread, and guarded 63 named CUDA initialization, allocation, device, stream, random-state, and transfer APIs. The guard recorded zero attempted calls. `torch.cuda.is_initialized()` was observed twice and returned false before and after import; those observations are recorded separately and are not counted as CUDA action calls. This list is an explicit focused guard set, not a claim that every possible CUDA API or native call path is intercepted.

The proof imports no source-68 modules: zero `wnn` modules were loaded. It does not replay the old CLI, run-identity, representation, model, source-manifest, or 29-module cold-import checks. Local Torch was 2.14.1; that does not prove the worker runtime. The actual worker’s `2.14.0+cu130` requirement, fresh source and resource checks, and all terminal payload checks remain separate runtime gates. No model, state, dictionary, cache, split, dataset, B, or remote payload was opened or hashed.

The exact harness and proof pins are `import_boundary_proof_nll_terminal_check_v1.py` (19,360 bytes, SHA-256 `7013b039d814fd8f5cd0ae307d9ba617493759ef71cf14f6e6546264901fdb4d`) and [IMPORT_BOUNDARY_PROOF.json](IMPORT_BOUNDARY_PROOF.json) (10,850 bytes, SHA-256 `fbb84d1c3226e25b81e395957e5752f185ee772da76768259c4140b8a0010eea`). Ruff passed for the new harness. The checker, original five focused fixtures, local-check receipt, dependency manifest, and original README were left unchanged.
