# Parent-fit R2 terminal integrity checker

The bounded checker in [`parent_fit_terminal_check_v1.py`](parent_fit_terminal_check_v1.py) is prepared for the root-owned run `fg19_parent_h256x2_f0_s1001_fit_r2_v1` on source `68ff6829`. It is not a terminal result. Root may call it only after the exact native invocation is captured exited with code 0; the checker intentionally runs before the parent acceptance and exact-stop receipts are created. It requires the already accepted and exact-stopped cache/profile ancestry.

The checker binds the full canonical trainer CLI to the pinned launch/admission, source manifest and exact 167-file tree; fit-only train and valid membership; the accepted cache formula, lineage and array hashes; checkpoint epoch and exact tensor inventory; finite FP32 H256×2 model tensors and normalization identity; and the epoch-boundary training-state schema, AdamW moments, OneCycle horizon, loader/RNG, auxiliary state, and four-epoch update counters. It checks the saved optimizer learning rate against the scheduler's final learning rate. Cache acceptance/exact-stop receipts are checked directly. The already accepted/stopped profile is bound transitively through the exact pinned admission SHA `42b5f3fe…dc50026b`; this checker does not separately reopen the profile receipts. It does not evaluate, resume, train, score, open dataset/prediction arrays, or accept/stop a service.

Checkpoint files are opened with `O_NOFOLLOW`, size-checked and hashed before a CPU `weights_only=True` load through the checker's local bounded reader. Source and JSON receipts use stable bounded readers. The frozen `propensity_terminal_support.py` remains unchanged; the checker does not pass unsupported size arguments to its loader.

The [focused synthetic tests](test_parent_fit_terminal_check_v1.py) cover model layout, counters, no-EMA auxiliary state, optimizer moments/rate consistency, scheduler horizon, typed native status, accepted cache lineage and bounded loading. The [local check receipt](PARENT_FIT_TERMINAL_CHECK_LOCAL_CHECKS.json) records those tests and static checks. The [cold-import proof script](parent_fit_terminal_cold_import_proof_v2.py) and its [module-path/SHA receipt](PARENT_FIT_TERMINAL_COLD_IMPORT_V2.json) preserve the exact import/read-sentinel command, all 26 runtime WNN source pins, and source-bound execution of the sibling CLI/tensor-identity helpers on synthetic metadata/tensor inputs. Those checks validate checker code only; they do not inspect changing parent checkpoints or establish training completion.

`verify_terminal` also uses `_launch_cli_args` and `_canonical_tensor_identity` from the sibling [S5 terminal checker](teacher_s5_terminal_check_v1.py); root's final preparation manifest must pin that helper alongside the frozen terminal-support helper. This small source-qualified reuse does not import teacher model rules or optimizer assumptions.
