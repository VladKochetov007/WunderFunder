# First-cell F0 evaluation prediction export v1

This is a local-only, source-qualified adapter for exporting feature-only predictions from the five accepted F0/seed-1001 epoch-5 runs. It does not perform scoring, choose checkpoints, add folds or seeds, or claim a quality result. The 468 evaluation groups are fit-excluded but exposed development evidence.

The fixed panel is `control/base`, `ema/ema`, `sparse/sparse`, `nll/base`, and `allthree/ema_sparse`. Each run is bound to its accepted terminal receipt, exact-stop receipt, unit and invocation, `model_ep5.pt` size/SHA-256, source manifest, representation state, normalization, and current split SHA. Epoch 5 and 44,760 successful updates are fixed for every arm.

At runtime the adapter verifies the complete 167-file source manifest in `EXPORT_SOURCE_MANIFEST.json` before importing the restricted `weights_only=True` loader and canonical WNN APIs. It also verifies the pinned `WNN_PORTABLE_DATA_MANIFEST` bytes and SHA, joins its six entries to all six source identities in the existing AllThree `ADMISSION.json`, and sets that exact approved path before private imports and canonical split loading. It records fresh stat-only observations of all six exact registered paths before and after canonical split loading, comparing leaf type, resolved path, device, inode, byte count, and nanosecond mtime. The canonical split loader then applies its portability checks to the relocated data aliases by reading and hashing the registered sources; this does not decode targets or masks for export. The adapter uses `load_campaign_split`, `SequenceFile.read(..., targets=False, mask=False)`, an explicit `TrainingEnvironment` and `InputConfiguration`, canonical `make_model` and `training.evaluation.predict`, strict FP32, and 2,000-row prediction chunks. It derives the valid parquet row-group count from the current split's component inventory (1,405 fit-valid plus 468 evaluation groups = 1,873); this is separate from the per-sequence 20,000-row time axis. It reads the current 468 evaluation groups only, in canonical manifest order, and writes one create-only little-endian FP32 NPY per arm with shape `(468, 20000, 2)`. Each sidecar and the completion manifest bind the export binding SHA, checkpoint, representation mode, ordered membership digest, prediction bytes/SHA, source, and split. The completion manifest records the portable registry pin and source names, all six admitted source identities and their before/after split observations, plus fresh stats-only observations of the one file opened directly, `datasets/valid.parquet`, including its approved parent alias, resolved path, device, inode, byte count, and nanosecond mtime. The worker requires that parquet leaf to be a non-symlink regular file resolving to the exact admitted target; it does not hash the 5.6 GB file itself. A completion manifest is written only after all five prediction files and sidecars are durable and the registered file identity still matches.

The B execution contract is explicit in `EXPORT_BINDING_V1.json`: project base, physical data root, source root, existing fit-receipt root, existing read-only support root, new private evaluation evidence root, its accepted-receipt paths, scratch root, and the absent `evidence_root/exports` output directory. The worker source and its pinned binding/manifest are staged at the evidence root. Existing fit receipts remain read-only at their original B paths; only the root-authority AllThree acceptance and stop copies are staged under `accepted_receipts/`. The existing fit `ADMISSION.json` and approved portability registry are read in place to verify all six registered data identities and registry membership; neither is restaged.

The worker also rechecks that the output leaf is absent and its filesystem has room for all five NPY files plus the fixed free-space reserve before creating the first output directory. This packet has not been staged or executed on B. The source worktree at commit `68ff682977b822f38351aac0f621146f5f13b440` remains unchanged. Root owns the later fresh-resource, selected-GPU ownership, process/disk-headroom, staging, and one-attempt execution gates; prediction export must wait for those gates and independent source review.
