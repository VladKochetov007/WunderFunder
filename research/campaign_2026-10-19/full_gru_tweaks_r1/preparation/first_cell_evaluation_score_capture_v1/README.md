# First-cell bounded score result capture V1

This folder contains an inert, local-only reader template for the conditional five-arm CPU score unit. It is aligned to [score-admission V4](../first_cell_evaluation_score_admission_v4/README.md)'s exact unit `computer-vision-homework-fg19-first-cell-score-v1.service`, private directory `/home/grinchenkoeg/computer-vision-homework-20261018/research_tmp/fg19_first_cell_f0_s1001_score_v1`, and scalar result path `/home/grinchenkoeg/computer-vision-homework-20261018/research_tmp/fg19_first_cell_f0_s1001_evaluation_v1/RESULT.json`.

The five actual score receipt literals—ADMISSION byte count/SHA, LAUNCH byte count/SHA, and invocation ID—remain unbound sentinels. `_require_bound_pins()` runs before path, systemd, cgroup, GPU, or process access. Root may bind those values only from the actual score admission and launch receipts, after which the exact body requires independent review before capture. This folder contains no actual export or score receipts and makes no result claim.

The reader checks those two pinned receipts, their exact schema/unit/result-path/invocation join, the staged export-acceptance/stop pin shapes, and admission-bound pins for the four scorer modules. It then queries only the exact score unit plus the `wnn-campaign.slice` parent, records the bounded selected-GPU/process observation, and captures a bounded stable tail of `unit.log` for both successful and failed score executions. It reads the exact export-root `RESULT.json` only when the unit invocation matches and systemd reports `Result=success`, `active/exited`, PID 0, code 1, status 0. The result is transported as bounded base64 bytes for root's later strict extraction; this reader does not parse, summarize, or endorse metric values. A failed or nonterminal unit does not trigger any access to the result path.

The implementation remains a single self-contained capture script so the root reader can inspect one closed body without a staged helper import. It reuses the bounded file, cgroup, GPU, and process helper ASTs from the reviewed AllThree result reader V2. The new fixture checks that helper correspondence, unbound-before-query behavior, synthetic receipt identity joins, strict success gating, bounded log-tail handling, and the no-payload/no-stdin boundary. It does not import the previous reader, scorer, WNN, model, or data code. See [the source proof](SOURCE_PROOF_V1.json) and [local checks](LOCAL_CHECKS.md).

The cgroup tree scans and process reads retain the reviewed reader's narrow post-read bounds; subprocess output limits are checked after the subprocess returns. This is not a hard OS resource budget. No prediction arrays, targets, moments, checkpoints, source payloads, or model/cache data are read or hashed. Root owns the actual capture, full scalar-result acceptance, exact stop, and any publication.
