# Common clean ancestry and bounded execution

The five-arm scientific question is fixed in [the campaign design](../DESIGN.json). The selected strong family is the six-epoch Main T3 warm student, H256×2 with raw112+event99 inputs and its teacher/label target blend. Its historical FP16 score is evidence for selecting this family; it is not the result of this new strict-FP32 comparison.

Historical T3 used a learned scoring-mask propensity, a three-teacher H384×2 cohort, and a previously distilled warm parent. Their complete cross-fold graph is unavailable as a clean reusable initializer. New fitting-only prerequisites are required, beginning with the already published [strict propensity implementation](https://github.com/VladKochetov007/WunderFunder/tree/235db75ab91e24c69f21e637a83a48512dc674fe). This avoids using production-trained weights as a clean outer-fold parent. The older historical Muon `all` flag is not a supported current canonical flag; its exact semantics and the replacement warm-parent recipe must be declared before admitting those later stages. No silent conversion to an easier labels-only control is authorized.

The [clean Main T3 rebuild candidate](CLEAN_MAIN_T3_REBUILD_CANDIDATE_R1.md) proposes one fresh, four-epoch T3-target H256×2 legacy-topology parent (211 inputs/23 outputs) per fold/seed cell, shared across its five arms. Each child warm-load expands that checkpoint to the 467-input/25-output experimental layout with the reviewed zero-extension path. It preserves the bound six-epoch child settings but is an ancestry adaptation, not a reproduction of the old A9/production-derived parent. Teacher Muon-all semantics, strict-FP32 source binding, and the active propensity receipt remain admission gates; the candidate does not assert that any teacher or student fit has completed.

[The base source tree](BASE_SOURCE_TREE.json) inventories the current canonical e20 source considered during preparation. The first actual execution uses the separate, unchanged published strict-propensity source235db75, not a patched historical snapshot. [The local binder](stage_profile.py) binds that complete source and the reviewed profile into [the one-shot remote admission](profile_admission_remote.py). It refreshes ownership, all populated descendants, GPU sharing, storage, source/split identity and output absence before staging or launching. Unknown outcomes are inspected, never blindly retried. Profile artifacts contain no retained campaign model or quality score.

The fresh B resource observation is indexed in [the campaign README](../README.md). Source and scalar receipts may be collected to Mac; actual arrays and models remain on B. This packet does not repeat any completed R1–R15, COMBO or original F3 work.
