# First-cell export admission v1

This local packet prepares one bounded admission for the fixed five-arm, feature-only first-cell prediction export. It has not been staged or executed on B. Root must finish its independent source review, bind the exact staged payloads and current native receipts, and perform a fresh preflight before one remote attempt.

`REMOTE_SUBMISSION_TEMPLATE.py` is a self-contained stdin body. It includes five strict-base64 payloads: the already-reviewed exporter, its binding and 167-file source manifest, and two exact ROOT-authority AllThree receipt copies. It creates the private evidence directory only after all read-only gates pass, stages those five files exclusively, writes `ADMISSION.json` and an empty `unit.log`, then attempts the exact export unit once. A successful bounded outer reply contains exactly `unit`, `outcome`, `admission_base64`, and `launch_base64`, after both durable receipts have been reread and checked. An uncertain outcome is preserved for exact-unit inspection; the body never retries or recreates the directory.

The AllThree fit admission and launch remain read-only at the original fit receipt root. Their exact acceptance and exact-stop sources are `records/child_allthree_fit_v1/TERMINAL_ACCEPTANCE.json` and `records/child_allthree_fit_v1/exact_stop/EXACT_STOP.json`; only those two ROOT-authority bytes are copied into the new evidence directory. The other four arms' accepted receipts and all predecessor receipts are read in place. This admission checks the five fixed epoch-5 acceptance/stop pairs, each model by stat only, the 14 predecessor receipt pins, the parent checkpoint, dictionary, cache arrays, profile receipts, canonical source closure, six portable data identities, selected-GPU owners, and parent/filesystem capacity before its first directory mutation. It does not hash model, cache-array, or data-array payloads.

The selected unit is `computer-vision-homework-fg19-first-cell-export-v1.service` in `wnn-campaign.slice`, with one CPU, 7.5 GB memory high, 8 GB memory max, no swap, a 7,200-second runtime cap, selected-GPU allocator cap 4,294,967,296 bytes, and one BLAS/loader thread. The body sets the fixed project/data/source/registry paths, physical scratch `TMPDIR`, CUDA UUID, strict-FP32 environment, and `-E -B -I` Python invocation explicitly.

The worker's expected completion marker is `exports/EXPORT_MANIFEST_V1.json`, with five `PREDICTION_SIDECAR.json` files. The result reader is a separate root-owned template. It reads only bounded log and receipt metadata, and only reads the completion manifest and five sidecars after the exact unit reports active/exited with status 0. The prediction NPY files are 74,880,000 bytes each, little-endian FP32 with shape `(468, 20000, 2)`; this admission and reader do not open or hash those array payloads.

`ADMISSION_SOURCE_BINDING_V1.json` records the exact rendered source, helper extraction provenance, five payload lengths and SHA-256 digests, staged names, and the outer reply/receipt contract. It also binds the exact 9,633-byte `EXPORT_SOURCE_REVIEW_V1.json` (`cf44af7624e81ee99e9705bf08e69b359f7048354df069cad35b26c7ec927c15`), whose PASS covers the exporter/scorer pair and their pinned inputs. This does not replace the independent admission-body review. `test_admission_packet_v1.py` is a narrow static check of those joins and the no-retry/source boundaries; it does not import WNN, Torch, NumPy, or the exporter.
