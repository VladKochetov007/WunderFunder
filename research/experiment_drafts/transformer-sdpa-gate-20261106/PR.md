# [Experiment] E-B300-SDPA-GATE-20261106: query-dependent SDPA head gate

No local tests, model imports, profiles, fits, inference, cache exports or GPU actions ran.

2. **Why it should work.** A per-query, per-head sigmoid can suppress attention writes that are unhelpful for a row while retaining the existing causal attention and output projection. The implementation applies `sigmoid(W norm_attention(x) + b)` after SDPA and before the output projection. Both new tensors start at zero, so headwise starts at a uniform 0.5 multiplier. The paper [Gated Attention for Large Language Models](https://arxiv.org/abs/2505.06708) motivates this placement in LLMs; it does not establish benefit for this forecasting task. The strongest alternative is that any gain comes from constant attention attenuation. `constant_half` tests that alternative; `headwise - constant_half` is the query-dependence contrast.

3. **Compute advantage.** The added treatment uses one `heads × hidden` matrix and one head bias per block and adds a small projection/multiply around the existing SDPA. It reuses the same data, optimizer and 30-epoch schedule, so eight B300s test the quality effect without first allocating more model capacity. The initial width-768/depth-24 teacher is about 170M trunk parameters by architecture arithmetic. A separate conditional four-fit scale panel uses width 1792, depth 40, 28 heads and FF width 7168 (about 1.54B parameters by arithmetic); that count and its memory/throughput are not measured. If initial headwise teacher targets appear useful, a separately allocated four-student endpoint tests whether the difference transfers to a small Transformer. No wall-time, memory, scaling or public-score benefit is assumed.

4. **Frozen comparison.** Initial arms are `none`, `constant_half`, and `headwise`, matched within F0/seed101001 and F2/seed101002. The model is a raw112 causal Transformer, width768, depth24, 12 heads, FF3072, context1024, chunk256, dropout0, no hints, efficient exact-window SDPA and compiled blocks. Training is 30 epochs on the complete source-qualified fitting membership, `normalization_scope=all_fit`, `training_mask=all_after_warmup`, fixed final epoch29, no outer-fold checkpoint selection. All configs use 8 B300 ranks, per-rank batch1, accumulation4, Muon with peak LR3e-4, momentum.95, five FP32 Newton–Schulz rounds, auxiliary AdamW beta(.9,.95), matrix weight decay.01, no vector/bias decay, clip1, warmup.05 and `warmup_cosine_v2` to a .1 floor. `bf16_bf16x9` is explicit: BF16 forward autocast with FP32 master parameters, gradients, loss and optimizer state; set `CUBLAS_EMULATE_SINGLE_PRECISION=1`. This is not an IEEE-FP32 parity claim. The efficient-mask/compiler path must pass the receiver check and profile; no fallback may change one arm alone. KV state remains the canonical bounded cache and resets per sequence.

5. **Bounded fitting panel.** The initial screen costs 6 new teacher fits: 2 per arm, 3 arms × F0/F2. There are no reused endpoints or shared-control substitutions. Profiles, DDP checks and one/eight-rank cache parity are engineering work, not fits. Conditional scale follow-up costs 4 additional fits (none/headwise × F0/F2) and is not included in the initial six or auto-started. Conditional student transfer costs 4 more fits (none-teacher/headwise-teacher × F0/F2), with a separate one-B300 student config for each fold, seeds1001/1002, width128, depth2, four heads, context128, output KD weight1, no hints, 30 epochs, AdamW and the same BF16/BF16x9 mode. Each student's profile and fit route the identical teacher cache. Students use only the initial width768 teachers; scale-teacher transfer is not allocated. Total if every separate stage is later admitted: 14 new fits (6 initial + 4 scale + 4 students), profiles excluded. Current executed fit/profile count is zero.

7. **Leakage and coverage.** Inputs are the existing observed raw112 rows; no future competition labels enter features or autoregressive feedback. Fitting-only normalization is explicitly `all_fit`. The trainer enforces component-clean outer folds and the expected fold in each config; receiver review must verify the actual canonical split manifests and data identities. Teacher caches export only each teacher's fitting membership. They are in-sample teacher predictions on the teacher's own fitting rows, not cross-fitted targets. The evaluation fold remains excluded from teacher fitting/cache, but that does not remove teacher overfit from training targets. The transfer panel is therefore about downstream student quality under these cache semantics. All cited folds have previous exposure; no pristine holdout or future-regime claim follows.

8. **Decision-changing result.** A mean headwise-minus-none gain of at least `+0.0005 WP` with both fold deltas nonnegative is a predeclared exploratory follow-up trigger, not significance. Apply the same descriptive rule to headwise-teacher versus none-teacher students when those four fits are separately admitted. A query-dependent mechanism claim additionally needs positive `headwise - constant_half` deltas on both folds. If constant-half matches or beats headwise, the evidence supports simple attenuation at most; any attenuation follow-up needs a separate allocation, and there is no automatic 1.54B gate promotion. A negative, mixed, or small result narrows this exact model/optimizer/precision panel; it does not refute all gated attention. Scale and student stages each require a separate explicit allocation even if a trigger is met. Any failed receiver check/profile blocks fitting until a matched, reviewed source/config amendment; do not downgrade backend, compiler, precision, or one arm independently.

9. **How to run.** On the allocated Linux receiver, use a clean checkout of the reviewed full commit, `uv sync --frozen`, and the environment below. `run.sh` requires actual data/split paths, a dedicated physical-disk run root, full expected commit SHA and exact visible device IDs; it rejects wrong folds, unsupported device counts, dirty runtime sources and reused stage outputs. It is a thin, explicit CLI over canonical sequence trainer/predictor/scorer and result bundler scripts. There is no queue, automatic fit, or approval mutation.

   ```bash
   PACKET=research/experiment_drafts/transformer-sdpa-gate-20261106
   export WNN_EXPECTED_COMMIT='<reviewed full 40-character commit SHA>'
   export WNN_DATA_ROOT='/actual/canonical/data/root'
   export WNN_SPLIT_F0='/actual/canonical/f0.json'
   export WNN_SPLIT_F2='/actual/canonical/f2.json'
   export WNN_RUN_ROOT='/actual/physical-disk/sdpa-gate-20261106'
   export CUDA_VISIBLE_DEVICES='<exact eight allocated B300 IDs or UUIDs>'
   export CUBLAS_WORKSPACE_CONFIG=:4096:8
   bash "$PACKET/run.sh" check

   CELL=none_f0
   bash "$PACKET/run.sh" profile "$CELL"
   # Human reviewer copies profile_receipt.json to approved_profile.json,
   # sets approved=true, and records reviewer and review note in the copy.
   bash "$PACKET/run.sh" fit "$CELL"
   bash "$PACKET/run.sh" evaluate "$CELL"
   bash "$PACKET/run.sh" cache "$CELL"
   bash "$PACKET/run.sh" cache-parity "$CELL"
   bash "$PACKET/run.sh" bundle "$CELL"
   ```

   Repeat profile, fit, evaluate and bundle explicitly for the other five initial cells, one at a time. Export and parity-check fitting caches for the `none` and `headwise` arms if the student follow-up is separately admitted; students do not consume `constant_half` caches. The emitted profile receipt is `approved=false`; only a separately reviewed `approved_profile.json` is accepted by the trainer. Conditional scale uses `scale-profile`, `scale-fit`, `scale-evaluate`, `scale-cache`, `scale-cache-parity`, and `scale-bundle` with `scale_none_f0`, `scale_none_f2`, `scale_headwise_f0`, or `scale_headwise_f2`; those commands write under `scale-teachers/`. For student cells, bind `CUDA_VISIBLE_DEVICES` to one B300 and run `student-profile`, `student-fit`, `student-evaluate`, and `student-bundle` with one of `none_f0`, `headwise_f0`, `none_f2`, `headwise_f2`. The wrapper routes the exact matching initial teacher cache and refuses a cache without a passing one/eight-rank receipt bound to that teacher checkpoint, fold, arm and manifest. Failed outputs are preserved; use a new run root for a diagnosed retry.
