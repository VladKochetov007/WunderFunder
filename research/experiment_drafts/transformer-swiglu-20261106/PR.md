# [Experiment] Test a compute-matched SwiGLU causal Transformer on B300

Implementation and receiver launch packet are prepared; receiver acceptance is pending. No local tests, training, inference, profiles or scoring ran. This packet records the earlier SwiGLU mechanism proposed in the [causal Transformer plan](../../unified/ideas/CAUSAL_AR_TRANSFORMER_GRU_DISTILLATION_B300_20261017_R1.md) and [large dynamics plan](../../unified/ideas/LARGE_DYNAMICS_TRANSFORMER_B300_20261019_R2.md). It does not claim a novel architecture or a quality result.

1. **Status and lineage.** `H-B300-TRANSFORMER-SWIGLU-20261106` and `E-B300-TRANSFORMER-SWIGLU-20261106` are a bounded implementation of the planned gated FFN in the present GELU-only sequence Transformer. The branch starts from `research-team` commit `7e4074314a62d0907c9608f9220cf72958708a2d`. Historical configs that omit `ff_activation` and `ff_hidden` retain their config fields, GELU parameter names/order, state-dict structure and forward path. The two optional keys are not injected into historical defaults.

2. **Mechanism, prediction and falsifier.** The reference uses `GELU(up(norm(x)))`; the candidate uses `SiLU(gate(norm(x))) * up(norm(x))`, followed by the existing down projection. For this causal numerical teacher, predict a positive matched-fold difference in fixed-final pooled weighted Pearson correlation (WP). A mean SwiGLU-minus-GELU teacher difference below `+0.0005`, a fold regression, or failed receiver admission fails this specific allocation trigger. A negative screen narrows this width/schedule/precision recipe; it does not falsify all gated FFNs.

3. **Matching and planned cost.** At hidden width 768, the GELU inner width is 3072 and the SwiGLU inner width is 2048. Each has 4,718,592 FFN matrix weights per block and equal leading dense FFN matrix-multiply work per token. This does not match total parameters, bias count, elementwise work, optimizer operations or wall time: SwiGLU adds 1,024 bias scalars per layer, SiLU and multiplication, and one additional independently optimized matrix. Four new teacher fits are planned (two folds × two arms), 30 epochs each, 120 teacher epochs total, with no inherited fit endpoints. A separate allocation would fund four one-B300 students, 120 additional epochs, with zero reused endpoints.

4. **Frozen teacher recipe.** The four committed configs use T768×24, 12 heads, context 1024, chunk 256, batch 1/rank, accumulation 4, eight B300 ranks, Muon peak LR `3e-4`, momentum `.95`, five Newton–Schulz steps, 5% warmup and `warmup_cosine_v2` to `.1×` peak. Matrix decay is `.01`, clipping is 1, dropout is zero, and endpoint is configured final epoch 29. Training and normalization use each fold's complete fitting membership (`normalization_scope=all_fit`); output caches contain no hidden hints. The paired arms use the same fold and seed, schedule, membership and evaluation. Changed FFN shapes consume different random draws, so paired seeds do not imply bitwise-matched initial tensors.

5. **Precision and runtime.** The explicit recipe is BF16 autocast with BF16x9 cuBLAS emulation, using FP32 master parameters, gradients/accumulation, loss, optimizer state and exported predictions. Exact-window efficient attention and compiled blocks are explicit. This follows the [24 October precision amendment](../b300-transformer-distillation-runtime/PRECISION_AMENDMENT_20261024.md); BF16x9 is not IEEE-FP32 parity and can affect Muon GEMMs. No throughput or memory-fit claim is made.

6. **Follow-up students.** Only after a separate allocation, profile review and passing teacher-cache gates, four T128×2 GELU students may be fit: F0/seed 1001 and F2/seed 1002 from each teacher family. Within each fold both teacher arms use the same student config and seed. Each student uses one B300, context 128, 30 epochs, AdamW `3e-4`, BF16/BF16x9, `normalization_scope=all_fit`, no hidden hints and equal label/output-KD weights (`kd_weight=1`, `hint_weight=0`). This compares the resulting student quality under these teacher caches. There is no labels-only student arm, so it does not estimate KD benefit against labels alone. The one/eight-rank cache exports must cover exactly the current fold's train and validation groups, bind the selected teacher checkpoint/config/source, and pass full-array parity before students can proceed.

7. **Leakage and endpoint.** The canonical source-qualified F0/F2 split remains fixed. Teacher training and normalization use only complete fitting membership; the teacher cache exporter emits `membership=fit`; student training consumes that cache and its own fold's fitting labels. Evaluation uses the existing canonical scored mask and pooled WP metric. The final configured epoch is fixed before outer scoring; no outer score chooses an epoch. F0/F2 are exposed development groups, not a newly pristine holdout.

8. **Comparison and uncertainty.** `compare_scores.py` validates identical split hashes, official metric identity, component IDs and component-centered moments, reproduces both pooled WP scores, and reports a deterministic 2,000-draw paired component bootstrap for each fold. The panel decision uses the arithmetic mean of the two fixed teacher-fold differences and requires both nonnegative plus mean at least `+0.0005`. Two exposed fold/seed cells cannot identify seed variability, establish statistical significance, separate fold from seed, or estimate public transfer; component intervals are conditional on these fits.

9. **Receiver acceptance and admission.** On the allocated Linux host, run the receiver check stage before profiles: focused sequence invariants, existing sequence contracts/recovery/Muon tests, two-rank DDP, and two-rank FP32 Muon checks for both FFNs. Then profile each teacher cell at one/eight ranks with its production config and at eight ranks with warmup zero; profile each student config at one rank with production and peak-LR variants only if the follow-up is separately authorized. Inspect actual B300/software, split/source/config identities, finite losses and optimizer states, completed update counts, and memory by rank with at least 20% device-memory headroom. Preserve every original `approved:false` receipt. A human reviewer may copy only the identity-matching production receipt to `approved_profile.json` and set `approved=true` with a review note: teacher uses the exact eight-rank production profile; student uses the exact one-rank production profile. The trainer validates the approved receipt against the full fit identity; a peak-LR or alternate-world-size receipt cannot authorize the full fit.

10. **Execution and artifacts.** `run.sh` exposes explicit single-stage commands and fixed cell names. It has no queue, loop over scientific cells, profile bypass or automatic approval. Set `WNN_EXPECTED_COMMIT`, canonical data/split paths, a receiver-reviewed persistent disk `WNN_RUN_ROOT` and exact allocated device IDs. Run `bash "$PACKET/run.sh" check`; it records `findmnt`, `df` and `lsblk` evidence for a human storage-capacity review. Then use one reviewed cell per stage (`teacher-profile-one`, `teacher-profile-eight`, `teacher-profile-peak`, manual approval, `teacher-fit`, `teacher-evaluate`, `teacher-cache-one`, `teacher-cache-eight`, `teacher-cache-parity`, `teacher-bundle`). Repeat explicitly for the other three teacher cells. Run `compare_scores.py` once per fold after both scores exist. The separately allocated student route uses `student-profile-one`, `student-profile-peak`, manual approval, `student-fit`, `student-evaluate` and `student-bundle`; cache bindings are revalidated against the actual current split, full committed recipe, source, checkpoint, parity receipt and manifests before each stage. Teacher result bundles include fit evidence and weights, all production/peak profile receipts, approved-profile copy, cache manifests and parity receipt. Student bundles include fit evidence and weights, its profiles, approved-profile copy, and the stage binding receipts embedding the parity receipt. Preserve the receiver acceptance bundle alongside these cell bundles.

11. **Evidence and limits.** Static source/config review and Ruff/shell syntax checks are the only local validation. New receiver tests and DDP checks are definitions for remote execution and remain unrun. No B300 acceptance, numerical parity, successful compile, fit, score, cache export, memory fit, quality improvement or throughput result is established. The paper [“GLU Variants Improve Transformer”](https://arxiv.org/abs/2002.05202) motivates testing gated FFNs in its reported sequence-to-sequence setting; its results do not establish gains on this numerical competition. The `+0.0005` threshold is only a trigger for considering a separately allocated student panel.
