## Data and recipe checks

1. `age_readout_portable_builder.py` uses the canonical `SequenceFile.read(row_group, targets=False, mask=False)` path for raw features. Fit row references are ordered as source-qualified train groups followed by selected valid groups; evaluation references are the frozen valid groups. Numeric group IDs are therefore not conflated across split sources.
2. For fit rows, the builder writes the canonical 112 raw features followed by the exact transported five-column suffix. For evaluation rows, it writes raw112, literal zeros in columns 112:115, and the pinned parent prediction in columns 115:117. It retains the original full-cache NPY v1 header bytes and C-order.
3. While writing each rebuilt cache, the builder stream-hashes the exact original header and every constructed row record, then compares that digest with the original cache payload identity from the root local-cache receipt. This checks the expected full row order and all used raw, target/weight, and parent bytes without transferring or rehashing the 32 GB original cache on Kaggle. It is a hash over the generated byte stream, not a separate readback hash of the completed output file.
4. The transport and loader bind exact sidecar bytes, ordered row references, membership digests, split/subset hashes, the parent-cache milestone, and the actual-parent metadata check. The parent is the frozen CPU strict-FP32 cached prediction endpoint; the parent model is not inferred on Kaggle.
5. Raw Parquet mounts are checked by file size and Parquet footer digest. Original source paths/mtimes are stored separately from actual Kaggle mount paths/mtimes; the portable code does not forge or compare a copied mtime. The full reconstructed cache digest additionally validates every raw row group used by the frozen caches.
6. Cache construction and profiling close readers/mappings and remove derived fold caches on normal completion. The profile/fit path calls `MADV_DONTNEED` as each sampled sequence is consumed. The complete fold caches remain ordinary disk files, not a full resident array.

These checks preserve the six-cell A/G/F × F0/F1 scientific recipe and its fixed parent controls. They do not make the exposed validation folds pristine. Fit-cache parent predictions are in-sample with respect to their parent fit membership, as already recorded in the frozen cache ancestry; this is a training-distribution limitation, not a remote-grade holdout claim.
