# [Experiment] GRU / causal Transformer / Mamba-2: published source and CP30 handoff

1. **Status, lineage and owner.** Source-preservation and integration proposal, E-ARCHITECTURE-CP30-HANDOFF-20261018; H-CAUSAL-TRANSFORMER-20261017, H-CONTEXT-TRANSFORMER-20261017 and H-SELECTIVE-SSM-20261017. The prepared implementation exists at `bd78ac1048fe9d6534e76cde8c6f8ec0d6aa6acb` on `codex/transformer-mamba-gpu-wave`. It uses an older trainer and an unrun single-F0/seed3/one-epoch screen. This PR adds a current-base handoff, not an automatic merge of that trainer or a claim of executed experiments. Receiving run owner and current executable source are unbound; launch_ready=false and training_authorized=false.

2. **Why it should work.** At the same label objective, attention may retain useful selected history beyond the GRU state; extending its window tests whether additional past context matters. Mamba-2 tests selective state-space recurrence. These are candidate mechanisms, not evidence of a win. Architecture dimensions, parameter counts, optimization behavior and compute differ; a quality difference does not uniquely identify memory as the cause. C−B isolates the declared window change; B−A and D−A compare complete model families under a common declared recipe.

3. **Compute advantage.** More GPUs buy independent paired cells and, separately, larger teachers or longer training. This comparison spends on full-data repetitions before selecting a family. No scaling law, B300 throughput or public-score forecast is asserted. Report both equal-exposure endpoints and actual GPU time/memory; a compute-matched comparison would require its own frozen budget and endpoints. A teacher improvement requires a later matched compact-GRU KD test, not a promised student gain.

4. **Frozen comparison.** Proposed A=GRU256×2; B=causal Transformer256×4/8heads/FFN4/window256; C=same/window2048; D=Mamba-2 width256/layers4/state64/head64/expand2/conv4/chunk256. Same complete source-qualified fitting membership, 211 inputs, labels-only objective, cold seeded initialization policy, row order, normalization membership, loss weights, optimizer/update schedule and fixed final checkpoint. Match paired initialization only where shapes permit; different model shapes cannot have identical tensors. Freeze six full epochs, fixed epoch5, no best-validation selection. Exact common optimizer/LR/clip/batch/update budget and stable attention/SSM implementations remain binding gates; do not claim the old one-epoch runner already implements this plan. Strict FP32 weights/states/activations/gradients/optimizer; autocast/GradScaler/TF32 off. The legacy wave only requested FP32; its TF32-off path is unverified. Current adapters must enforce and record actual precision. Reset all model/feature/cache state per sequence and serialize complete architecture state for exact resume, or restart under a new attempt ID.

5. **Thirty paired runs.** F0/F1 seeds1001–1008 and F2/F3 seeds1001–1007, 30 cells for each of A/B/C/D, **120 fits total**. Three preregistered contrasts B−A, C−B and D−A. Original F0/seed3 screen and engineering profiles do not count. All folds are exposed. Bind data/split hashes, fit-only normalization and ancestry per cell; no production train+valid checkpoint may be relabeled as a clean held-out parent.

6. **Validation and significance.** Unchanged global_wp_clip2_v1 and official masks. For each contrast compute D=mean_f(mean_s(per-fit paired WP delta)), with four equal fold weights. Reuse the workflow's 10000 shared-seed bootstrap draws and separate paired component resampling, RNG20261018; eight seed identities are not 30 IID holdouts. Report marginal95% and Bonferroni98.3333% intervals for the three-contrast family, all fold means, costs, failures and exclusions. These are approximate conditional intervals, not a guarantee of power, new-regime coverage or calibrated significance. A seed ensemble or blend is a different endpoint and cannot replace the declared contrast.

7. **Leakage and coverage.** Past/current supplied features only; no future label/target inputs, bidirectional attention or cross-sequence state. Sliding-window cache, Mamba recurrent state and input transforms must pass suffix/prefix/reset/chunk invariance checks on the receiving GPU. Fold-clean normalizers and complete connected-component exclusion remain mandatory. No ranking by public leaderboard feedback. Compare any later promising endpoint against a source-qualified strong baseline; the production TL3 ensemble is not a clean F0 control.

8. **Decision-changing result.** Proposed useful threshold D≥+0.0005 WP per primary contrast, with compatible family-adjusted seed/component intervals and fold robustness; this is an allocation criterion, not a predicted effect. Report cost before deciding whether the gain merits a downstream KD comparison. No speed/CPU claim follows. Inconclusive intervals may justify bounded precision follow-up; a negative result narrows the declared model/context/optimizer budget. No dependency or profile failure is a scientific rejection.

9. **How to run.** From a complete current checkout, `python scripts/experiment_draft_plan.py research/experiment_drafts/architecture-cp30-handoff/recipe.json` prints metadata only; it was not run. There is deliberately no runnable current-base training command yet. Reuse `wnn.training` model/forward/state/input/optimizer/checkpoint/provenance seams and current per-cell infrastructure. Port only reviewed architecture modules from the frozen source, retaining current prediction safety and trainer changes. Bind Linux/CUDA environment and pinned Mamba build, data roots, output paths, actual device profile and per-cell owner before any fit. Do not execute the historical host runner as this CP30 design.

10. **Evidence to return.** Exact current source and inherited module pins; data/config/split/environment identities; architecture/parameter/FLOP counts; per-cell row/update/checkpoint identity, losses, LR, preclip norms, clipping/nonfinite counts, time and peak memory; complete predictions/official grades and paired uncertainty. Return weights separately from evidence with SHA256 manifests and approved storage locations. Profile/support work must be reported separately from scientific fits; failed cells never become zero scores or silent exclusions.
