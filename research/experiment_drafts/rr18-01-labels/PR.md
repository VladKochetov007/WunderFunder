2. **Why it should work.** One broad recurrent layer may provide useful state capacity with fewer serial recurrent transformations than two narrower layers, improving the quality/cost tradeoff for a causal sequence model. The discriminating observation is the paired endpoint contrast between H512×1 and H384×2 after the same cold labels-only fit schedule, followed by measured CPU-serving latency. The strongest alternative is that any score difference comes from residual parameter-count mismatch or optimization behavior rather than width/depth organization. The current treatment changes hidden width and layer count together, so it tests an architecture choice near a fixed parameter budget; it does not isolate “depth alone.” The old H512×1/H256×2 screen reported 0.67323776 versus 0.66977764, but it combined a 2.27× parameter gap with a teacher-target coefficient of 0.9 and propensity weighting. It is not evidence for the cold labels-only effect tested here.

3. **Compute advantage.** The expected engineering advantage is less sequential recurrent depth for the H512×1 arm, with quality held as the primary outcome and CPU latency measured before an architecture recommendation. The current compute ladder is the frozen Beleriand paired CP30 recipe; no larger-model scaling or leaderboard gain is inferred from it. A DataSphere/B300 follow-up could buy additional training only after the paired result justifies it and a finite campaign allocation is recorded; its current GPU-hour budget is null, so no paid cloud job is admitted.
