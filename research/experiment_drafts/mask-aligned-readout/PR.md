# Run the four-fit mask-aligned readout experiment on B300

1. **Status and lineage.** Implements the existing #36 proposal on `experiment/mask-aligned-readout`, targeting `research-team`. This is a child of H-023/H-030/H-035 in the mask/propensity fine-tuning line, affecting the student/readout rather than the teacher or distillation link. Status: implemented, unvalidated on B300; zero new fits, profiles or evaluations. [README.md](README.md) contains executable receiver commands; [recipe.json](recipe.json) fixes the experiment. The original proposal is preserved in [PROPOSAL_20261022.md](PROPOSAL_20261022.md).

2. **Mechanism.** The competition objective uses scored rows, while the control trains on all valid prediction rows. Weighting fitting losses by real fitting-side `is_scored` may better align readout updates with that scored population. Expected observation: a positive matched treatment-minus-control weighted-Pearson delta. The frozen trunk and shared initialization isolate the readout-weighting intervention; parent quality, fold and seed remain confounded between cells. The public [MarkBrezina repository](https://github.com/MarkBrezina/WunderConnectome/tree/5d086fc90ea0c11a39391dde702e2a4f0a47a869) supplied an author-reported lead, not a verified competition result; no code or weights are copied.

3. **Compute advantage and budget.** Reuse two existing frozen GRU parents and train exactly four new heads. New parent fits: zero. Two bounded engineering profiles precede fitting and produce no scientific checkpoints. Full selected fitting components are used; there is no proxy subset, adaptive search or automatic budget expansion. Runtime savings and B300 throughput are unmeasured.

4. **Fixed comparison and implementation amendment.** Each cell starts both arms from identical pinned `@ep3` parent bytes. Freeze `inp,gru`, inherit preprocessing, use valid-side fitting data with fraction 1.0, clear propensity/class/episode weighting, and vary only `--mask-weight`. Both H256×2 parents retain WMSE and auxiliary coefficients 0.3/0.3, since-weight 32/floor 0.25. The canonical mask affects main **and auxiliary** loss weights: the estimand is explicitly scored-row weighting of the configured readout objective, not main WMSE alone. New fits use fresh AdamW LR 5e-4, weight decay 0.01, one-cycle scheduling, one epoch, batch 32, chunk 2000; fixed epoch 0 and no outer-fold evaluation during fitting. New computation is FP32, autocast/TF32 off. Exact historical FP16 parents are retained for this diagnostic; no end-to-end FP32-history claim. Before/after audits enforce frozen parameter and preprocessing invariance.

5. **Cells.** F0/seed1001 uses `oldz4_h230_parent_f0_s3_r3@ep3`; F2/seed1002 uses independent `h382_muonall256prop0_f2_s3_e4@ep3`. Each has `all_valid` and `is_scored_weighted`, giving four fits total. Checkpoint, provenance and split SHA-256 pins live in the recipe. Missing artifacts stop execution; no silent alternate checkpoint or cross-fold substitution.

6. **Validation and uncertainty.** Canonical `global_wp_clip2_v1`, targets/predictions clipped to [-2,2], complete held-out coverage and scoring on `need_prediction & is_scored`. Primary: treatment-minus-control delta per fold and equal-cell mean, with per-target scores. Use the canonical paired whole-component bootstrap, 10,000 replicates per fold and independent streams from seed 221022; average matched fold draws to obtain the equal-cell interval. It measures conditional component-sampling sensitivity, not fit/seed/parent uncertainty. Both folds have previous exposure; this is a two-cell screen, not a significance claim. Secondary: unchanged parent, fixed 0.75-parent/0.25-child blends, their deltas against the parent and treatment-blend minus control-blend. No weight search.

7. **Leakage and coverage.** `train.parquet` lacks `is_scored`; this head-fit experiment uses the real mask only on valid-side fitting components. It never constructs a train-side pseudo-mask or feeds masks into the model. Canonical campaign splits bind source-qualified fitting/evaluation membership; held-out components are excluded from fit weights, preprocessing and checkpoint selection. Parent preprocessing and frozen tensors must remain unchanged; prediction export is feature-only. Legacy parents are checked against exact pinned artifacts and recorded provenance, without pretending they contain newer metadata. Unknown historical ancestry is not upgraded to a new clean-history certificate.

8. **Decision.** Mean paired primary delta ≥ +0.0003 and both cells nonnegative supports a separately budgeted confirmation. Mixed signs are uncertain; an interval crossing zero alone is not a kill rule. Both cells below the useful threshold narrow or stop this exact recipe. A missing asset, source/membership mismatch or failed finite-update/memory check stops the current run rather than changing the experiment. Wider temporal/regime generalization and submission value remain unknown.

9. **Execution.** [receiver.py](receiver.py) orchestrates the existing `scripts/train_rnn.py` and `scripts/predict_run.py`; it does not duplicate the trainer. Provide [receiver-assets.example.json](receiver-assets.example.json), install the locked Linux CUDA environment, and invoke `preflight → profile → fit → predict → score` as documented in [README.md](README.md). Profiles prove actual trainer-process B300 UUID, driver, strict FP32, finite updates and ≥10% memory headroom. New child provenance captures that actual-process runtime. Source identity includes all Python under `src`; evaluator identity additionally binds packet code and prediction entrypoint. Snapshot fields recording no execution in this delivery are not runtime permission gates: a future explicit receiver command is the operator's execution decision.

10. **Returned evidence.** Persist profile receipts; exact parent, split and source hashes; head-only trainables; frozen-state and preprocessing identities; child provenance/checkpoints; full-coverage predictions and their hashes; and `grade.json` with paired intervals, all secondary endpoints, target-cache, recipe, audit and evaluator-source bindings. Keep failures and do not silently overwrite prior artifacts. Scientific checkpoints and heavy weights remain separate from code/evidence. Actual runtime, memory and scores are not populated with estimates.

11. **Validation performed and limitations.** Static source, formatting and structural checks are recorded in [VALIDATION.json](VALIDATION.json). Receiver tests are provided for later execution. Local tests, training, model inference and B300 jobs were not run. This PR contains runnable implementation and explicit missing-asset checks; it does not claim a successful GPU run or a submission improvement.
