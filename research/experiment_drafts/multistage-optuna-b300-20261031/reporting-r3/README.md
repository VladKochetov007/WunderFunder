# Multistage GitHub reporting R3

New self-contained reporting capsule. Reporting R2, training Source4 and scientific outputs remain unchanged. Existing inner-control mirror views and exact terminal-fit deduplication are retained.

R3 reads at most four full-primary refits directly from their prepared selection and actor runtime roots. It creates no entries in the old native mirror. Each additive view uses stable `s4-<fit_id>` identity, Stage4 and `phase=primary_refit`; receipt binding covers the prepared request, selected config, owned fit launch, approved profile and separate root approval. Admission requires fresh Source4, 10325 source-qualified train fitting members, 1873 source-qualified valid evaluation members, train-only normalization, and no transferred initializer or teacher. Auxiliary8260/control runs cannot enter this path.

Native metadata, evaluation labels and contexts remain intact, including an absent native `primary_split_sha256` when `split_sha256` carries the exact official primary identity. Derived snapshot identity records the official primary split. Journals retain their original raw SHA/byte/line identities and existing declared train-step stride10; all other events and evaluation events remain preserved. Full valid is development-exposed reporting.

After root stops only the exact owned old publisher and deploys the verified new capsule, launch:

```sh
PYTHON reporting-r3/scripts/multistage_github_publish.py \
  --runs-root H/dashboard-runs-r2 \
  --primary-prepared-root H/campaign-r2/primary-refits-prep-r1 \
  --primary-runtime-root H \
  --token-file EXISTING_PRIVATE_TOKEN_FILE \
  --state-file EXISTING_PUBLISHER_STATE_FILE \
  --deadline-epoch 1793425269.6589406 --poll-seconds 120
```

Use the same restart state after the owned publisher stops to retain terminal/hourly comment deduplication. Primary runs whose launch receipts or native journals are not ready are omitted until a later cycle. Existing inner views continue to use the existing mirror root.

The local GitHub mirror must also use R3 because the older snapshot validator accepts only Stage1-3 inner-control runs:

```sh
PYTHON reporting-r3/scripts/multistage_github_mirror.py \
  --git-root EXISTING_GIT_ROOT --runs-root EXISTING_LOCAL_DASHBOARD_MIRROR \
  --deadline-epoch 1793425269.6589406 --poll-seconds 120
```

This capsule includes the unchanged `publish_checkpoint_releases.py` dependency used by the local mirror. No publication or network request happens during imports or CPU tests. Root owns deployment and external execution.

Checks: `python scripts/multistage_github_test.py` and `python scripts/multistage_github_primary_test.py` (nine CPU-only tests). Source hashes and file sizes are bound in `SOURCE_MANIFEST.json`; generated bytecode is excluded.
