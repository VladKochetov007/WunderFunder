2. **Question.** Does output distillation improve a compact raw-112 Transformer over its same-cell label-only control, and how does its KD endpoint compare with the exact PR28 GRU-KD endpoint? The cross-architecture comparison is descriptive: model shapes, parameters and FLOPs are not matched. Existing rationale is in [Section 25 of the canonical note](https://github.com/VladKochetov007/WunderFunder/blob/experiment/streaming-student-distillation/research/unified/ideas/CAUSAL_AR_TRANSFORMER_GRU_DISTILLATION_B300_20261017_R1.md#25-distill-to-the-architecture-we-can-actually-serve).

3. **Why this is useful.** A bounded streaming Transformer may transfer behavior that differs from the recurrent baseline, while its actual inference cost remains unknown. Same-architecture label-only controls isolate the incremental KD contrast. The two-cell panel is a focused executable amendment, not a replacement for the historical broader architecture/window portfolio and not evidence of CPU deployment value.

4. **Frozen configs and objective.** New fits are F0/seed1001 and F2/seed1002, each with `student_t128_labels` and `student_t128_kd`. The model consumes 112 raw features and uses width128, two layers, four heads, FFN multiplier4, dropout0, and sliding KV context128 per layer. Each run uses three epochs, batch1, four accumulated 256-row chunks, AdamW LR`3e-4`, weight decay`.01`, clip`1.0`, warmup fraction`.05`, and the first32 fitting sequences for normalization. The label arm uses `label WMSE + 0 × KD WMSE`; KD uses `label WMSE + 1.0 × KD WMSE`. Both configs retain a learned 64-dimensional hint projection with hint weight0, as required by the shared model schema. All arithmetic is strict FP32; autocast, GradScaler, TF32, and quantization are disabled. Exact runtime configs are under `research/experiment_drafts/b300-transformer-distillation-runtime/configs/` at the pinned runtime source.

5. **Four new fits and reuse.** PR30 adds four student fits. It reuses two exact T768×24 teacher models/caches and four GRU256 label/KD endpoints from PR28: F0/student seed1001/teacher seed101001 and F2/student seed1002/teacher seed101002. Reuse is valid only when source, split/component membership, config, seed, cache manifest, and endpoint hashes match. A mismatch requires a separately reviewed source/cache binding; do not reuse by filename.

6. **Primary comparison and interpretation.** The primary contrasts are KD minus label-only within F0/seed1001 and F2/seed1002. Report both folds and both targets, pooled official `global_wp_clip2_v1`, uncertainty, memory/time, and the exact matched controls. A `+0.001 WP` gain is a useful signal for a bounded follow-up, not an automatic promotion rule. A smaller or mixed result, or an interval crossing zero, is not an automatic rejection. The comparison to PR28 GRU-KD is secondary and is not parameter- or FLOP-matched. Do not infer replication or generalization from two exposed cells.

7. **Causal and data controls.** Bind canonical source-qualified F0/F2 splits, component manifests, fitting membership, normalizer, teacher checkpoint/cache provenance, and all input hashes before admission. Forward complete ordered sequences from row zero and reset state per sequence. Warm-up rows0–98 remain in the forward pass but are excluded from the fit/score mask. Preserve source/target row alignment and teacher mapping; no teacher output is an inference-time feature. Apply only the fixed terminal epoch, with no outer-validation checkpoint selection.

8. **Risks and falsifiers.** The architecture comparison has unequal shapes and possibly unequal compute; it cannot establish architecture superiority at equal parameters/FLOPs. Output KD may fail to improve its matched labels-only student. Sliding-cache correctness, B300 performance, resource headroom and eventual CPU serving remain unmeasured until receiving-host checks. A positive KD result alone does not establish a deployable model or justify quantization.
