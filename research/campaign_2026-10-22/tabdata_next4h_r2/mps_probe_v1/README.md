# Private MPS engineering probe

[Result summary](RESULT_SUMMARY.json) and the exact [profile runner](mps_probe.py) record a78.6-second two-mode probe on GPU0 while the22 existing non-MPS fits continued. Both modes used the same fresh seed, H256x2, batch32, strict FP32, canonical source and two objective arms. Each arm passed60 finite successful optimizer updates. The added pair achieved roughly0.79x its direct-mode sequence throughput under MPS. This is a conditional small profile; aggregate throughput of existing co-resident jobs was not measured, so it is not a universal MPS rejection or a full-node speedup measurement.

The controller used only a fresh0700 private pipe/log directory and foreground daemon in its own systemd cgroup. It changed no GPU compute mode and never connected to or signaled foreign MPS processes. Its own daemon exited0, its pipe was removed and final CUDA/MPS-client counts were zero. A270-second runtime,20-second stop and10-second finalizer bounded the probe inside five minutes and within the original node wall. Generic MPS-client force-termination was not validated for long scientific fits, so MPS was not promoted to the training cohorts. No model-quality score or checkpoint resulted. Raw timing, allocator, GradStats, server/cgroup and cleanup evidence remain in the recorded node path.
