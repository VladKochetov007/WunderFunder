# LB-пары: проверка «ручек» данных на тесте (4 октября)

Каждая пара — 2 модели h128 на Muon ×6 (seed 3 и 4), обученные на всех данных с дообучением головы на valid.
Пары отличаются **одной ручкой**. Скорер ~4–7 мин на пару. Абсолютный балл пары ниже ансамбля из 5 моделей (ожидаю ~0.660–0.663); важна **разница с `pair_base`**.

Почему так: решения о данных у нас переносились на тест ~1:1 (valid в родителе +0.0024 локально и на LB), а улучшения модели — на ~10% (Muon: +0.002 локально, +0.0002 на LB). Локальный шум одного прогона ~0.0012, поэтому малые эффекты различает только LB.

## Порядок отправки
**День 1 (5 посылок) — использование valid, самое переносимое:**
1. `pair_base.zip` — контроль.
2. `pair_v2.zip` — valid ×2 в обучении родителя (×1 = 0.6641, ×3 = 0.6611 на старом рецепте).
3. `pair_fullft.zip` — дообучение на valid всей сети (lr 1e-4, 2 эп.) вместо только головы.
4. `pair_ft4.zip` — дообучение головы 4 эпохи вместо 2.
5. `pair_vtm0.zip` — в родителе неоцениваемые строки valid с весом 0 (учимся на valid только по маске).

**День 2 — веса train:**
6. `pair_prop1.zip` — пропенсити p¹ вместо p² (теоретически «правильный» вес по метрике).
7. `pair_classmix.zip` — доли классов train как в valid.
8. `pair_advval.zip` — вес train-последовательностей по похожести на valid.
9. `pair_quiet.zip` — перевес тихого класса 3 (локально не подтвердился на 2-м seed — проверка).
10. `pair_since0.zip` — без since-weight (локально −0.002).
11. `mix8.zip` — ансамбль 8 моделей с разными взвешиваниями данных (~35–40 мин).

## Добавлено 4 октября днём: крупная ставка
- `pair_onorm.zip` — модели видят кроме сырых признаков их причинные z-оценки внутри текущей последовательности (адаптация к распределению каждой последовательности на тесте).
