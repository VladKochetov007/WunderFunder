# Prediction-audit implementation review

Date: 2026-10-17. The initial code review was read-only and covered `prediction_audit/run_prediction_audit.py`, `prediction_audit/prediction_audit_core.py`, `prediction_audit/gmetric_standalone.py`, and `theory/derive_sequence_decomposition.py`. I did not execute code. The canonical `src/wnn/gmetric.py` and standalone metric file have no textual diff. This addendum records the separate alignment validation and corrected presentation produced afterward.

## Sufficient-statistic decomposition check

On exact-file recheck, the within/between formulas in `derive_sequence_decomposition.py` are correct: `within_y = Σ(wyy − wy·seq_y)`, `within_p = Σ(wpp − wp·seq_p)`, and `within_cov = Σ(wyp − wy·seq_p)`, with `seq_y=wy/weight` and `seq_p=wp/weight`. The between terms use the same sequence means and global means. The script's canonical-score reconstruction guard is useful. Raw second-moment subtraction is less stable than the canonical centered accumulator, so the decomposition is descriptive and should remain accompanied by its score-difference check.

## Exact target, mask, and row-order binding

At sequence level, the audit does useful alignment checks: it requires target-cache row groups to be exactly `0..1872`, validates the Parquet row-group count and 20,000-row length, and during grading checks every Parquet `seq_ix` in a selected group against the cache's sequence ID. The fold cache is reindexed by row-group ID. The chosen prediction arrays are shape/dtype checked and finite-group coverage is fixed before grading; all comparisons use one shared whole-group intersection.

At the initial review, the in-audit checks stopped at group identity: they did not compare the score mask, target values, or within-group step order to Parquet. A separate later validator closed that target-cache alignment gap on the full shared panel. Its receipt reports exact alignment on 467 row groups / 9,340,000 rows, with zero mismatches in `seq_ix`, `step_in_seq`, target values, `need_prediction`, scored mask, and official score mask; the 846,654 selected-row count also matches. See the [alignment receipt](../prediction_audit/ALIGNMENT.json). This validation does **not** prove prediction-array producer order: the arrays still have no matching producer receipt, so their sequence and within-sequence order are inferred from the intended cache contract rather than verified from the prediction files.

The grade phase rechecks size, mtime and inode for target/fold caches and Parquet, not their full SHA-256 values. Prediction files are SHA-256 checked before and after grading. A same-size, same-mtime replacement of a target/cache/Parquet file could evade the phase check; this is an integrity-hardening gap, not a likely accidental path. A stronger integrated audit would recheck inventory hashes and retain the validator's target/mask/step comparison. The fold alignment helper also builds a dictionary before comparing key sets; duplicate valid `row_group` records can silently overwrite one another while set coverage still passes. Check uniqueness and length before constructing the mapping.

## Causality and preprocessing claims

Inventory records hashes for current `predict_run.py`, `train_rnn.py`, and `nn.py`, plus a checkpoint and history hash, but explicitly does not bind those files to the cached predictions. It does not record a complete dependency/environment manifest for input decoding and preprocessing. Thus current source comments and the checkpoint can support an intended interpretation, but they cannot prove how a historical cache was produced or that every preprocessing path was causal.

There is a small logic/report mismatch in the lookahead gate: `settings.get("lookahead") not in ("", None)` accepts a checkpoint with no `lookahead` key, while the receipt then says the inspected args had empty lookahead. Missing should mean “unknown”; require the field and explicit empty value if this check is meant to attest to it. The three checkpoint records inspected in Round 3 do have an explicit empty `lookahead` value. That resolves the ambiguity for those records, but the absent cache-to-checkpoint receipt and incomplete preprocessing/environment manifest still leave the stored predictions unbound to those checkpoints and current source.

The event flags read `i0_p0`, `i0_p11`, and `seq_ix` from the same physical Parquet row group, cast price codes to float32, then compare adjacent values. The project data reader also materializes model-visible features as float32, so this is consistent with the current model input representation. Row zero is deliberately not an event. One interpretation detail: `age_buckets()` initializes the last-event index to zero, so ages before the first actual AND event are rows since sequence reset, not elapsed time since an observed event. The first age bins must be described with that left-censoring/reset convention.

## Transform semantics

The no-fit scenarios are causal transforms of saved predictions, not hidden-state interventions. `hold_until_event()` forces the baseline output at row zero and then repeats the most recent emitted prediction until the next selected event. The cached recurrent model has already produced its output at every row; output holding does not stop those latent updates. Cadence is anchored at sequence row zero. The EMA is reset per sequence, uses `alpha = 1/tau`, and initializes so its first output is exactly the first baseline output. Therefore `tau` is a reciprocal step size, not the EMA half-life. Raw-input EMA is clipped only by the official scorer; clipped-input EMA clips before filtering. The half blend is formed in raw prediction space and then clipped by the scorer.

The `quiet_not_and` region is the complement of the AND clock and therefore includes OR-only changes; it is not a “no input changed” region. The exception region is based on raw cached target changes, whereas the retrospective plateau oracle groups by clipped labels. Those definitions answer different questions when two raw labels differ but clip to the same score label.

The label-run oracle is implemented in the right score space for its stated diagnostic: clip each target and prediction first, identify runs separately per target using equality of clipped labels, and average only selected clipped predictions within each run. The official weight is constant over such a run, so an unweighted selected mean is also the weighted mean. Its scored outputs preserve target–prediction covariance within runs and remove the measured within-run prediction variance up to float32 rounding. The resulting WP identity is a valid diagnostic check. It is intentionally noncausal: future labels define run membership, and future predictions contribute to the average. It is not a Bayes ceiling, deployable candidate, or evidence that a model can know a label plateau online.

## Metric, bootstrap, and sufficient-statistic interpretation

The standalone scorer is textually identical to `src/wnn/gmetric.py`. It validates selected values, casts to float32, clips to `[-2, 2]`, weights by absolute clipped target, and uses centered weighted moments for the pooled Pearson calculation. The streaming moment merge is the appropriate stable path for the score; zero-weight labels contribute no moments. The audit's direct weighted-MSE calculations also use the same clipped values and target weights.

The chain bootstrap resamples unique chain IDs with replacement, maps each draw to multiplicities for its member sequences, and uses the same resampled clusters for every scenario and model. It reconstructs pooled moments from the saved per-sequence centered moments, then forms scenario-minus-baseline deltas, so the pairing logic is sound. Its scope is only conditional uncertainty for these fixed cached outputs on the shared fold-0 panel; it does not include training-seed, fit, checkpoint-selection, or pristine-holdout uncertainty. It uses 512 percentile-bootstrap replicates, so tail quantiles have finite Monte Carlo resolution.

The original score JSON exposed two ambiguous names: an `exposure.selected_rows` count actually meant rows changed by the transform *and* selected by the official mask; bootstrap `mean_delta` meant the resampled-bootstrap mean, not the observed fixed-panel scenario-minus-baseline delta. The append-only [corrected presentation view](../prediction_audit/RESULTS_CORRECTED_VIEW.json) renames the former to `changed_selected_rows`, records `observed_delta` from canonical scenario WP minus baseline WP, and calls the resampled quantity `bootstrap_mean_delta`. The [bootstrap summary](../prediction_audit/BOOTSTRAP_SUMMARY.json) uses those clarified fields. The correction changes labels and adds derived reporting fields only: it does not change predictions, masks, moments, scores, bootstrap replicates, or intervals.

The saved six raw sums per sequence, target and scenario are sufficient to reconstruct pooled raw moments. Within- and between-sequence covariance terms in `derive_sequence_decomposition.py` are components over the *same full-panel denominator*; they sum algebraically to pooled correlation when the variances are correct. They are not independent subgroup correlations, causal effects, or removable error budgets. Raw second-moment subtraction is less stable than the canonical centered accumulator, so the reconstruction assertion is valuable.

## Required interpretation limits

The audit is a useful fixed-prediction test of emission policies. A loss under output holding would show that changing emissions hurts these existing predictions under this panel and scorer; it would not prove that price-event exceptions are predictively useful, that hidden state should update on quiet rows, or that hidden-state freezing worsens score. Conversely, an oracle gain would quantify removable within-clipped-label-run output variance for these predictions, not an attainable online gain or a Bayes ceiling. Any conclusion about the original mechanism needs the separate hidden-state/output-policy evidence and the new exception-level residual/weight data, with provenance limits kept attached.

The later canonical retry confirms all causal output transforms have negative observed deltas on the shared fold-0 panel, with paired 95% chain-bootstrap percentile intervals below zero across the three arrays. These are deterministic causal transforms of the saved row-ordered values; they are not evidence that the historical producer itself was causal. The target-cache alignment pass does not repair that provenance gap, and no hidden-state-update intervention was performed.
