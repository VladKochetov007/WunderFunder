# Fixed causal Kalman input probe

This packet contains an isolated NumPy reference and a prediction-only frozen-GRU replay. The filters, synthetic checks, first-eight input projection and corrected full replay are complete. Attempt r1 failed in the output-width guard before model construction or inference; corrected attempt r3 used the checkpoint head width and completed the three-arm replay. An independent grader then reported a small positive local-trend point difference on the selected exposed-F0 panel, with a conditional component interval that nearly crosses zero. This is an exploratory fixed-model screen, not clean validation or a trained-feature result. See [R2 results](RESULTS_R2.md) and the raw [grade receipt](grade_r2.json).

## Frozen question and recipe

[recipe_r2.json](recipe_r2.json) is the corrected runnable recipe; [recipe.json](recipe.json) is retained unchanged as the r1 contract. Both compare the unchanged `warm_mechanism_f0_s3_c_r3@ep1` endpoint with two fixed input replacements on the first 16 source-qualified F0 evaluation groups. The parent checkpoint is SHA-256 `78357eca2aec188e227544d46887935265720c35e99a1437269b952d01eb88c2`. Arms replace raw columns `0, 3, 52, 55` with either scalar random-walk or local-trend posterior levels. They process all 20,000 rows per sequence and reset state between sequences.

The transform uses the four μ/σ values extracted from the frozen parent's buffers in [kalman_parent_normalization.json](../kalman_parent_normalization.json), with exact full-buffer hashes checked again after checkpoint load. No evaluation rows fit statistics or select Q/R. `build_inputs` first constructs the existing 99 event features from original raw input; the injected `TrainingEnvironment.forward_chunk` dependency then copies each chunk and replaces only those four raw slots. The model width remains 211 and no learned weights or official metric are modified.

[frozen_gru_probe.py](frozen_gru_probe.py) defaults to a metadata-only, no-Torch preflight. It validates the 16 frozen row groups and sequence IDs, source/data metadata, normalizer, and hashes of the probe and reused training components. The r1 receipt is preserved at [preflight_receipt.json](preflight_receipt.json); corrected source and membership pins are in [preflight_receipt_r2.json](preflight_receipt_r2.json). The r2 live receipt is at `/home/vlad/development/wunder/research_tmp/kalman-online-20261018/kalman_gru_probe_preflight_r2.json`. The runtime branch reads `SequenceFile.read(targets=False, mask=False)` and saves each arm's row-group IDs, sequence IDs, and float32 predictions without labels or masks.

The exact execute command is frozen in `recipe_r2.json`. It used batch 1, chunks of 4,000, FP32, TF32 off, a 5,000,000,000-byte RAM limit, one GPU, and a separate r2 output directory. The completed [r3 execution receipt](replay_execution_r3.json) records a 104.4-second replay, 1.126 GB worker-cgroup peak, 350 MB sampled GPU memory and zero OOM events. Process RSS was reported as 1,434,452 KiB and differs from the worker cgroup peak; both readings are retained. No labels or masks were read during prediction.

## Checks and observed input behavior

- [synthetic_receipt.json](synthetic_receipt.json) records finite 20k-row outputs, future-perturbation prefix invariance, exact A-B-A reset, constant/extreme stability, local-trend covariance PSD, random-walk steady-state equivalence to a matched constant-gain EMA, retained raw inputs, and exact streaming/batch posterior agreement.
- [f0_input_projection_receipt.json](f0_input_projection_receipt.json) records an earlier feature-only projection of the first eight F0 groups. It read only the four selected channels, processed 160,000 rows, checked actual A-B-A prefix equality, and used no Torch, GPU, labels, or masks. This is input-path evidence, not a model score.
- [f0_first_group_raw_filtered_innovations.png](f0_first_group_raw_filtered_innovations.png) shows only the first 1,000 rows of one sequence across four selected channels. In that panel, the scalar filter lags transitions and the local-trend filter overshoots at plateau entry. These are descriptive visual observations; they do not establish physical price/noise meaning or target relevance.
- [execution_measurement.json](execution_measurement.json) preserves the resource-meter discrepancy from the synthetic run. Its process `ru_maxrss` reported 841,376 KiB despite the requested 500 MB cap. The synthetic command's scope unit was not recorded; after it exited, systemd had discarded its cgroup path and its `memory.current`, `memory.peak`, `memory.events`, and `MemoryMax` could not be inspected. Wrapper enforcement for that run is therefore unverified. The unrelated active grader scope's readings are explicitly not attributed to this run. No rerun was made.
- The admitted r1 attempt was a 5-second implementation failure, not a Kalman or model result: it deserialized the checkpoint on CPU, then stopped at the bad width guard before model construction, state loading, CUDA transfer, any sequence read, or forward. Its durable attempt record and log are hash-pinned in [execution_failure_r1.json](execution_failure_r1.json). A metadata-only checkpoint inspection used one CPU and a 1,000,000,000-byte cgroup limit (measured peak 299,560,960 bytes). The corrected r2 preflight revalidated the same frozen 16 groups under a 500 MB limit and 20% CPU quota, with no Torch import, payload load, GPU use, or OOM events; the subsequent r3 replay passed its fresh one-worker admission without OOM.

The checkpoint's empty legacy `args.aux` string coexists with `head.2.weight` shape `(23, 256)` and a 23-element bias. The corrected model factory call takes output width from the stored weight tensor, as the canonical loader does. The checkpoint loss is `wmse` and its readout is `None`; the default replay environment also has no readout tables, so `evaluation.predict` returns the first two model outputs. This matches the prediction cache's two-column shape.

The input plot and synthetic checks motivated this fixed-replacement diagnostic. F0 is exposed and the 16-group panel was selected before scoring; its score is descriptive and cannot establish a family-level result. The score and limitations are documented in [RESULTS_R2.md](RESULTS_R2.md). An independent CPU scorer and alignment audit reproduced the score and component intervals to floating-point precision; see [receipt](independent_regrade_r3.json) and [scorer](independent_regrade_r3.py). Its `p_le_0` field is a bootstrap tail fraction, not a two-sided significance test. The frozen GRU was never updated, so the replay says nothing about learned Kalman features, model online learning, student transfer or a submission endpoint.
