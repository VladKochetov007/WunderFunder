# PR17: causal local-trend teacher and distillation

This package is the full Git source tree at `588b93f9c2ad7e53aac7b1e2a39f30c32047ea22`; the recipe names base `origin/research-team@1ff144e09`. It contains the full `src/`, the eight-file adapter delta (including `scripts/train_kalman_teacher.py`, checkpoint reconstruction in `predict_run.py`, and teacher validation/cache construction in `build_distill_cache.py`), canonical trainer/scorer, split/data helpers, committed folds, `pyproject.toml`, `uv.lock`, and PR/recipe documentation. Its tiny NumPy synthetic prototype/receipt is included and is not task or B300 evidence.

The trainer wrapper accepts `--kalman-arm raw|ema|fixed|learned` and `--kalman-channels pilot4|all112`, then forwards the normal canonical trainer arguments. Direct teachers start from fresh weights, use canonical WMSE, H1024×2, batch 16, chunk 2,000, strict FP32, AdamW (`lr=.001`, `wd=.01`), OneCycle, clip 1, two epochs and the fixed epoch-1 endpoint. The direct matrix is four arms × two scopes × CP30 = 240 teacher fits. The required first profile is the learned `all112` H1024×2 shape with one warmup and four measured updates. The exact command template is in `recipe.json` under `commands.profile`; smoke is `scripts/train_kalman_teacher.py --synthetic-smoke --kalman-arm learned --kalman-channels all112`. Neither was run during packaging.

The full proposal adds three H256×2 student arms (90 more fits), making 330 total. Their epoch-1 endpoint uses a same-fold four-family distillation blend: `strong`, `full_finetuned`, `raw_wmse`, and `samefold_baseline`, with total coefficient 0.8125 and student alpha 0.5. The treatment replaces only `samefold_baseline` with the matching fold/seed learned smoother at the same coefficient. The draft does not supply the required clean per-fold/seed teacher registry, run IDs, fixed epochs, coefficients, checkpoint/provenance hashes, or split-bound cache identities. Do not admit student cells until that lineage is reconstructed and validated. No checkpoints or teacher caches are in the package.

The four committed fold manifests are included. The package contains source helpers for targets, graph and split handling, but no raw parquet, target/cache arrays, or `chain_folds.npz`; that last file has no producer in this source commit and must come from the verified canonical data package. PR17 records no B300 profile, task fit, teacher cache, or grade. The eager Python time loop and the 448 added channels for `all112` remain actual-device memory/throughput risks.

## Independent implementation audit

At pinned commit `588b93f9c2ad7e53aac7b1e2a39f30c32047ea22`, the local-trend recurrence is causal and its posterior state is carried across chunks and reset for each sequence batch. The current synthetic smoke is much narrower than the planned trainer: it checks a 24-row prefix and reset, finite loss, and only the learned level-process-noise gradient. It does not compare against an independent Kalman oracle, test chunk continuation, perform an optimizer update, or round-trip a checkpoint through prediction/cache export.

Before admitting PR17 fits, fix/test the wrapper's precision guard: it accepts duplicate flags such as `--precision fp32 --precision bf16` because it checks only the first occurrence, while the canonical parser uses the last. Explicitly assert highest float32 matmul precision in addition to disabling TF32. Bind `src/wnn/features.py` and `src/wnn/data.py` into model-source identity; validate recipe-critical checkpoint arguments in the cache builder; and export with explicit `--epoch 1` so prediction sidecars bind the fixed checkpoint checked by the cache builder. The current source identity covers the adapter and GRU core but omits those imported feature/data semantics.

Minimum bounded gates: (1) CPU scalar float64 Kalman oracle for fixed/learned filters, including the current initialization convention (seed level from x0 and then assimilate x0), covariance/finite/gradient checks, one-shot versus carried-chunk equality, independent sequence reset and future-prefix invariance; (2) tiny CPU shared-trainer update with FP32/autocast/TF32 assertions, finite gradients, learned-Q/R update, fixed epoch1 save/reload and prediction-sidecar hash checks; (3) synthetic B300 all112 shape at B16×T2000, input211, H1024×2, strict FP32 actual forward/backward/AdamW, one warmup plus an update, peak memory/timing/headroom capture, then streamed T20000 prediction and checkpoint/export parity. The required student source registry remains absent and must bind per-cell source run IDs, epochs, weights, checkpoint/provenance hashes and fold lineage before any KD cache or student fit.
