# TL3 final-supervision capability audit

**Status: static capability audit only.** This packet reads and pins the R2 matched-design proposal and relevant canonical and archived source. It makes no source changes, runs no tests or models, and does not authorize execution. R2 remains a proposal; see its pinned `recipe.json` in `SOURCE_BINDINGS.json`.

The proposed same-topology comparison is implementable in the canonical training stack after small, reviewed additions, but it is **not runnable as written today**. The repository has neither the 263-channel tiedlead input/model path nor a way to keep the family head in the alpha-0/family-weight-0 control. These are concrete implementation gaps, not a scientific or architectural impossibility.

## Recovered tiedlead semantics

The archived `wnn_nn.py` snapshot defines one shared encoder `Linear(104,128) → GELU → Linear(128,64) → GELU`. It applies that same module to each 52-channel instrument block concatenated with that block's row-to-row difference. The two 64-wide embeddings feed a zero-initialized `Linear(128,256)` residual. In `tiedlead`, the same encoder also processes `[i1(t), i1(t) − i1(at last i0-price event)]`, then a zero-initialized `Linear(64,256)` residual. The snapshot reads `RS_TIED_DIMS` from the environment with default `128,64`; the modified design must bind these dimensions explicitly rather than inherit an ambient setting. This is recovered source behavior, not proof that any particular historical run used those defaults.

The archived trainer's `lead_features` constructs the appended 52 values by gathering the full i1 block at the last `ev_i0px` event, forcing row 0 to count as an event. It concatenates that block after the existing features. The current data layout also has contiguous i0/i1 blocks at `[0:52]` and `[52:104]`, with eight `a` channels following; current event features include `ev_i0px`. The current default model input is therefore 112 raw + 99 event = 211 channels; appending the lead yields the R2 width 263. The archived trainer and architecture snapshot are pinned but partial; the audit does not claim a complete frozen historical feature/runtime closure.

## Canonical integration and the blockers

`training.inputs.build_inputs` is the correct place to add an opt-in, sequence-local causal lead block, and `training.normalization.fit_normalization` already calls that same builder. Add the lead once to the default 211-channel path before normalization; keep it last and reject unsupported combinations or use explicit stored indices rather than assuming `-52` when other optional input blocks are enabled. Require the model's `mean/std` width and the actual input width to agree at 263.

`training.models.make_model` already dispatches plain GRUs to canonical `RNNModel`, but CLI `--enc` only accepts `linear/mlp/tokens/conv`, and `RNNModel` rejects other encoder names. Add a focused tiedlead adapter at the canonical model/input boundary, invoked before the GRU's existing GELU, so its zero-initialized residuals augment the same projection as the archived source. Reuse the existing GRU, head, runner, optimizer, checkpoint, and provenance paths; do not copy `train_rnn_rs.py` or modify frozen snapshots. Require one shared encoder object for i0, i1, and lead calls; preserve exact feature order, fitted normalization, causal sequence reset, and two-column inference output.

The family-head mismatch is independent. `setup_model.build_model` appends eight family rows only when `distill_family_weight > 0`; the same weight gates parent-state extension, family targets in both loaders/batches, and `require_families` cache validation. R2 changes that weight between arms, so current construction necessarily gives the control a different output topology. Reuse `append_family_output_head` and `extend_family_output_head`, but introduce a separate explicit “family head/data present” setting. Set it in both arms; let only the loss coefficient differ. Validate that positive weight requires the head and family cache, while zero weight retains the same eight rows and source-bound cache. `evaluation.predict` already exports only `out[..., :2]`.

Current alpha-zero code is also not an explicit label-only branch: `main_loss` still forms `(1-a)*label + a*teacher` and, if family targets are present, computes the family loss before multiplying by its weight. Finite validated cache values make the arithmetic reduce to labels and zero family contribution, but `0 * NaN` can still contaminate either result, and it needlessly consumes teacher/family values. Add explicit zero-coefficient branches: use the clipped label directly at alpha 0, and skip family-loss computation at family weight 0. Keep the model/head/cache topology independent from these weights. The generic six-source arithmetic already exists in `wnn.distillation.combine_teacher_chunk`; this adapter should not reimplement the source mixture or family averaging.

## Minimal review tests before any fit

1. Compare the new lead builder with the pinned archived formula on a tiny synthetic sequence: row-0 event, repeated rows, known i0-price event boundaries, correct 52-column gather, independent sequences, and future-row perturbations leaving earlier lead features unchanged.
2. Check the tiedlead model's shared-module identity, input/output widths, zero residual initialization, exact parameter shapes, forward/state shape, and gradients through each shared call. Verify normalization and chunked runner calls see the same feature order and sequence reset.
3. Build paired candidate/control distilled models with the same seed and parent and the explicit family-head flag. Assert identical initialized state keys/shapes and family rows; assert both produce 10 training outputs and two inference columns.
4. On synthetic finite inputs, compare alpha-0 loss and parameter gradients with direct label-only WMSE; provide nonfinite teacher/family sentinels to prove those branches are not evaluated. With a positive family coefficient, assert the family head receives gradients; with zero, assert it does not receive objective gradients while remaining in the model.
5. Validate the shared teacher-cache schema and family order for both arms, parent extension, checkpoint save/load, and prediction/export. Reuse the existing source-qualified six-source cache builder/validator rather than create another implementation.

## Decision

No fundamental blocker prevents a same-topology final-stage control. The launch blocker is the absence of the two explicit capability changes above plus their tests and source/provenance bindings. In addition, freeze `RS_TIED_DIMS=128,64`, bind the canonical 211→263 feature ordering, and confirm the family rows survive parent extension and checkpoint/export. This audit establishes interfaces and code gaps only; it establishes no numerical parity, historical runtime identity, checkpoint compatibility, or fit result.

Exact source/evidence paths, SHA-256 pins, and line ranges are in [`SOURCE_BINDINGS.json`](SOURCE_BINDINGS.json). The static test plan is proposed only; no tests were run because this task allowed source inspection and documentation only.
