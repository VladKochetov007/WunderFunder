# F0 submission receipts

Start with the [packet interpretation](../README.md). These receipts distinguish
FP32 selection, actual native serving and independent artifact checks.

- [LOCAL_ASSETS](LOCAL_ASSETS.json): selected epoch5 checkpoints/provenance,
  recovered native runtime and wrapper identities.
- [EXTRACTION](EXTRACTION.json): compact scored rows and complete diagnostic
  panel; its footer wording is qualified by the packet erratum.
- [BLEND_SELECTION](BLEND_SELECTION.json): all five fixed scalar mixtures,
  endpoint reproduction and exposed-F0 winner75/25.
- [REFERENCE](REFERENCE.json): hash-bound FP3275/25 full-fold and panel arrays.
- [WIDE_F32_BUILD](WIDE_F32_BUILD.json): initial single-wide engineering package.
- [MIX75_F32_BUILD](MIX75_F32_BUILD.json): fixed selected pair, exact tensors,
  native binaries, wrapper, package hash and decimal size.
- [MIX75_Q8_BUILD](MIX75_Q8_BUILD.json): same fixed pair under Q8VNNI inference.
- [F32_PANEL](F32_PANEL.json): actual Python3.11 ZIP callbacks, approximate
  GPU parity, natural sequence reset and measured slow CPU runtime.
- [Q8_PANEL](Q8_PANEL.json): actual Q8 callbacks/reset, prediction differences
  and approximately4× improvement in matched Beleriand runtime.
- [INCUMBENT_PANEL](INCUMBENT_PANEL.json): same-host two-sequence timing of the
  exact archived four-model xteam_h4 ZIP; its score is not a fair F0 comparator
  because its model ancestry differs.
- [INDEPENDENT_REVIEW](INDEPENDENT_REVIEW.json): direct metric rescore, exact
  checkpoint-to-package tensors and scope/lineage limitations.
- [SUPPORT_EXECUTION_V1](SUPPORT_EXECUTION_V1.json): successful bounded serial
  support units, preparation environment, active full-replay allocation and
  extraction wording erratum.

- [Q8_ABI](Q8_ABI.json): all three native libraries pass ELF dependency checks,
  maximum required GLIBC2.34; actual scorer image remains unmeasured.
- [Q8_v2_PANEL](Q8_v2_PANEL.json) and [Q8_avx2_PANEL](Q8_avx2_PANEL.json):
  complete two-sequence Python3.11 callbacks and resets match the V3 native
  predictions bit-for-bit on the same VNNI-capable CPU. These are library-level
  checks, not a claim about the speed of a CPU lacking VNNI.
