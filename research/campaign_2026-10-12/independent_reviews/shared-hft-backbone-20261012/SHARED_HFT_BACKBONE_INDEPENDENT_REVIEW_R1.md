# Independent review: shared HFT backbone, R1

**Verdict: static serving semantics pass for the isolated, default-off Q8 prototype.** The F0 receipts support exact callback parity on the tested feature panel and an ABI-compatible CPython 3.11 build. This review does not certify target-CPU runtime, native-Q8 quality, a final F1 endpoint, or production promotion.

I reviewed source commit `70749a118e1333fd04f1e09596de37b1d9126c80` (the full source object ID additively corrected in the Py311 receipt), its changes in `native/src/python.rs` and `native/src/rnn_fast.rs`, and the raw packet at `ops_continuation_20261011/cpu_shared_backbone_r1`. I also checked `ROOT_SHARED_BACKBONE_REVIEW_R1.json`, `IMPLEMENTATION_AND_PREBENCH_R1.md`, and `ABI_PY311_EVIDENCE_R1.md`. No build, benchmark, fit, or package mutation was run for this review.

The consumer’s preflight is appropriately narrow: sharing requires two models, exact float32 `0.5/0.5` coefficients, two served outputs, dynamic Q8VNNI, and no imported Q8 codes, factors, or governor. It compares normalization, input projection and bias, and every recurrent tensor by float bit pattern; constructor shape checks cover the associated widths. A changed trunk is rejected. The producer preflight binds the own F0 student CP1 and HFT CP0 checkpoint hashes, agrees on canonical 211-input GRU configuration and normalization, and reports only the four head tensors as changed. The benchmark crops each output head to the first two official rows before constructing the predictor.

The shared step advances the first model through its ordinary Q8 step, then evaluates the second model’s own quantized `head.0` projection, its own GELU, and its own `head.2` against the first trunk’s post-step hidden/projection byte codes and corresponding dynamic scales. It does not average head parameters or advance the second recurrent state. The baseline does advance both independent models. Since the accepted trunk tensors, precision, initial reset state, and inputs match, the second model’s shared activations are the same as its independently computed activations; the native reset test and callback receipts confirm bitwise outputs for the pinned pair. Both member outputs are still accumulated in index order with the fixed half coefficients, followed by the existing finite-value handling.

`shared_backbone` defaults to false. The false branch retains independent member stepping, including the original alternating order for dynamic-int8 members; omitted versus explicit false also matches in the recorded API self-test. `predict` still resets features, online normalization, and model states on a sequence change, consumes warm-up callbacks before deciding whether to return a prediction, and advances the feature clock before inference. The second model’s unused recurrent state is reset and remains resident: this is a recurrent-compute optimization, not a package-size or resident-memory reduction.

The three raw F0 receipts (`PAIR1_R1.json`, `PAIR2_R1.json`, `PY311_PAIR_R1.json`) all pin the same feature-only panel SHA-256 `e5e6472c…0d6a3`, ten complete 20,000-row sequences, two reset passes, 400,000 callbacks per method, and no label load. A bounded independent JSON check confirmed that each receipt has identical separate/shared sequence-hash maps and that all three maps agree on the same ten sequence IDs. Each receipt also records identical output replay across reset passes. The baseline and treatment use the same `EnsemblePredictor` API, callback runner, features, weights, Q8VNNI precision, and fixed coefficients; the sole constructor difference is `shared_backbone`.

The additive Py311 receipt reports a CPython 3.11.16 `abi3-py311` build. Its wheel passes the submission ABI checker with no `libpython` dependency and maximum GLIBC 2.34, within the stated bookworm 2.36 envelope. The same-interpreter/path import probe resolves the extension ELF and matches its hash to the ABI-checked wheel. There is a preserved evidence gap: the raw Py311 pair stores the package `__init__.py` path/hash in fields named `native_module_path`/`native_module_sha256`; it does not serialize the loaded extension’s `sys.modules` path and hash in the measured process. The frozen relative import and post-run probe strongly corroborate which ELF the pair used, but a final scorer package should record the loaded ELF path/hash directly. Do not rely on a `libpython` `LD_LIBRARY_PATH` workaround.

For F1 CP1/HFT CP0, wait for both exact producer terminal/export gates and the complete fixed-mixture quality grade. Then freeze both checkpoint, provenance, training-state, export, and grade hashes; independently recheck canonical input settings and byte-identical normalization/input/GRU tensors after the actual export/crop. Export the two checkpoints as separate members at fixed `0.5/0.5`; do not pass a `PARENT|HEAD` merged/parameter-averaged member. The current `submission/solution_native.py` does not enable sharing, so keep the default false and make any candidate opt-in explicit in a package-specific source copy. Build from the reviewed source through the established Py311 `abi3` route, bind all three packaged CPU libraries and checkpoint exports in a create-only receipt, run `check_submission_abi.py` on the exact ZIP, then import that ZIP under Python 3.11 and capture the loaded ELF path/hash. Finish with the offline scorer callback/reset/warm-up parity gate, the complete local Q8 quality grade, and target AMD runtime/package checks before root considers promotion.
