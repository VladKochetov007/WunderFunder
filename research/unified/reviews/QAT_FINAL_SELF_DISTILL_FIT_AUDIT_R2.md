The root's fit-completion record and profile/allocation receipt confirm the two root-admitted 1,440-update arms completed; the source code and deployment evaluator were not changed by this reviewer.

The fit provenance files bind both arms to the same seed-3 epoch-5 CP5 initializer, the same frozen FP32 teacher state, same F0 split and 315-component subset, the same source-qualified fitting membership, distillation cache, propensity model, normalization, and sample-order digest. Each completed exactly 1,440 optimizer updates over 72 batches, with no AMP skips or evaluation during fitting. Actual `model_ep0.pt` and `model.pt` byte hashes match each run's provenance. Aside from the run name, the only command-argument differences are `--qat recurrent_w4` and `--qat-learn-scales` in the candidate arm; the control remains FP32.

The candidate metadata identifies LSQ-inspired learned per-output-row steps, not a complete LSQ reproduction. Train and valid row-group integers are separate namespaces and must not be compared numerically across files. These runs can support exposed adaptation diagnostics and the predeclared matched comparison, not clean cross-validation or a public-score forecast.

One provenance limit remains: normal-fit metadata pins the propensity model SHA and the shared cache path, but does not record the payload hashes of the large propensity-cache NPY files. This audit did not reread or hash those payloads. The paired provenance and exact checkpoints are summarized in the [machine receipt](receipts/QAT_FINAL_SELF_DISTILL_FIT_AUDIT_R2.json).
