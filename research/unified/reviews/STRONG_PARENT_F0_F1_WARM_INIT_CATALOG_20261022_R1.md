## Warm-initialization compatibility

### Appending `i1_history`

A standard parent has 112 raw plus 99 event inputs (211 total). `i1_history` appends 156 causal channels for a 367-input child. The generic state transformer in [`inheritance.py`](../../../src/wnn/training/inheritance.py#L84) already supports a strict feature-name prefix and zero-extends `inp.weight`; it also copies the parent normalization buffers and assigns each added channel mean 0 and std 1. The current gate’s `appendable_modes` omits `I1_HISTORY_MODE`, so `can_extend_research_features("none", "i1_history")` rejects before that transformation can run. The smallest conditional source change, if history is selected, is to permit exactly the `none` → `i1_history` extension while retaining the existing name-prefix and state-shape checks. Do not broaden other parent/child combinations by assumption.

`setup_model.load_initializer` requires `--inherit-init-preprocessing` for this extension and inserts the new columns at index 211. This keeps the first 211 inputs and their stored mean/std exact, inserts 156 zero projection columns, and initializes the added normalization to mean 0/std 1. The history prior is fitted from a deterministic, uniform 64-group sample of the child’s fit membership (`seed + 20261012`) in `setup_preprocessing`; it is not copied from the no-feature parent. The i1 semantic mask is applied after normalization and addresses only the appended history channels, so the all-zero capacity control retains the original parent function. A selected warm-history continuation still needs a focused numerical parity check before fitting; no such check was run here.

There is a material scaling difference from cold C: `fit_preprocessing` computes model input mean/std only when `args.init` is absent, so warm extension keeps mean 0/std 1 for the added 156 slots. The separately fitted i1 prior is not a general input normalizer: it uses a deterministic uniform sample of 64 fit groups (seed `fit_seed + 20261012`) to estimate the 52 channelwise first-difference RMS scales, and only the log-energy block divides by those scales before `log1p`; the two residual blocks stay in raw units. Cold C obtains model normalization for all 156 added columns from `fit_normalization`, which reads the first two training batches and takes every seventh flattened input row, with standard deviation floored at 0.001. Zero input weights still preserve the parent function at initialization, but the added-channel gradient scale and optimization path differ from cold C. A conditional warm-history pair must explicitly freeze the added-slot normalization choice and use identical values for control and treatment while preserving the original 211 statistics. Reusing zero/one is the current generic behavior; matching cold C’s fitting-only input normalization requires a narrowly scoped implementation that reproduces or deliberately amends that estimator for only the added columns, then a source/membership and initialization-parity check before fits. For i1 mode, `_input_research_control` leaves history unmasked while fitting normalization; `configure_i1_input_mask` applies the semantic mask after stored normalization. The all-zero B control therefore sees exactly zero history after normalization and is not invalidated by a constant-mask bug.

### Adding the dynamics auxiliary head

The current dynamics screen is explicitly cold-only: [`validation_inputs.py`](../../../src/wnn/training/validation_inputs.py#L30) rejects `--init` and teacher-cache options, and requires the 367-slot all-zero `i1_history` control. `RNNModel` adds a 52-output head and two 52-wide target-normalization buffers when enabled; ordinary outputs are concatenated with the auxiliary predictions only in training mode ([`nn.py`](../../../src/wnn/nn.py#L154)). At evaluation, the branch is absent; the export helper can also strip the head and target buffers ([`dynamics_auxiliary.py`](../../../src/wnn/training/dynamics_auxiliary.py#L192)).

A warm parent without that head does not load strictly today: `setup_model.load_initializer` calls `load_state_dict` on the child state, while the parent lacks `dynamics_aux_head.*` and the two target buffers. The current screen also rejects `--init`, distillation/cache inputs, and standard auxiliary losses in [`validation_inputs.py`](../../../src/wnn/training/validation_inputs.py#L30); [`setup_model.py`](../../../src/wnn/training/setup_model.py#L108) requires exactly two pre-dynamics outputs. The F0/F1 parents have 23 readout rows with structure/next auxiliaries, and their continuation controls reuse distillation caches, so a warm dynamics continuation cannot be enabled by merely allowing one new state-dict key. If selected later, it needs a separate, tightly scoped warm mode that preserves the exact parent readout/cache recipe in both arms, places `dynamics_at` after the parent outputs, allows only the intended new head and two buffers, and rejects every other missing, unexpected or shape-mismatched tensor. Both arms must have the same new head initialization; only the treatment changes the auxiliary-loss weight. Existing [`fit_dynamics_target_normalization`](../../../src/wnn/training/dynamics_auxiliary.py#L108) already derives targets from complete fitting sequences and inherited raw-channel means/stds, while the head’s training-only output branch keeps eval predictions unchanged. A 211-input parent would additionally need the conditional zero extension to the required 367-slot all-zero `i1_history` input described above. If both history and the head are selected, both input-extension and state-extension parity gates are required. No warm dynamics support is implemented by this note.

## Scope and remaining limits

This catalog used small JSON receipts, provenance and source files only. It did not load tensors or prediction/data arrays, run tests, fit models, or choose a mechanism. Cache metadata pins source claims but is not a substitute for a fresh preflight of each actual checkpoint, source tree, membership, target and propensity artifact. The conditional four-fit allocation and treatment decision remain owned by the root controller under the accepted plan.
