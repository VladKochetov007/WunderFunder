# Bounded LSQ scale confirmation recommendation R1

This is a recommendation to the root controller, not a fit admission or a
resource authorization.

The 10% F0 seed-3 learned-scale endpoint has a small positive WP point delta
against its matched nonlearned per-update absmax control (`+0.00019414`), but
its descriptive paired component interval crosses zero. The t0 gain is larger
than the t1 movement, and the 10% screen is one exposed fold and one fitting
seed. The outcome justifies one diversity check; it does not justify a sweep
or a scale-benefit claim.

After the currently admitted root-owned GPU cohort completes and fresh
capacity is available, prioritize one **matched 10% pair on F3 / fitting seed
4**. Use the same `recurrent_w4` treatment: learn all selected row steps,
including the two Q8 head blocks, versus nonlearned per-update absmax row
steps. Bind both arms to the same clean-T3 F3 seed-4 CP5 parent, F3 teacher and
propensity/cache ancestry, split, hashed 10% component subset, preprocessing,
sample order and source revision. Hold FP32 AdamW `lr=1e-4`, `wd=0.01`,
OneCycle, 1,440 updates, raw fixed epoch-0 endpoint, no EMA/SWA and clipping
fixed. Keep the two arms identical except run name and scale-learning flag.
Score the complete F3 endpoint panel through the frozen component grader.

This is a bounded two-fit confirmation, not a full-data promotion path. Reuse
the existing measured B16/C1000 profile only if the exact hardware, source,
model shape and recipe remain unchanged; otherwise root should refresh the
profile before fit admission. Do not repeat seed-3/F0 merely to narrow its
bootstrap interval. Treat an uncertain or negative follow-up as evidence for
allocation, not an automatic mechanism-kill rule. If the direction remains
promising across this distinct seed/fold, root can decide whether a 30% or
full-data scale step has sufficient information value and capacity.

The proposed pair must be registered under a new LSQ follow-up experiment ID.
Its F3 validation is still previously exposed development evidence, not a
pristine holdout. Root owns registration, current resource admission, exact
commands, collection and any later promotion.
