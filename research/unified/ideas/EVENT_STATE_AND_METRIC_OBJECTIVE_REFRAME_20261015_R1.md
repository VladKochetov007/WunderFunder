## Card A — distinguish each field's staleness from its event group's staleness

**Existing lineage:** `H-087` / `H-138`. **Mechanism family:** causal input state. **Status:** a specific unrun representation variant, not a novel family.

**Question and competing explanations.** The current causal 211-column input has per-field values/deltas but only three shared age clocks (`since_i0px`, `since_i0trade`, `since_i1px`). Does a feature's own time since change add predictive context? Or are group-level event ages sufficient, with per-field age only adding width/redundant clocks? Existing GRU state may also infer the age from repeated values.

**Source component and analogy.** Engle and Russell's ACD work models durations between irregular financial transactions as state ([NBER working-paper record](https://www.nber.org/papers/w4966)). Eisler, Bouchaud and Kockelkoren report history-dependent order-event impact in small-tick markets ([primary paper](https://arxiv.org/abs/0904.0900)). These sources motivate testing timing, not the specific feature or a gain here. The indexed [Rogii writeup](../sources/competition-writeups/rogii_top1.txt) shows particle-filter feature value changed with the rest of the model and the fixed ensemble performed best on its reported CV metric. Its random-source lesson is conditional contribution measurement; its static features and score do not transfer.

**Intervention and controls.** For each raw channel `j`, maintain an exact-change clock: `age_j(t)=0` if `x_j(t) != x_j(t-1)`, otherwise `min(age_j(t-1)+1, 10000)`; append `log1p(age_j(t))` to the base inputs. Reset at sequence boundaries and initialize row 0 to zero. Compare three matched arms from the same parent:

- C: existing 211-input recipe.
- G: append 112 broadcast clocks, one per raw-feature group `[0:22], [22:44], [44:52], [52:74], [74:96], [96:104], [104:112]`; a group's clock resets when any member changes and all fields in that group receive the same age.
- F: append the 112 individual ages above.

G and F have the same input width and counter state. Their difference tests field-specific age resolution; C measures whether either expanded representation helps. For G/F, zero-extend the parent input projection so the original prediction is unchanged at initialization. Keep teacher/label treatment, update count, loader order, checkpoint and official scorer fixed.

**Cheapest discriminating measurement.** The already-indexed [CPU timing fixture manifest](../../campaign_2026-10-15/vast_a_cpu_probe_r1/CPU_TIMING_FIXTURE_R1.json) binds eight complete, distinct-component F0 fitting sequences, `[8,20000,112]` raw features and no targets or scoring mask. Its binary stays unread by this scout. Root may admit a tiny feature-only screen on that exact fixture: report how often each individual field age differs from its seven-group clock and the age-distribution support, with reset parity checks. This can show that field age contributes a distinct coordinate; it cannot show predictive value or reject the mechanism. If the clocks are distinct, the cheapest quality comparison is a matched complete-sequence G/F model screen from the same function-preserving parent, with C as the endpoint control and source-qualified evaluation components graded by the unchanged official scorer. The primary contrast is F−G, with F−C and G−C secondary. The diagnostic's fitting components and every evaluation fold remain exposed development evidence.

**Falsifier.** If the input-only screen finds field age identical to its group clock, the proposed field-resolution mechanism is absent for those channels and no model fit is warranted. Distinct clocks are only a necessary representation check: if the matched F−G endpoint contrast later has no stable direction or component-level structure, defer this encoding at that fidelity rather than concluding that per-field age has no predictive value on other populations or scales. A wide interval alone does not close it.

**Cost and artifact.** Adds 112 counters (448 bytes as int32) and O(112) comparisons per row; the current [`StreamingEventFeatures`](../../../src/wnn/features.py) already keeps the previous 112-value row for delta/flag computation. G/F both add 112 model inputs and require actual Q8 size, one-row runtime and target-host measurement before serving. The reusable artifact is a reset-safe feature transform and source-bound parity/grade receipt.

## Card B — preserve the pooled-correlation rejection; gate any metric-fidelity reopening

**Existing lineage:** `H-055`. **Mechanism family:** metric-aligned learning objective. **Status:** exact older recipe rejected by E-291; only an exact clipping-semantics probe is proposed, and a new fit is deferred unless that probe shows material divergence.

**Question and competing explanations.** The original H-055 explanation was that accumulated prediction/target mass reveals between-chunk offsets and scales missed by batch-pooled `gcorr`. E-291 found the tested pooled-memory recipe worse. One narrower unresolved issue is that both the tested `gcorr_pool` and `gcorr` leave predictions unclipped, while `global_wp_clip2_v1` clips predictions as well as targets. Is this distinction active on current strong endpoints and does it change useful gradients, or is it negligible, leaving E-291's rejection fully applicable? H-018's per-chunk failure is separate: that recipe encountered degenerate chunk targets.

**Exact prior recipe and result.** The frozen [`ftpool_folds.sh`](../../campaign_2026-10-01/jobs/ftpool_folds.sh) added `--loss gcorr_pool --pool-decay 0.995` to one-epoch GCLP fine-tuning of clean since parents (seeds 3/4, folds 0/1, fixed epoch 0), for both head-only and two-stage endpoints. It used label-only fitting with no teacher/cache, so `gcorr_pool` was active; the matched reference used batch `gcorr`. E-291's paired component bootstrap over 925 sequences/290 components found pooled-minus-reference `−0.001521`, 95% interval `[−0.002868, −0.000161]` for two-stage, and `−0.000414`, interval `[−0.001260, +0.000463]` for head-only. The contemporary independent code review passed the loss math/numerics and noted that both correlation objectives left predictions unclipped. This is a real negative on an exposed older recipe, not an unrun H-055 proposal. No old result is overwritten.

**Cheapest discriminating measurement.** First run a tiny source-level synthetic gradient audit only: compare autograd for the exact current `PooledCorrMemory` and batch objective with finite differences of `global_wp_clip2_v1`, including predictions below/at/above ±2, constant and near-constant targets, zero-weight rows, chunk boundaries, and memory resume. The expected difference outside the clip range is not evidence of a quality gain. Separately, let the data owner report from already-existing hash-bound parent predictions the score-weighted fraction of rows where prediction clipping changes the value; this scout does not open prediction or feature payloads. Root should declare what constitutes material activity before seeing that summary. If clipping is inactive or immaterial, keep E-291 rejected and do not fit.

**Coherent reopening, only if the probe warrants it.** A new objective would clamp predictions to the official ±2 range and use the official target clipping/`abs(clip(y))` weights while retaining the `.995` detached-memory algorithm and prior treatment. Compare it to the exact matched batch-`gcorr` reference, not to the cached alpha-0 job. In the current trainer, cached distillation targets take a hard-coded weighted-MSE branch before `objective()` even at alpha 0; `--loss gcorr_pool` is therefore a no-op on that path. Any future loss comparison must be a no-cache, label-only recipe with teacher/cache and TD targets absent, so the CLI loss reaches `objective()`. The current alpha-0 comparison is intentionally WMSE and remains untouched. If reopened, reuse the existing GCLP command path and memory resume support; make only the narrow loss correction, not a new framework or a decay sweep.

**Falsifier and allocation.** If clipped and unclipped objectives differ only on negligible score-weighted mass, the repaired loss still fails the synthetic official-gradient check, or a later fixed-endpoint comparison does not improve official score/component behavior, retain E-291's rejection at this descendant's scope. A zero-crossing interval alone is not a kill rule. Given E-291, this card does not recommend or allocate a new fit now; only a materially different clipping-gradient result earns a small source-qualified comparison on a current parent. A corrected fit has ordinary one-epoch fine-tune cost and no serving cost; the first probe is synthetic/source-only and bounded.
