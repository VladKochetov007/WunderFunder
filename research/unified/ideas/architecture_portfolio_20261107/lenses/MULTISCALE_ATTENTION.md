# Multiscale attention and local/global temporal encoders

**Scope:** independent architecture proposal; literature and design only. No fits, profiles, training-data access, GPU/SSH activity, or execution authorization.

## Task and data contract

The objective is the official two-target global clipped weighted Pearson score on its fixed mask. Process every row in order, including warm-up and unscored rows, to advance state; train on all official train rows after warm-up 99 (train has no `is_scored` mask), and score validation only where `need_prediction & is_scored`. State resets at a sequence boundary. The full sequence length is 20,000; the core input has 112 features (`src/wnn/data.py`, `SEQUENCE_LENGTH`, `N_FEATURES`, and `Sequence.features`). The 2,000-step figure is a training/TBPTT chunk, not the sequence length. The review contract records 10,325 fitting sequences, 1,873 validation sequences, and 3,528,273 scored validation rows for the qualified manifest. The optional 211-feature input is 112 raw plus 99 derived causal event features; it is total width 211, not 211 additional features. Treat feature columns as named identities, not as an ordered price/volume depth axis.

Keep the official whole-sequence train/valid boundary. Fit feature normalization and every model, teacher, initializer, and other learned transform on fitting members only. Validation is already development-exposed and remains the full official primary evaluation; do not substitute row splits, random folds, or shuffled `seq_ix` ordering. Within a sequence, use the ordered timestep index as relative lag evidence; it does not establish cross-sequence timestamps or calendar time. The evaluator's mask and target alignment govern warm-up and whether the current `x_t` may be used for `y_t`; retain the current predictor's exact convention.

## What transfers from the literature

- **PatchTST:** patches let attention operate on subseries tokens and reduce token count; the paper also adopts channel independence. Its reported task is long-horizon forecasting, and its channel-independent path models each channel's temporal history separately. The transferable component is a completed-subseries summary. Its full channel-independent design is a poor first fit for per-timestep outputs where contemporaneous and lagged cross-feature interactions may matter. [Paper](https://arxiv.org/abs/2211.14730), [official implementation](https://github.com/yuqinie98/PatchTST).
- **iTransformer:** variate tokens carry a feature's lookback series, and attention mixes across variates. This directly represents feature correlation for fixed-lookback forecasting, but it does not naturally emit a causal representation at each timestep: each feature token embeds a temporal window, so stepwise prediction needs a different prefix embedding for every output or risks future access. [ICLR 2024 paper](https://openreview.net/pdf?id=JePfAI8fah), [official implementation](https://github.com/thuml/iTransformer).
- **Transformer-XL:** segment-level recurrence with relative positional encoding addresses context continuity across chunks. That mechanism maps naturally to a 20,000-step sequence trained in 2,000-step chunks. It does not establish a Connectome gain. [ACL paper](https://aclanthology.org/P19-1285/), [authors' code](https://github.com/kimiyoung/transformer-xl).
- **Griffin/Hawk:** Griffin combines gated linear recurrence with local attention; Hawk uses the recurrent block. This gives a useful online state plus an exact recent window. The paper's efficient recurrence depends on optimized kernels; Google DeepMind's reference implementation includes Flax/Pallas and an unoptimized PyTorch path, so CPU latency and a direct serving adaptation remain unknown. [Paper](https://arxiv.org/abs/2402.19427), [Google DeepMind code](https://github.com/google-deepmind/recurrentgemma).
- **TLOB:** this finance-specific design uses temporal attention over snapshots and feature attention over LOB variables, preceded by Bilinear Normalization. It is relevant as a factorized feature/time-mixing component, but its paper uses fixed input windows for horizon classification; its normalization and head need a causal, per-step regression audit before reuse. Feature attention over IDs is plausible; a convolution that treats price/volume column IDs as ordered book depth is not. [Paper](https://arxiv.org/abs/2502.15757), [official implementation](https://github.com/LeonardoBerti00/TLOB).
- **QK normalization:** QKNorm normalizes query/key vectors per head and learns their scale. Treat it as a controlled stability ablation, not a presumed quality improvement or part of the initial architectural comparison. [Findings of EMNLP paper](https://aclanthology.org/2020.findings-emnlp.379/).

These sources support mechanisms, not transfer to this objective, data, or inference envelope. The task is not the fixed-horizon MSE benchmark used by most time-series Transformer papers.

## Ranked architecture proposals

### 1. Raw-step plus completed-patch context (first comparison)

**Mechanism.** Preserve one joint token per timestep so the encoder can mix the 112 contemporaneous features before modeling time. Add a slower branch that reads only completed 32-step patches, giving it a multiscale summary without changing the output clock.

**Exact causal schedule.** At sequence position `t`, form `e_t = Linear(F,128)(x_t)`, where `F=112` for the core recipe or `F=211` for the 112-raw-plus-99-derived event recipe. Process it in two pre-norm causal attention blocks (`d=128`, 4 heads, `d_ff=256`, raw window `W=128`). Use a single relative encoding choice for the initial recipe (RoPE on integer step offsets, or a clipped relative-lag bias; do not combine both). This raw branch can use `x_t` only if the current interface permits it for `y_t`; otherwise shift the input exactly as the current interface does.

Partition positions into non-overlapping patches `[32n, 32n+31]`. After the output for a patch's final position has been formed, pool its step embeddings by concatenating their mean and last embedding, then project `256 -> 128`. Process the resulting token in two causal patch-attention blocks (`d=128`, 4 heads, `d_ff=256`, last 64 completed patch tokens) and update a 128-unit GRU summary state. While producing any output inside patch `n`, the slow branch may use only patches `< n`; it sees no part of the current patch. Publish the new patch token and update the GRU after the final output in that patch. Thus local outputs see up to 128 exact preceding/current positions, patch attention sees up to 64 completed patches (2,048 steps), and the GRU compresses the longer completed prefix. Patch alignment and state reset are per sequence; they do not use `seq_ix`.

Fuse `[raw_hidden_t, last_completed_patch_hidden, completed_prefix_GRU_state]` (384 values) through `384 -> 128 -> 2`. Before the first patch closes, use learned zero-state/null context. Preserve the official eligible mask after warm-up; do not delay predictions to patch boundaries.

**Size and work estimate.** With `F=112`, `d=128`, `L_step=L_patch=2`, `d_ff=256`, and GRU hidden width 128, a rough parameter estimate is
`F*d + (L_step+L_patch)*(4d^2 + 2d*d_ff) + 2d*d + 3(d*h+h^2) + 384*d + 2d`,
or about 0.72M parameters before small biases, norms, and relative-position terms. Using the total-width 211 event input adds approximately `(211-112)*128` stem parameters. With `T=20,000`, `N_patch=ceil(T/32)=625`, attention-pair work scales as `H*T*W_step*L_step + H*N_patch*W_patch*L_patch`; the recurrent summary costs `O(N_patch*d*h)`. This avoids full `T x T` attention. Online state consists of per-layer raw KV windows, per-layer patch KV windows, the GRU state, and a partial-patch accumulator; no complete sequence buffer is required by this design.

**Assumption and falsifier.** There is useful evidence in completed multistep summaries beyond what the raw local stack and parameter count alone capture. Reject that premise for the next tranche if the full model fails to improve the parameter-matched raw-only control in both paired seeds, and no pre-registered fixed-weight complementarity path is useful. The patch branch's score contribution is still an empirical question; PatchTST's forecast results do not predict this metric.

### 2. Griffin-lite: recurrent state with a local attention window

Embed all `F=112` core features jointly to `d=128` (the optional total-width event recipe uses `F=211`). Stack six pre-norm residual blocks in the paper's recurrent/local spirit: repeat `[RG-LRU recurrent, RG-LRU recurrent, local attention]` twice. Use recurrent width `D_rnn≈4d/3=171`, the paper's short causal Conv1D filter length 4, local attention with 4 heads and `W=128`, RoPE for local attention, and a gated MLP with expansion 3. A two-output head reads every eligible timestep. Each recurrent layer updates at each input; its Conv1D tail and recurrence state reset only at sequence boundaries. Local attention retains a 128-step KV window.

The Griffin block pattern is grounded in its paper; these small dimensions and the regression head are a proposed adaptation. A rough parameter formula is `F*d + L_r*(3*d*D_rnn + 9*d^2) + L_a*(4*d^2 + 9*d^2) + head`, with `L_r=4`, `L_a=2`, giving about 1.3M parameters before normalization, biases, and recurrent gate details. Work is approximately `O(L_a*H*T*W*d_head + L_r*T*d*D_rnn + (L_r+L_a)*T*9d^2)`. This has no patch-boundary lag and fixed recurrent state across all 20,000 steps, plus local attention over exact recent inputs.

**Assumption and falsifier.** The full prefix can be usefully compressed into recurrent state while local attention preserves recent interactions. Reject it if the matched two-seed test does not improve the paired local-attention control and its frozen student/serving profile offers no practical advantage. Main risk: the recurrence is sequential during online prediction and may be memory-bound or slow on this CPU path; the optimized Google implementation is not evidence of performance in this PyTorch package.

### 3. Transformer-XL-style relative attention across 2,000-step chunks

Use a joint per-step `F -> 128` embedding (`F=112` core, or total width 211 with derived events), two pre-norm causal Transformer-XL blocks (4 heads, `d_ff=256`), the paper's relative attention, and a 512-position per-layer memory. Train through ten 2,000-step chunks per 20,000-step sequence; carry memory across chunks and detach it at TBPTT boundaries, never resetting it there. Reset only at sequence boundaries. Within a chunk, position `t` attends causally over earlier positions in the chunk and cached previous memory; at the start of a later chunk this is at most 2,512 available positions. Inference maintains the same bounded previous memory and current-chunk state. The relative offset is an integer position difference, not an inferred timestamp.

For `L=2`, a rough parameter estimate is `F*d + L*(4d^2 + d^2_rel + 2d*d_ff) + 2d`, about 0.31M if each layer has its own relative projection (`d_rel=d`). Attention-pair work is about `H*L*N_chunks*(B*(B+1)/2 + B*M)` for full causal within-chunk attention (`B=2,000`, `M=512`, `N_chunks=10`); this is roughly 242M query-key pairs per sequence over both layers, before the value products and projections. The finite per-chunk context and compute make this a third-priority comparator rather than a default. A local-window replacement would reduce work but would be a separate architecture recipe, not a faithful Transformer-XL replication.

Do not add QKNorm to the first run: relative attention is the defining intervention. If attention-logit diagnostics later show saturation, compare QKNorm as a separate fixed-recipe ablation using per-head L2-normalized queries/keys and a learned scale. QKNorm's translation evidence does not establish a time-series benefit.

## Why not start with feature tokens or independent channels?

The official PatchTST design independently encodes each channel's history; an anonymized feature here may trigger or gate another feature at a variable lag. A late output head cannot recover interactions that the temporal trunk never formed. iTransformer makes cross-feature attention explicit, but its token is a feature's whole lookback and its feed-forward projection does the temporal work. Rebuilding those feature tokens for each causal prefix is a poor match for a stateful one-step API and can accidentally expose later sequence positions. A joint token per timestep gives an explicit point at which contemporaneous channels mix, while relative lag attention can connect events at different positions. TLOB motivates a separate factorized-stem test: project each current-step scalar feature to 32 values, add its feature-ID embedding, run two feature-attention blocks (`d=64`, 4 heads, `d_ff=128`) over simultaneous features, pool to a 128-wide event token, then reuse the causal temporal/patch path. This costs `O(T*F^2)` feature-attention pairs and is not in the first screen. Audit normalization for past/current-only behavior and train-only learned statistics. Feature IDs have no sortable depth order, so do not apply a DeepLOB-style ordered-depth convolution. These are task-fit hypotheses, not evidence that cross-channel modeling is necessary.

## First informative comparison and serving path

Run only after a separate recipe/resource admission. The first pair should isolate the completed-patch branch:

1. **Treatment:** architecture 1 as specified.
2. **Control:** the same stem, raw-step blocks, fusion head, optimizer, loss, data order, training steps, and output interface. Replace the patch/GRU branch (about 0.39M parameters) by a per-timestep `128 -> 448 -> 448 -> 256` MLP branch with GELU. This is approximately parameter-matched (within about 5%) but has no additional cross-time state.
3. Train two matched seeds per arm (four fits total), using fitting sequences only. Pair seed and loader order across arms. Train on all official train rows after warm-up 99. On validation, process every row to advance state and score only `need_prediction & is_scored`. Use the unchanged official train/valid boundary. Report the primary aggregate score, each target score, train/valid separately, and both paired seed deltas. Do not tune on validation or select a short-position subset as primary.

The specific falsifier is that the completed-patch model does not show a consistent paired advantage over the parameter-matched raw-only control. Two seeds do not establish significance; if signs disagree, preserve uncertainty and do not promote on the best seed. Current task-contract endpoints (TL3 WP 0.692377425 and the earlier fixed 90% TL3 + 10% LSTM endpoint WP 0.692502063) are historical context, not paired controls for this screen. The contract says the terminal PR61 Transformer/student endpoint is still unknown; do not assume it is positive or negative.

**Teacher/student route.** If a selected multiscale/Griffin teacher is useful but exceeds the CPU serving envelope when actually measured, distill its two per-step outputs into the existing GRU256x2 or other accepted small student. Generate teacher targets and fit student-side transforms only from fitting members; combine train-only supervised loss and a frozen teacher-loss recipe. Validate the student on the official full validation without deriving distillation weights, initializers, or blend weights from validation. For ensemble complementarity, pre-register a fixed blend (or train-derived weights only if a valid independent fitting protocol exists); use validation only to accept/reject that frozen choice, never to optimize it. No teacher scale, student gain, serving speed, or ensemble gain is known from this design note.

**Implementation risks:** state reset and feature availability must exactly match the current CPU API; a patch is published only after its last constituent input is legally available; 2,000-step training chunks carry state and do not become independent sequences; all relative offsets reset at sequence boundaries; normalization is fitting-only. CPU latency, batch throughput, GPU memory, and the cost of 20,000-step training are unmeasured. The 99-derived event features must retain their declared causal construction in the exact input recipe.
