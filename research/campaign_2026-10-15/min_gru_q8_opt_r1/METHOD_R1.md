# Method and implementation scope

The sealed matched-matrix callback profile showed H384×2 minGRU Q8 VNNI at 0.93937s versus H256×2 GRU Q8 at 0.30860s for a 20k raw112 callback. Its follow-up RDTSC profile attributed 36.84% of inclusive raw callback ticks to candidate/gate/state work, 23.70% to Q8 activation quantization, 23.08% to Q8 matvec, and 14.06% to encoder plus head GELU. That phase build was bitwise identical to the earlier uninstrumented minGRU output/state. These shares motivated a narrow AVX2 implementation test; they do not establish a causal decomposition of the original latency gap.

The optimization reuses existing exact-bit AVX2 helpers in `native/src/min_gru.rs`: the Q8 activation quantizer calls `vnni::quantize_avx2`, fast GELU calls `approx::avx2::gelu_slice`, and the fast candidate/write/state update evaluates eight recurrent values at a time using the existing `sigmoid8`. Scalar tails remain. If AVX2/FMA is not available, if an activation includes a NaN where the vector GELU/update cannot preserve exceptional behavior, or for the portable path, execution falls back to the scalar helper. The predictor exposes `avx2_fastpath_enabled` so the measured Q8 policy is asserted rather than inferred.

The candidate rule remains `x >= 0 ? x + 0.5 : sigmoid(x)`, the write remains `sigmoid(gate)`, and the state update remains `(1 - write) * old + write * candidate`. The vector update uses separate multiply and add operations; it does not change the model's represented weights, row scales, layer order, hidden-state layout, or the existing VNNI matrix operation. The original GRU path is untouched. The implementation commit also includes root's merged independent-width/native-minGRU source baseline; this task tested minGRU and compiled that integrated tree, but did not repeat the width-specific test suite.

The profile runner loads the same deterministic synthetic H384×2 weights and source-qualified train row-group37, sequence7598721 raw features as the sealed scalar callback. It applies common clean-F0 211-column normalization and runs the real raw112-to-causal211 callback, including per-row Python/native calls and reset. The fitting sequence is used only as a serving input; targets and masks are never loaded. The scalar reference is the sealed release library SHA `5e29328c940aeaada3f38c86a75a824585fedae78bf68d6a1dd5d78b98996f13` from source commit `7364a452e0c72c2600a27e21cb66f6deb9e714ce`.

The runner checks precision=`q8vnni`, fast activations, and AVX2/FMA selection, warms each callback once, then measures three 20k callbacks per policy in alternating order. It requires every full output and final hidden state to match the scalar baseline bitwise and be finite, with zero-state reset before each replay. Rust unit tests compare vector helpers to scalar calculations across SIMD tails, callback widths, ties-to-even quantization boundaries, and NaN fallback.

This is a local cost test, not model-quality evidence. Phase counters from the previous build perturb that profile and are not used for the speedup calculation. The primary result is the paired uninstrumented comparison in `OPTIMIZED_CALLBACK_PROFILE_R1.json`; its absolute scalar median differs from the earlier session's mean, so only the within-session paired comparison is interpreted.
