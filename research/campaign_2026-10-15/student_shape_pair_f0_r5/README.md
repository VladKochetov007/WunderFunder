# F0 seed-3 matched student T4 profile R5

R5 repairs the R4 bootstrap failure without changing the profile jobs or trainer. R4 version 2 ended before the runner started because the outer bootstrap requires every `external_mounts` logical path to be listed in `manifest.files`. R4 added the two target-cache mounts but omitted their file descriptors from that allowlist. The exact v2 log, status and identities are preserved in [the R4 terminal receipt](../student_shape_pair_f0_r4/PROVIDER_TERMINAL_R4.json).

R5 adds exactly two `manifest.files` entries, using the already bound producer SHA-256 and byte sizes for `cache/train_targets.npz` and `cache/valid_targets.npz`. The R4 source archive and outer-kernel bytes are hardlinked unchanged; the external mount map, target data, ancestry, two B16/C2000/FP16 profile specifications and 1,800-second kernel deadline are unchanged. The two large target payloads are neither read nor copied. The intended private profile source update is version 3, followed by the existing kernel slug at version 3 after fresh root/critic review and provider preflight.

[R5 preparation and bootstrap fixture](prepare_and_validate_r5.py) executes the actual sealed R4 outer kernel against the R5 manifest and unchanged 272 KB archive. It redirects only the Kaggle input/working roots into a physical local fixture, creates small external-mount stubs, and intercepts `subprocess.Popen` after the bootstrap has extracted the archive, validated and symlinked all inputs, and written runtime specs. This tests the manifest allowlist and mount loop; it does not run the trainer, verify large payload contents, allocate a GPU, profile a shape, fit a model, or evaluate quality.

The generated records are [the R5 bundle-delta receipt](R5_BUNDLE_BUILD.json), [the actual-bootstrap fixture receipt](R5_BOOTSTRAP_FIXTURE.json), [source binding](SOURCE_BINDING_R5.json), [generated-kernel seal](GENERATED_KERNEL_SEAL_R5.json) and [offline preflight](OFFLINE_PREFLIGHT_R5.json). [The R4 delivery erratum](R4_REVIEW_ERRATUM_R1.md) records the missed outer-bootstrap allowlist check and the correction to future profile validation. Root independently reran the physical bootstrap fixture; its result is indexed in the [root fixture review](../../unified/reviews/STUDENT_SHAPE_T4_R5_ROOT_FIXTURE_20261015_R1.json).

R5 source version 3 was created after an exact private v2 READY/file-size preflight. The [source-version preflight](PROVIDER_PREFLIGHT_SOURCE_VERSION_R5.json) and [terminal readback receipt](PROVIDER_SOURCE_VERSION_R5.json) bind the exact v3 inventory and downloaded archive/manifest hashes. The readback manifest contains both required target-cache descriptors. After a fresh typed-quota and exact-kernel check, the existing private kernel slug was pushed as version 3; the [kernel-push receipt](PROVIDER_KERNEL_PUSH_R5.json) records that action.

The exact version-qualified v3 run ended in an infrastructure error. The [terminal receipt](PROVIDER_TERMINAL_R5.json) and collected output inventory show both H256×2 and H512×1 worker processes reached strict distillation-cache validation, where resolving the two input-mounted homogeneous-cache symlinks crossed the registered cache root. Both workers failed before any optimizer update and emitted no model or prediction artifacts. This is cache-path containment evidence, not architecture or quality evidence. Two Tesla T4 workers ran concurrently; typed GPU quota fell by 558.902 seconds, while the latest runner-log event is at 374.192 monotonic seconds. The provider charging basis remains uncertain.

The temporary R5-specific provider-preflight helper failed on actor-side schema assumptions and one order-only metadata comparison before any provider mutation; it was retired in favor of the reviewed R3 exact-provider primitives. [That tooling diagnostic](R5_LOCAL_PREFLIGHT_TOOLING_DIAGNOSTIC_R1.json) preserves the failures. These checks do not alter the frozen profile recipe, data, or kernel source.
