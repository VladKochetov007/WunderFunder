# F0 seed-3 matched student T4 profile R5

R5 repairs the R4 bootstrap failure without changing the profile jobs or trainer. R4 version 2 ended before the runner started because the outer bootstrap requires every `external_mounts` logical path to be listed in `manifest.files`. R4 added the two target-cache mounts but omitted their file descriptors from that allowlist. The exact v2 log, status and identities are preserved in [the R4 terminal receipt](../student_shape_pair_f0_r4/PROVIDER_TERMINAL_R4.json).

R5 adds exactly two `manifest.files` entries, using the already bound producer SHA-256 and byte sizes for `cache/train_targets.npz` and `cache/valid_targets.npz`. The R4 source archive and outer-kernel bytes are hardlinked unchanged; the external mount map, target data, ancestry, two B16/C2000/FP16 profile specifications and 1,800-second kernel deadline are unchanged. The two large target payloads are neither read nor copied. The intended private profile source update is version 3, followed by the existing kernel slug at version 3 after fresh root/critic review and provider preflight.

[R5 preparation and bootstrap fixture](prepare_and_validate_r5.py) executes the actual sealed R4 outer kernel against the R5 manifest and unchanged 272 KB archive. It redirects only the Kaggle input/working roots into a physical local fixture, creates small external-mount stubs, and intercepts `subprocess.Popen` after the bootstrap has extracted the archive, validated and symlinked all inputs, and written runtime specs. This tests the manifest allowlist and mount loop; it does not run the trainer, verify large payload contents, allocate a GPU, profile a shape, fit a model, or evaluate quality.

The generated records are [the R5 bundle-delta receipt](R5_BUNDLE_BUILD.json), [the actual-bootstrap fixture receipt](R5_BOOTSTRAP_FIXTURE.json), [source binding](SOURCE_BINDING_R5.json), [generated-kernel seal](GENERATED_KERNEL_SEAL_R5.json) and [offline preflight](OFFLINE_PREFLIGHT_R5.json). [The R4 delivery erratum](R4_REVIEW_ERRATUM_R1.md) records the missed outer-bootstrap allowlist check and the correction to future profile validation. R5 is offline-prepared only; no source version or kernel version has been created or pushed.
