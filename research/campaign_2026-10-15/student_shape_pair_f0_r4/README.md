# F0 seed-3 student shape pair R4 target-cache mount repair

R4 preserves the two T4 resource-profile jobs and their H256×2 / H512×1 recipe after the first R3 kernel exposed a missing worker input. The R3 H256 job stopped during `load_campaign_split()` because the frozen fold0 split requires `cache/train_targets.npz` and `cache/valid_targets.npz`; it returned before CUDA allocation or an optimizer update. This is an infrastructure failure, not architecture evidence. The original terminal log and provider output inventory remain linked in [the R3 packet](../student_shape_pair_f0_r3/README.md) and are not overwritten.

R4 adds the two existing fold0 target-index assets from private READY dataset version 1 to each job’s declared inputs and to the outer kernel mount map. Their content hashes, byte lengths and exact hash-named flat filenames come from the existing fold0 portable input registry and its source bundle manifest. Packet preparation checks the fold0 split, portable registry, and local file size/mtime without opening either large payload. At runtime the runner defers duplicate input hashing, then the unchanged `load_campaign_split()` portable verifier checks each whole-file SHA-256 and row-index digest before any fit.

The archived source code is reused unchanged from R3. Only the two small embedded profile job documents gain the target-cache input descriptors and the deferred-hash path list; both trainer argument vectors, model shapes, optimizer, profile budget and R2 job/run labels remain fixed. The outer archive hash and mount map consequently change. R4 is not byte-identical to R3, and the existing private profile dataset bundle must be versioned before the kernel is pushed. No payload was copied, rebuilt or uploaded as part of offline preparation.

[The input binding](INPUT_BINDING_R4.json), [source binding](SOURCE_BINDING_R4.json), [bundle-build receipt](OFFLINE_BUNDLE_BUILD_R4.json), [mount-map receipt](KERNEL_MOUNT_SUCCESSOR_R4.json), [generated kernel seal](GENERATED_KERNEL_SEAL_R4.json) and [offline preflight](OFFLINE_SPEC_PREFLIGHT_R4.json) record the exact change. The preflight confirms that all paths named by the frozen fold0 split are mounted, both archived job specs match their checked files, and every non-spec archive member matches R3. Provider versioning and repaired two-shape T4 profiles remain gated on a fresh typed quota check and exact-target READY/status checks; no new fit or quality result is claimed.
