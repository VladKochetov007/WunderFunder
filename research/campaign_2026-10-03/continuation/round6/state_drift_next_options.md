# Prospective state-drift interpretations and next falsifiers

Written while independent v2 review is pending. No actual capture or drift result has been opened. This note changes neither the frozen candidate nor its thresholds, authorizes no computation, and proposes no seed grid. Any use of actual arrays below requires subsequent controller authorization. The first probe remains the original four-completed-updates/skips0 population.

The probe asks whether inherited student state agrees with a current-weight prefix and whether that difference reaches the local prediction, whole gradient and actual update. It does not ask which state predicts unseen targets better. A prefix-consistent state can change the gradient in either direction, and the altered local step still detaches that state: it is not full-prefix backpropagation. Both arms share fixed cached targets and genuine incoming EMA/moments; neither a changed training loss nor a changed parameter update establishes generalization. The fresh fixed panel after four updates is not historical full-fit behavior or inference with a final checkpoint.

1. **State age versus observable persistence.** A large incoming hidden discrepancy may be concentrated in a transient or weakly observed part of the recurrent state. The rival is a discrepancy that persists through the query and continues to reach the readout. After authorized receipt of the binary output, the cheapest falsifier is a CPU summary of already stored main outputs at query offsets0/8/32/96/256/end, plus the end-hidden difference. Use the same rows, current pre-student weights and independent default repeats for any descriptive per-lag numerical floors; no labels, scoring or additional model forward is needed. The source end-hidden was produced before the optimizer step, even though it is stored in the post packet: do not compare it under the subsequently changed branch weights. Preserve each case and RMS rather than select the most responsive rows. Near-floor end responses would weaken persistent mismatch for this window; sustained responses would weaken the transient explanation. Neither outcome establishes global contraction, a burn-in length, or uselessness of input history in other directions. This extends natural state-age analysis, not raw-input corruption or another EMA/student factorial.

2. **A changed gradient versus a changed realized step.** Genuine warm Muon/Adam moments, clipping and weight decay can make a local gradient contrast differ from its realized update contrast. The cheapest falsifier uses the already captured whole preclip gradients and actual parameter deltas: report their baseline norms, absolute differences and descriptive direction agreement, marking zero/near-zero reference vectors explicitly. No CPU replay of CUDA Muon is required: CPU float32 orthogonalization cannot stand in for the actual CUDA low-precision path. A substantial gradient contrast with a negligible realized-step contrast is consistent with optimizer filtering, but does not identify clipping, momentum or one loss head as its cause. A substantial step contrast rejects a purely gradient-only interpretation for that moment state; it still says nothing about a useful descent direction on unseen data. Do not sum uncertified component gradients, reset moments, or infer a conditional/full-GRU optimum. Default-repeat stability is not universal certification of altered-branch operation noise.

3. **Gradient credit versus the timing of parameter changes.** Training carries hidden generated under changing parameters; fixed-checkpoint inference carries hidden under fixed parameters. This is a protocol distinction before it is a performance defect. The original combo's1000-row updates also change optimizer/scheduler/EMA cadence and loss masses relative to2000 rows. A material state-drift contrast makes state age a concrete rival to a credit-only explanation; a valid narrow null leaves cadence and normalization rivals alive. The strongest next mechanistic discriminator is one common-macrostep credit comparison, conditional on admission: start from the SAME genuine warm pre-state, make two identical1000-row student and EMA forward calls in BOTH arms, change only the student midpoint detach, pool ONE original four-loss functional over4000:6000, and perform one clip/optimizer/scheduler/EMA attempt. Incoming state is shared; do not add a fresh/stale-state factor. Forward/target/loss identity with a whole-gradient difference would demonstrate a credit intervention while excluding within-macrostep parameter-age differences. An identity failure would falsify the instrument before any fit. This is the already proven tiny R5 foundation extended to an admitted backend, not a proposal to reproduce the original recipe with a different objective or run32 fits. Keeping two connected activation graphs can exceed the1000-row probe's VRAM budget; do not silently shrink the batch or borrow its peak as a cost estimate. If it cannot fit the5.5GB observed cap, retain the CPU proof and defer the actual comparison.

My preference is to extract options1/2 from the existing admitted capture first, then consider the single option3 instrument only if it resolves an identified ambiguity and the controller has budget. No new fit is justified by drift detection alone. A later claim of predictive benefit would need an independently frozen learning comparison and component-disjoint evaluation; previously exposed folds are not fresh confirmation, and none of these local diagnostics supplies a public score.
