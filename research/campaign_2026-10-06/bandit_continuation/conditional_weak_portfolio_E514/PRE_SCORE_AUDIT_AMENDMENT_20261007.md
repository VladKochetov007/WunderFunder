# E-514 pre-score audit amendment

Recorded on 2026-10-07 before any E-514 portfolio comparison score was calculated.

This amendment changes only prediction provenance and the pre-score row-order gate. The candidate identities, anchor, calibration rule, outer chain partition, mixture grid, official metric, and scoring protocol remain as preregistered.

## Why the legacy replay gate was replaced

The first audit found that the legacy `ab12_h128_plain_fallback` prediction array has no prediction sidecar binding it to a checkpoint or row-group order. Replaying its current cache against the current official metric gives `global_wp_clip2_v1 = 0.605613678` on the 764 groups named by the current `devB` split, while the 2026-09-15 training log records `weighted_pearson = 0.597818561`. A bounded, chunked legacy block-WP diagnostic over the same cached predictions gives `0.595069713`. These disagreeing diagnostics do not establish a model effect; the old cache cannot be shown to represent the exact fixed checkpoint and target-cache row order used by the old run. The whole-array diagnostic was replaced with a streaming calculation after its 1.5 GB helper scope was OOM-killed; the campaign parent remained below its hard limit and had no local OOM event.

The original requirement to reproduce the old run-card scalar as a row-order check is therefore not a valid gate. The E-514 notebook will instead use fresh inference exports from the frozen checkpoints and bind their checkpoint, prediction bytes, and complete `valid_targets.npz` row-group order in sidecars. It will regenerate the organizer baseline prediction in the current target-cache order and bind it to the baseline ONNX hash, target-cache hash, output hash, and row groups. Old cache files remain historical artifacts and are excluded from the E-514 comparison inputs.

## Revised pre-score gates

Before any E-514 comparative scoring:

1. Export `ab12_h128_plain_fallback` and `ab48_basehead_f0` from their existing one-epoch `model.pt` checkpoints with `scripts/predict_run.py`, using distinct E-514 output names. Confirm exact `(1873, 20000, 2)` float32 shape, finite values, checkpoint hashes, prediction hashes, and row groups equal to `valid_targets.npz` order.
2. Regenerate the supplied organizer baseline with `scripts/predict_baseline.py valid` under the bounded CPU worker. Preserve the old baseline array first. Bind the regenerated bytes to `baseline/baseline.onnx`, `cache/valid_targets.npz`, the predictor source, and the exact row-group list.
3. Retain the existing C1 `model_ep1.pt` sidecar checks and recursive fit/propensity/checkpoint-selection ancestry gates. The first default `model.pt` C1 exports were preserved in `E511_C1_DEFAULT_MODEL_EXPORTS_20261007/`; the frozen E-511 grader rejected those sidecars because it requires the fixed `model_ep1.pt` hashes. Corrected explicit-epoch exports passed E-511 grading and are the E-514 anchor inputs.
4. Hash every used input and sidecar into `SOURCE_MANIFEST_E514.json`, persist the chain partition, and calculate no comparative scores if any gate fails.

No models are fitted or initialized differently by this amendment. The old cache/run-card disagreement is retained as provenance evidence and is not used to select candidates, choose mixture weights, or update a bandit reward.
