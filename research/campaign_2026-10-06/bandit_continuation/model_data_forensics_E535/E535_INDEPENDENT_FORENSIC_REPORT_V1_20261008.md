## Finding

The 0.6674 public endpoint and the H230 one-member public endpoint are not a matched comparison. The most concrete differences are training/evaluation membership and number of independently trained students served. Teacher identities, warm starts, and final use of training rows also differ. I found no evidence that the official mask or sequence-reset rule was implemented incorrectly in H230; both reference and H230 training commands use the same score-aware training weight option. The old incumbent local comparator is invalid because it fit most of the evaluated groups. None of these findings proves a software bug caused the public-score gap.

The user-reported scores are public benchmark observations: teammate pair 0.6674, H230 fold-0 seed-3 single 0.6649, prior own best 0.6660. The artifact snapshot recorded 0.6674 at submission ID 26n9pg4y and H230's handoff was still awaiting a portal result at that time. The later 0.6649 result was not independently bound here to a submission ID or ZIP hash. Do not rewrite either frozen receipt; reconcile the new user-reported result in a separate state update. Public scores are not a causal test of these recipe differences.

## Data semantics, mask, and serving

The competition description says every sequence is 20,000 ordered rows, steps 0–98 are warm-up, and the model state must update on every row, including unscored rows, then reset when seq_ix changes. seq_ix is an identifier, not an input feature or time ordering. Targets t0/t1 are float32 future-movement indicators for i0; the exact target law is undisclosed. Four observed target quanta are documented, so an event-clock hypothesis is plausible, but do not assign an undisclosed market interpretation to the label process. Sources: docs/data_overview.md:35–52, 82–90, and src/wnn/data.py:84–109.

The official metric remains global_wp_clip2_v1: selection is need_prediction AND is_scored, both target and prediction are clipped to ±2, original clipped-target magnitude supplies the weight, and target correlations are pooled globally. Sources: docs/data_overview.md:137–177 and src/wnn/gmetric.py:14–38, 173–215. is_scored is read separately from the model's 112 feature columns (src/wnn/data.py:84–109). In training, --valid-true-mask .03 substitutes a sequence-normalized score-mask weighting with epsilon for the propensity weights on sequences carrying the true mask; it neither removes unscored rows from recurrent state updates nor changes the official grading mask (scripts/train_rnn.py:315–329, 555–583, 1224–1226, 2053–2058). The archived final lane and H230 commands both specify --propensity prop_f0, --prop-power 2, --prop-eps .03, and --valid-true-mask .03. No specific mask mismatch was found.

The current feature code describes ev_i0px as simultaneous changes in the two i0 price-like columns and derives recency features from it (src/wnn/features.py:7–10, 44–81, 112–143). Documentation explicitly warns that p indices identify columns, not quote rank (docs/data_overview.md:127–131). An earlier E535 small-sample artifact used the label “best-price events”; that name is not warranted. Its original JSON and plot remain untouched. The corrected plot labels this as a paired i0_p0/i0_p11 price-code-change proxy.

Both the official sequence-reset rule and H230's package checks support correct H230 sequence reset and deterministic callback behavior. The package has one fixed member and i16 storage; its serving path is submissions/h230_hetero_s3_ep1_i16/pkg/solution.py:1–10, 64–80 and pkg/members.json. The teammate artifact exposes only its hashes and two-member identity in the captured manifest, so exact runner-level comparison remains unverified.

## Bounded EDA and next diagnostic

The completed E535 sample is 24 whole validation row groups selected deterministically (12 H230 fit-valid, 12 H230 excluded-eval; seed 535). It read only seq_ix, i0_p0, i0_p11, t0, t1, and is_scored, one 20,000-row group at a time. All sampled seq_ix values matched the split. The sample shows target-change and paired-price-code-event rates move together across these groups; target plateau medians are usually 2–3 rows. It does not establish a population relation or a training effect. Its purpose is to motivate a falsifiable representation screen.

A useful unconventional mechanism is a dual-clock recurrent student: retain ordinary row-by-row state updates but expose event-time elapsed rows and a gated state decay/update based on paired price-code events and target-change dwell. This asks whether the recurrent model should represent both row time and market-event time, rather than replacing causal row processing. The existing since_i0px feature is a low-cost starting signal. The 24-group plot is only a proposal-generating diagnostic; first verify event/target co-location and official target-weight contribution over the full fixed 468 eval panel before spending a fit. Do not call p0/p11 best quotes.

The active H230 actor profile was launching when this critic was told to finish and release the role. No full parquet table, full prediction array, 1405-group fitting scan, or model fit was run here. ## Prioritized discriminating tests

1. **Serve-pair contribution:** independently fit fresh own-weight H230 seed-3/seed-4 students with identical clean fold-0 recipe, cache, membership, and fixed epoch. Grade each member and their equal prediction mean on the same 468 exposed groups at FP32 and delivered i16. This separates member averaging and quantization from teacher-family effects; it does not estimate public transfer.
2. **Family treatment by budget:** preserve the matched H230 recipe and compare family weight 0 versus 0.1 at fixed epoch 1, then a predeclared longer schedule (e.g. four epochs with fixed epoch 3) in both arms. Keep initialization, cache, target coefficients, sampler, and fold membership identical; no checkpoint selection on the evaluation groups. Compare complete endpoints, not standalone loss.
3. **Teacher-source composition:** with one fixed schedule and own weights, test reference-inspired sources against H230's new same-fold GRU384 component while preserving the 0.8125 source scale. Keep family-head weight fixed and predeclare a main-target-source ablation; do not import teammate weights or claim a replica from architecture resemblance.
4. **Mask falsifier:** add a small deterministic parity probe that hashes per-batch main row weights for representative valid sequences and confirms both implementations apply the same score-mask fallback while still stepping every row. Current source flags match; run only if the probe reveals a concrete path difference.
5. **Event-time representation:** after the full-panel stream diagnostic, compare row-time versus dual-clock students with identical data, initialization, training budget, and fixed evaluation membership. Falsify or retarget the mechanism if paired code-change events do not meaningfully organize target transitions or weighted scored rows.

All validation groups discussed here have prior exposure. Repartitioning them does not create fresh confirmation. Numerical priors for these distinct mechanisms remain null; public scores do not prove an implementation bug.
