Blocker — E508 “controller-reviewed” profile is self-attested, not authenticated.
`e510_raw_teacher_pair/prepare_packet.py:39-51` checks that the receipt’s SHA equals a CLI hash and that a second CLI string equals the first. There is no trusted pinned digest, signed controller record, or other independent attestation. The generated kernel also sets both `WNN_E508_PROFILE_RECEIPT_SHA256` and `WNN_E508_PROFILE_REVIEWED_SHA256` to the same embedded digest (`prepare_packet.py` template around lines 263-264); the worker therefore checks self-consistency only. A forged JSON with the required packet/status/counts, plausible positive timing, <=4.3 GB allocator use, and T4 name can be hashed and passed twice. The tests demonstrate that exact weakness: `tests/test_e510_raw_teacher_packet.py:27-49,75-80` uses a synthetic receipt and accepts its self-computed digest as the controller review. So omission is blocked, but an actual E508 result/review is not required. Block packet materialization and any fit until the reviewed hash comes from an independent trusted source (or verify a signed E508 receipt); add a test proving a structurally valid synthetic receipt is rejected absent that attestation.

Blocker — C1-C4 admission does not close over actual cache-array bytes or schemas.

Correct source checkpoint hashes and coefficients therefore do not prove the student will consume cache arrays produced from those sources. Require array hashes plus shape/dtype/row-order and numerical/mask checks before admission.

Additional cache-path bypass: `validate_files` says the cache root must stay in-repository but only rejects absolute/empty paths (`scripts/validate_bandit_campaign_recipe.py:84-90`); `../` is accepted. `_validate_commands` then compares `--distill-cache-root` against that same recipe-controlled value (`bandit_campaign_recipe.py:200-209,242`), while command digests live in the mutable recipe.
