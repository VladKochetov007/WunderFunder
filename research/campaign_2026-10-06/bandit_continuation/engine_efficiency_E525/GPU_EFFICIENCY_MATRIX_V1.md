## Sequential matrix, not a combinatorial sweep

1. **Baseline:** actual exposed device, B16,20,000 rows,chunk2,000, H23031-output recipe,FP16+FP32 parameters/moments,zero workers, existing fusedAdam/pinned prefetch. Three warmup and20timed outer batches. Preserve actual whole-step profile before optimizations.
2. **GPU-only precision:** identical already-resident tensors, same initializer and gradient/update semantics. FP32 reference; FP16+GradScaler; BF16 only when actual backend supports the required operations. Reset model/optimizer/RNG/scaler per variant. Do not silently enable TF32 in the full-mantissa reference. Three warmup and10timed updates with one matched update/reload check and finite checks. These timings exclude input delivery.
3. **Delivery:** retain baseline physical/effective batch and dtype; zero vsone worker, bounded prefetch depth1 vs2, sequential/memmap cache access. Start with actual measured anonymous memory rather than estimating from on-disk cache size. Change one delivery component at a time. Same sequence order/loss denominators. Include cold and warm cache observations, and do not force unsafe global cache eviction.
4. **Batch:** B8/B16/B32, B64 only after actual memory profile. Declare whether the effective update batch is held constant with accumulation or is itself a new optimization arm. No learning-rate/scheduler/EMA-clock drift hidden as a resource optimization. Select by complete throughput and headroom, not maximum VRAM occupancy.
5. **Two-device cohort:** on two actual T4s, compare two independently seeded workers on separate UUIDs against serial completion. Include shared-host CPU/target IO contention, exact output isolation, aggregate anonymous/pinned memory, watchdogs and data identity reuse. Do not split this small GRU into pipeline stages as the default.
6. **Compile/kernels:** first use a trace to select feature/loss/readout fusion or launch reduction. Count cold compile, warmed time and peak workspace. Preserve forward/state/gradient/one-step parity under its intended precision; validate dropout/RNG, scaler/optimizer support and sequence reset before CUDA graphs. An isolated GEMM gain is not end-to-end evidence.
7. **FP8:** only on an actual supported GPU/library. First a declared eligible Linear/projection block, higher-precision state/reductions and explicit amax/scales; compare cast/calibration overhead and gradient errors. FullGRU FP8 requires an independently implemented supported forward/backward, not a dtype flag. TCN/parallel linear-recurrence teacher descendants can provide a second hardware-compatible route; evaluate fixed-student contribution later.
8. **Vast offer selection:** once working access is supplied, read actual offers, CPU/RAM/disk/network and total billing. Shortlist one economical16-bit card and at mostone FP8-capable alternative. Run the same baseline/shapes, then choose completed fixed-endpoint work/dollar including startup/transfers/export/retained storage. No current price or speed is assumed.

All variants retain their own identified receipts. An OOM or unsupported kernel is execution evidence: preserve it, diagnose and reduce/repair a newly identified probe. Changed precision/batch/optimizer semantics need a separately frozen quality test. A useful stage may be promoted on cost and numerical validity while its scientific score remains unknown; intervals are not automatic rejection gates.

## Numerical and quality checks

Compare outputs, carried states, loss numerator/denominator, parameter gradients, clipping and one optimizer update against the declared reference. Report both absolute/relative errors and finite/overflow/skip counts; do not use one arbitrary tensor tolerance as a substitute for a fixed official endpoint. When stochastic components are active, freeze/replay RNG rather than falsely requiring deterministic equality across unrelated runs.

TBPTT, physical batch, effective update batch, number of optimizer updates and EMA/scheduler clocks are separate fields. Preserve them for a hardware comparison. If they change, create a scientific child with equal-work and equal-time views. A frozen short pilot can detect a broken implementation, but does not establish long-horizon convergence or a public score.
