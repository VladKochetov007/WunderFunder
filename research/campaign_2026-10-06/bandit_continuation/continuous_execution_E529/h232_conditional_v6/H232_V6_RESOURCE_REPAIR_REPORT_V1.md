The abort receipt reports cgroup available memory 8,033,509,376 / 32,212,254,720 bytes (fraction 0.2493929545), just 19,554,304 bytes below the 25% gate; the separate 6.5 GB floor passed. The receipt contains no abort-time `memory.stat` or OOM counters, so it does not establish whether anonymous memory, file cache, or another charge caused the gate. V5 produced no graded result.

There is one earlier `memory.stat` load-boundary observation, not an abort snapshot. Across `load_campaign_split`, `inactive_file` fell from 2,338,213,888 to 133,890,048 bytes while `active_file` rose from 10,305,536 to 2,260,815,872 bytes; `anon` rose from 37,085,184 to 54,882,304 bytes and the sampled file-refault counter remained zero. Under that observed state, V6's conservative cache eligibility would veto relief (`inactive_file < 768 MB` and active file dominates). Later fit/abort composition is unknown. This is a concrete falsifier risk: V6 only helps if a later threshold crossing has reclaimable inactive file and stable anon/working-set signals. The worker must preserve the original abort when it cannot demonstrate that condition and recover measured headroom.

## V6 contract

V6 retains the V5 H232 recipe, explicit AMP initial scale 4096, checkpoint target and fold-0 membership. The historical default-scale recipe remains separately recorded; this is not described as an exact reproduction of that historical default. The training source is unchanged from V5. The only source-archive change versus V5 is an opt-in trace hook in `source/src/wnn/data.py:117-163`: after an existing `SequenceFile.read`, it appends the split, row-group index, and compressed byte range derived from that already-open PyArrow reader. It returns no changed feature, target, mask, ordering, or membership value. Trace writes are enabled only when explicit V6 environment paths bind the exact identity-checked train/valid files.

At a cgroup-only headroom breach, while the unchanged host byte and fraction gates still pass, V6 requires a consistent `memory.current`/`memory.max`/`memory.stat` sample from the same most-constrained cgroup and a comparable prior sample. It considers relief only with at least 768 MB inactive file, active-file/inactive-file ratio at most 4, anon growth at most 128 MB/sample, active-file growth at most 256 MB/sample, and file refault growth at most 64 MB/sample. It then issues `POSIX_FADV_DONTNEED` only against recent, traced compressed byte ranges in identity-bound, read-only train/valid parquet files. It does not write `memory.reclaim`, drop global caches, or change any data/model path.

The original 6.5 GB and 25% hard gates remain in force. Every advice event is capped at 768 MB; a worker is capped at 320 events and 245.76 GB cumulatively, with at least 20 seconds between events. Those maxima reserve 38.4 MB/s and are bounded by the 34,000-second worker lifetime. They cover a conservative 214,749,877,962-byte read ceiling (four complete fit passes, two additional raw-pair passes for setup/fallback-hash conservatism, and one valid-export pass), with 31,010,122,038 bytes of reserve. This is a capacity bound, not an expected eviction volume. After advice the worker resamples; it continues only if the host gates still pass and cgroup available memory is at least `max(6.5 GB, 25% of limit) + 512 MB`. Missing/unsupported advice, identity or snapshot mismatch, insufficient inactive file, active/anon/refault veto, rate/budget exhaustion, or failed post-advice recheck preserves the original abort.

The prepared packet adds one ungraded delivery stage after a successful fit: fixed epoch-3 validation prediction export using `scripts/predict_run.py ... valid --epoch 3 --output-name h232_v6_fixed_ep3 --inference-precision fp32`, capped at 1,800 seconds and still inside the 34,000-second worker cap. The worker verifies checkpoint/provenance hashes, finite float32 output, expected 1873×20000×2 shape, fixed valid row-group ordering, and sidecar hashes. It computes no metric. The root-owned grader may later evaluate that artifact; this packet makes no score claim.
