# H233 recipe and checkpoint audit

**Finding:** the four H233 correction heads trained and received finite, nonzero updates. I found no source or checkpoint evidence that explains the near-anchor result through a dead gradient path, untrained output layer, changed parent, target-scaling error, or evaluation-group use in fitting. The implementation matches its frozen teacher-heavy readout objective. That objective is a plausible reason for small corrections, but this audit did not measure target-to-anchor residuals and cannot establish that cause.

The audit is bound to recipe SHA-256 `a97bf67c68e2988044778f39254122683ef37899dd4384cc6e3571240c373022`, trainer SHA-256 `fd74eb03deb0cea24f89dc5d330fdca6c3135f7f3f48cccb31ac5be84ec9c645`, readout module SHA-256 `2930740c551f34d42e1d300e30a7f1edcb0ca46758c8355018d4a36477829426`, and training-helper SHA-256 `b49233a7ed7e7e44d1a67cd765879a96e9294a5934071840b77da0d37d7424c7`. The runtime lock is SHA-256 `831c3de1ea5ae48a9330f82a2cc829fb93021c8ac82f5dff9e1da40ea8bf1b3b`; the fit terminal receipt is `73f1d03075d637f342e375af2c346ddf1883d8f31029557b94fe886058c0f958`.

The fit receipt records 14,920 completed optimizer updates per epoch, zero skipped updates, and finite loss and gradient checks for all four heads. The root tensor/source check rehashed all 11 runtime members, found 16 parent tensors bitwise unchanged, found all 24 readout-state tensors finite, and recorded 29,840 completed optimizer steps. Epoch 0 to epoch 1 losses declined for every head: hidden-only `0.101552 → 0.101272`, additive `0.101546 → 0.101271`, multiplicative `0.101554 → 0.101288`, and conditional-residual `0.101545 → 0.101272`.

I independently loaded only the two small readout checkpoints on CPU and computed parameter norms; I did not load prediction arrays or rerun the grader. All four final output projections changed between checkpoints. Their output-weight L2 changes were `0.22998` (hidden-only), `0.27397` (additive), `0.09026` (multiplicative), and `0.21040` (conditional-residual). Hidden-projection changes were nonzero in every mode. The hidden-only context projection stayed unchanged, as that control intentionally disconnects it.

The zero-initialized output projection makes each head equal the parent at initialization. On the first backward pass its own output layer can receive gradient while the upstream projection/fusion layers initially receive none; after the output layer updates, gradients can flow into those upstream layers. The observed epoch-0 and epoch-1 changes confirm that this path became active. The parent is explicitly put in evaluation mode with gradients disabled, and chunk inference runs inside `torch.no_grad()`. The fit updates only the separate readout controls.

The actual target code is consistent with the recipe: clipped labels are blended as `0.3 * y_clip + 0.7 * t_clip`; each teacher prediction is scaled by `0.8125`, the two own fold-0 C1 seed-3/seed-4 epoch-3 predictions are averaged, and the teacher is clipped to `[-2, 2]`. The weighted loss clips the target again (idempotent for this convex blend) and weights errors by `abs(y_clip) * main_row_weights`. `main_row_weights` uses the pinned same-fold propensity cache with power `2`, epsilon `0.03`, warmup exclusion, and the `0.03` true-mask correction. The mask correction remains active even though `mask_weight=false`; that setting only avoids using the mask as the initial row-weight definition.

Fit membership is the frozen fold-0 set: 10,535 train groups plus 1,405 fit-development valid groups. The 468 exposed evaluation groups are excluded. The parent is the pinned C1 seed-3 epoch-1 checkpoint. The export terminal receipt reports exact parent-anchor replay parity (`max_abs_error=0`, `RMSE=0`); this checks the parent replay, not whether child corrections equal the anchor. Root supplied the near-anchor grading result as context; this audit did not independently read scores or candidates and makes no score or public-transfer claim.

A useful next comparison, if separately preregistered and admitted, is one direct-label readout arm: keep the same parent, readout controls, fold membership, row weighting, seed, optimizer, two-epoch budget, fixed epoch, and export/grading contract, while changing only the target coefficient to `DISTILL_ALPHA=0` so the readout fits clipped labels directly. This distinguishes a teacher-heavy objective effect from limited correction capacity without changing the architecture. It is a proposal only; no fit was run or authorized here. H233's small deltas do not establish family failure.
