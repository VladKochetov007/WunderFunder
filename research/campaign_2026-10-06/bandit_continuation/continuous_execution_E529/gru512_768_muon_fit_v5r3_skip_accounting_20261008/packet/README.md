# GRU512/768 Muon capacity fit V5R3

V5R3 is an identified successor to V5R2. It preserves V5R2's exact trainer and runner archive, scientific command arguments, FP16 autocast/GradScaler initial scale 4096, seed 9, clean-fold membership, B8 batch, four epochs, fixed epoch-3 checkpoint, two-thread-per-arm allocation, distinct T4 assignment, mounted input closure and memory-safe page-cache handoff. It reuses the completed V4 B8 profiles; it does not repeat profiles. The 512/768 Muon pair is independently initialized and trained. This remains a clean-fold capacity screen, not an all-data teacher-family replication or public forecast.

V5R3 corrects a validator rule that rejected an otherwise finite model whenever GradScaler skipped a step. Each epoch must retain the exact expected optimizer-attempt and completed-batch counts. Completed updates and skips must be nonnegative, their sum must equal attempts, and at least one update must complete. The raw counters and the validator's interpretation are retained in the arm result, so differing realized update counts remain visible. This records AMP behavior; it does not change the scaler, optimizer, schedule, or fit attempt budget.

The frozen trainer reports loss every 20 batches when evaluation is withheld. V5R3 requires all 75 samples per epoch across four epochs, in order and finite; this is explicitly sampled loss telemetry, not a per-optimizer-step loss trace. It also requires finite checkpoint tensors and finite FP32 feature-only predictions for the frozen 468 evaluation groups. The worker does not score predictions or read labels/masks in the prediction path.

V5R1 verified all six mounted inputs by full streaming hash in 390.463 seconds. Immediately before worker admission, the measured 30 GiB host had 4.225 GB available. After the 20% operational reserve, the runner's available worker budget was -2.218 GB; its unchanged 8 GiB-per-worker gate rejected before launching either arm. V5R2 added 64 MiB page-aligned `POSIX_FADV_DONTNEED` hints while streaming full hashes, preserving exact mounted files and the existing RAM gate. The call is only a kernel hint; successful return does not prove eviction. V5R2's bounded 512 MiB synthetic-file probe is retained as local implementation evidence, not as Kaggle memory proof.

The two independent arms each receive two CPU threads and a distinct physical T4 UUID. Shared-host fit timing remains uncertain because prior profiles used four CPU threads per arm; actual per-arm progress and terminal output are required. The packet has no silent batch or single-arm fallback.

Valid local/cloud cross-validation is the primary selection evidence; public evaluation is confirmation, and a public mismatch alone does not automatically kill a direction. No fit is authorized until root embeds an independent source review and an exact conditional-fit receipt.
