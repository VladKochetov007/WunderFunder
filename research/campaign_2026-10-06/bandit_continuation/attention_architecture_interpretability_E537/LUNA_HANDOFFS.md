## Handoff 1: H234 child, feature-wise PLE front end

**Question.** Does scalar geometry, before feature mixing, constrain the current recurrent model? Owner deliverable: one narrow independently written embedding module, train-only knot artifact, integrated candidate/control source, focused correctness receipt, actual-device profile, admitted fit artifacts, predictions and independent grade.

**Implementation contract.** Work initially with K=8 intervals per raw feature, embedding width8. Knots are strictly ordered training quantiles after dropping duplicates; a constant feature uses a deterministic zero/constant basis plus the preserved raw path. Clarification to the initial prose: specify whether K denotes intervals or knots in the config; use `n_intervals=8`, so at most9 breakpoints. The first and last finite breakpoints use the observed fitting range; out-of-range values are clamped in the basis with an unbounded raw residual channel. Never normalize using the rest of the sequence. Fit knots once with bounded streaming fitting-only samples, record channel order and SHA. Use monotone cumulative linear basis coordinates, then a learned per-feature linear map. The learned embedding itself need not be monotone. Project to a shared input width, retaining the same current event/age vector in both arms.

Freeze an equal-parameter linear-embedding control with the same outer projection, GRU and head. The treatment changes only the scalar basis. If it gains, an ordinary parameter-matched nonlinear input MLP is the next discrimination; do not run both extra periodic maps and MLP ablations before delivering this first result. A periodic numeric basis is a later named child with its own frequency initialization, range and aliasing checks.

**Correctness review.** Manual basis values for below-min, at each knot, between knots and above-max; ties/constant/all-invalid handling under the repository's actual finite/sentinel policy; exact fit/eval membership separation; serialization and feature order; basis continuity; finite gradients; identical prefix/full/chunk/row predictions with dropout disabled. Identity/linear basis limit must reproduce its control when initialized accordingly. No full expanded-data cache: compute basis in bounded chunks or fuse the small gather/interpolation.

**Admission and screen.** Profile B2/4, chunk256/512 and GRU hidden128 as the small architecture screen; root chooses a common safe shape for both arms. This is a small-model claim only. Target ceiling20 GPU-minutes for pair fitting, plus declared export/grade time. Measure whether basis expansion or decode dominates. The next scale rung tests the same intervention on the current GRU256/384 recipe or full-data independent teacher. Student path retains a compact spline front end or distills the larger PLE teacher to the baseline input model.

**Falsifier/next action.** If the matched MLP explains the gain, keep the capacity improvement but drop the specific sensor-calibration explanation. If only the small model loses, reserve a bounded full-scale check when basis capacity interactions remain plausible. Save all outcomes; report source/config/knot/prediction hashes.

## Handoff 2: H250 descendant, prefix channel-attention adapter

**Question.** Does a causal estimate of changing cross-sensor relationships improve prediction beyond static mixing or per-channel retention? Owner deliverable: a state module with a slow reference, narrow recurrent integration, paired controls, profile and admitted fit through grade. This is a different operator from appending H250 correlation features.

**Exact state/operator.** One head of d16 initially; no full Transformer. Let current projections be q,k,v from a fixed-width current causal representation. Keep FP32 `C[d,d]`, `aq[d]`, `ak[d]`, all zero at sequence reset. With fixed lambda=exp(-log(2)/64), update `C=lambda*C+outer(q,k)`, `aq=lambda*aq+q*q`, `ak=lambda*ak+k*k`; normalize each `C_ij/sqrt(max(aq_i*ak_j,eps))`; `A=softmax(R/tau, axis=-1)`, initial tau1 constrained positive; read `A@v`. Current-row update precedes current-row output, an explicit causal choice. Denominator epsilon and tau floor are source-bound config fields, fixed before the fit. All three states detach at the same declared training boundary.

Projection/context choice for the first test: current input encoder output, not an extra recurrent cell. Use a zero-initialized residual projection into the baseline readout so all arms initially reproduce the parent if using an audited parent; if fitting from scratch, pair the shared-base initialization. A static full mixer and a diagonal dynamic gate should have the same output width and reported trainable parameter budgets. If control padding creates unused parameters, report actual effective capacity rather than call that perfectly matched. A later H250 appended-cross-moment control can separate generic statistics from multiplicative attention.

**Independent oracle/tests.** At every prefix, recompute discounted cross-products directly from the stored toy prefix and compare to recurrence. Include lambda1 and the admitted decay, zero channels, large/small scale, 20,000 repeated rows, reset A→B→A, arbitrary chunk cuts, suffix perturbation, gradients through q/k/tau and state detach. Verify positive rescaling of one q or k coordinate leaves normalized R unchanged except defined epsilon behavior. Do not assert invariance of the entire v/readout branch. Disjoint batches must not share moments. Set all inference dropout to zero.

**Cost/admission.** State is d²+2d=288 FP32 values =1,152 bytes/sequence at d16; projections, softmax and training activations are additional. At d32 it is1,088 values =4,352 bytes. Stable state size is not proof of fast training. Straight loop may bottleneck GPU dispatch; profile a simple recurrence before investing in a scan kernel. Fixed scientific comparison ceiling20 GPU-minutes plus declared export; no custom CUDA/Triton before its need is measured. Ladder d16→32→64 and one→two layers only after informative evidence. Richer teacher compresses into GRU gates or a fixed recurrent student.

**Interpretation/falsifier.** Full mixing must beat both the static and diagonal mechanisms or earn conditional teacher value in a declared complete endpoint. Synthetic switching-correlation data checks capacity, not competition performance. If the full treatment helps but donor-state/diagonal tests show no dependence on off-diagonals, reclassify the explanation. No hard scientific rejection from a single noisy small-screen delta.

## Handoff 3: H218/H228/H120 interaction, grouped causal Transformer teacher

**Question.** Does separating sensor identity, within-row mixing and causal history improve on the current row-token attention recipe, and does dual-clock bias add value when the baseline already receives the same event-age features? Deliverable: an independent teacher implementation and complete source-bound recipe; staged fit/export/grade after reviewed actual-device profile. Preserve the existing H218 prototype and its chronology evidence.

**Minimal v1.** Reuse the H218 layer's *state-interface expectations* as a project convention, but implement own group attention clearly. d96, 8 learned group slots, 2 temporal layers, 4 heads, local window64. Feature token `e_j + numeric_map_j(x_j)` uses raw channel identity; no assumption that p-index is book depth. Learned within-row slot queries pool112 raw tokens into8 group tokens; this pooling uses only the current row. An identical current event/age path is available to all arms. Each group attends to its own past/current group tokens within64 rows; a current-row cross-group attention layer exchanges information. Two target queries attend to the current group states and use separate scalar heads. Keep a direct current-row linear path.

**Chronology specification.** Full batch tensor dimensions are `[B,T,G,D]`; group attention never treats future time as another feature. A mask permits `s<=t` for history and `s=t` for current cross-group mixing. LayerNorm runs over D only. No time-axis BatchNorm, context RevIN or full-chunk centering. For streaming, per layer store at most64 preceding key/value tokens per group (define whether current token counts toward64; choose current+63 prior), and row/group event counters. `None` initializes every tensor/counter; detach state only at the declared credit boundary. Training chunks may be256/512 but cannot silently truncate inference cache differently. Completed long-block summaries are **not** in v1; v2 may add only causally completed16-event blocks and a separately represented live prefix.

**Clock v2, separately identified.** Retain exactly the same observable event flags/age inputs in row-clock and dual-clock controls. For each pair `(t,s)` add learned bounded functions of log1p(row distance) and log1p(observed group event-count distance), plus known current age. Define group events from either fixed fitting-only groups or a fixed documented feature grouping; a differentiably changing group definition cannot silently redefine an already cached event count. Compare row-distance bias alone versus dual bias with equal input features and matched bias capacity. Never use target-change time, next-label-change distance or scored mask as input.

**Tests and current-source traps.** Future-suffix invariance must hold at every layer, including group pooling, normalization, event counts and output head. Compare full pass versus row-by-row versus random chunk partitions across block/cache rollover. Change sequence ID/reset between identical prefixes and require replay equality. All-invalid group handling, float32/AMP gradients, save/reload, masks on partial chunks and teacher-cache row alignment are explicit checks. Upstream iTransformer's context-axis mean/stdev and PatchTST's whole-context patch/flatten head are valid for their forecasting contract but cannot generate causally valid per-row outputs from a full current chunk without adaptation. XCiT's token-axis normalization similarly requires prefix treatment. Source verification details are in SOURCE_REVIEW.md.

**Comparison and ladder.** First deliver a matched row-token H218-style baseline versus group-token model at the same declared data/update budget, reporting parameter/FLOP/runtime mismatch honestly. Reuse C's basis only if the interaction is registered; otherwise use linear scalar maps in both. Then dual-clock v2 versus row-clock v1. Do not spend the full3-way ladder before the first terminal result. Profile actual cloud B2/4 and chunk256; proposed fit ceiling30 GPU-minutes for the first small pair, export separately accounted. Teacher ladder d192/4 layers/window256 → d384/6/window512+completed summaries. Actual measured hardware decides whether single GPU, dual independent GPU workers or TPU is appropriate; any TPU production needs the project's numerical/full-shape checks.

**Student and endpoint.** Train all teacher weights independently; cache predictions only for membership allowed by the declared ancestry. Compare a fixed recurrent student trained with the old own recurrent-teacher target mixture versus the same student with the new attention-teacher contribution. Report standalone teacher, student, and a fixed served blend endpoint separately. A weaker teacher can be useful conditionally. The final official ZIP/runtime test is a later deliverable owned by root; this report promises no public improvement.
