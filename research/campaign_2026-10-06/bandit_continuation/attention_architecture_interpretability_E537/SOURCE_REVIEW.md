# E537 primary-source review and transfer boundaries

This review verified 14 primary research papers, author repositories for five methods, and specific source files for XCiT, iTransformer and PatchTST. It did not run any third-party implementation. All proposed transfers are our hypotheses, not evidence of Challenge2 improvement. The current implementations remain independently authored by the later actor. Numerical priors remain null.

## Claim–source ledger

| Primary source | Component actually supported | Proposed transfer and gap |
|---|---|---|
| Katharopoulos et al., ICML2020, [Transformers are RNNs](https://arxiv.org/abs/2006.16236) | Kernelized causal attention can be expressed through recurrent sufficient statistics. | Makes finite-state attention plausible; does not establish that a normalized linear memory preserves the important financial history. |
| Schlag, Irie and Schmidhuber, ICML2021, [Linear Transformers Are Secretly Fast Weight Programmers](https://proceedings.mlr.press/v139/schlag21a.html) | Delta updates correct a key–value map rather than only adding outer products; finite memory has collision limits. | E537-A transfers targeted overwriting. Its proposed predictive benefit and key interpretation remain untested. |
| Yang, Kautz and Hatamizadeh, [Gated Delta Networks](https://arxiv.org/html/2412.06464v1), equation8 | Global decay and key-specific replacement combine in one recurrent matrix update. Chunkwise training is a distinct algorithmic concern. | E537-A equation is algebraically the same update in value×key orientation. A naive Python row loop does not inherit paper throughput. Author README verified; kernels not audited. |
| Gorishniy, Rubachev and Babenko, NeurIPS2022 / arXiv v4, [On Embeddings for Numerical Features](https://arxiv.org/abs/2203.05556v4) | Piecewise-linear and periodic scalar embeddings are useful degrees of freedom across multiple tabular backbones. | E537-C tests scalar geometry at fixed temporal backbone. It does not assume unknown channels are physical prices/volumes. |
| Liu et al., ICLR2024 / arXiv v4, [iTransformer](https://arxiv.org/abs/2310.06625v4) | Variate histories become tokens and attention mixes variates. | Group/entity tokenization motivates D. The source forecasts after an observed window; per-row streaming requires a new causal history encoder, not a transpose alone. |
| Nie et al., ICLR2023, [PatchTST](https://arxiv.org/abs/2211.14730) | Subseries patches and channel-independent processing reduce temporal token count. | Only completed causal patches or the live prefix may summarize past rows in D. Coarse tokens can erase brief microstructure events, so retain a current-row path. |
| Kidger et al., NeurIPS2020, [Neural Controlled Differential Equations](https://arxiv.org/abs/2005.08926) | Observations can drive an evolving latent state for irregular multivariate streams. | Motivates observation-driven clocks, not an ODE-solver dependency. Whole-series interpolation used in some methods must not leak future samples into online predictions. |
| El-Nouby et al., NeurIPS2021 / arXiv v2, [XCiT](https://arxiv.org/abs/2106.09681v2) | Channel attention is built from query–key cross-moments normalized across tokens. | E537-B transfers the channel operator and replaces image-wide normalization with explicit prefix state. This recurrent adaptation is not the published image model. |
| Chevyrev and Kormilitzin, [Signature primer](https://arxiv.org/html/1603.03788v2), Chen identity section | Iterated integrals encode ordered path information; signatures of adjacent path segments compose algebraically. | E537-E selects antisymmetric level2 areas and trailing windows. Raw time stays in another branch; invariance alone is not a task benefit. |
| Hyvarinen, Sasaki and Turner, AISTATS2019 / arXiv v3, [Nonlinear ICA Using Auxiliary Variables](https://arxiv.org/abs/1805.08651v3) | Identifiability can follow under explicit conditional-source and auxiliary-variable assumptions; real versus randomized auxiliary pairs yield a contrastive construction. | E537-G uses history as a possible auxiliary and treats sensor semantics as hypotheses. Interacting/noninvertible financial sensors may violate the assumptions. |
| Cont, Kukanov and Stoikov, [The Price Impact of Order Book Events](https://arxiv.org/abs/1011.6402) | In the authors' actual market data, order-flow imbalance relates to short-interval price change and depth. | Motivation for event innovations and normalized relationships; no license to name anonymous channels, reconstruct true OFI, or import external market data. |
| Cont, Cucuringu and Zhang, [Cross-Impact of Order Flow Imbalance](https://arxiv.org/abs/2112.13213) | Their multi-asset analysis distinguishes contemporaneous explanatory impact from lagged forecasting effects. | Motivates testing ordered cross-group lag information in E/G, rather than treating all correlation as predictive causation. |
| Jain and Wallace, NAACL2019, [Attention is not Explanation](https://arxiv.org/abs/1902.10186) | Attention weights are not automatically faithful explanations of a model's prediction. | E537-H uses intervention controls. A heatmap alone cannot identify which anonymous channel economically causes a target. |
| Zhang and Nanda, ICLR2024, [Towards Best Practices of Activation Patching](https://arxiv.org/abs/2309.16042) | Localization conclusions depend on corruption and evaluation choices. | E537-H requires zero, realistic matched-donor and random-donor controls, with a known-mechanism sanity case. Findings in language models do not validate a financial interpretation protocol. |

## Specific author-code findings

The exact source bindings are in [CODE_SOURCE_MANIFEST.json](CODE_SOURCE_MANIFEST.json). GitHub API `commits/main` was resolved, then raw files were fetched at that immutable commit and hashed. No fetched source was executed or included in an implementation. This matters because browser-cached `main` pages and current raw fetches had different line numbering; use pinned revisions, not an unqualified line number on a mutable URL.

- **XCiT**, `82f5291f412604970c39a912586e008ec009cdca`, `xcit.py`: XCA transposes q/k/v to channel×token layout, L2-normalizes q/k over the token axis, forms channel attention, then mixes v. Applying that normalization over an entire training chunk while predicting its earlier rows is future leakage. E537-B's prefix square sums replace this operation; it uses uncentered cross-moments deliberately. [Pinned source](https://github.com/facebookresearch/xcit/blob/82f5291f412604970c39a912586e008ec009cdca/xcit.py).
- **iTransformer**, `c2426e68ca13f74aaec08045c5c724d8ad328124`, `model/iTransformer.py`: context-axis mean/stdev precedes inverted embedding; the head outputs a future forecast after the input window. This is coherent for that source task. Calling it once on a full chunk and decoding earlier rows as online outputs would violate our contract. [Pinned source](https://github.com/thuml/iTransformer/blob/c2426e68ca13f74aaec08045c5c724d8ad328124/model/iTransformer.py).
- **PatchTST**, `204c21efe0b39603ad6e2ca640ef5896646ab1a9`, `PatchTST_supervised/layers/PatchTST_backbone.py`: optional RevIN, temporal `unfold`, per-channel encoder and flattening over patches form a whole-window forecast path. End padding repeats the last observed value; padding alone is not a future leak for a forecast after the window. The streaming problem is using a completed future part of a chunk to emit earlier rows. [Pinned source](https://github.com/yuqinie98/PatchTST/blob/204c21efe0b39603ad6e2ca640ef5896646ab1a9/PatchTST_supervised/layers/PatchTST_backbone.py).
- **GatedDeltaNet**, `b53d6d3a161267432a79c1c04af69fa52bddc921`: author repository/README provenance verified; the primary paper's recurrence was inspected. This is not a kernel, license-compatibility or package-install audit. [Pinned README](https://github.com/NVlabs/GatedDeltaNet/blob/b53d6d3a161267432a79c1c04af69fa52bddc921/README.md).
- **Numerical embeddings**, `a8fc25025c83f2321c63ff127a3bcef83bb1bfb5`: the old author repository URL redirects to `rtdl-num-embeddings`. README provenance and backbone-independent scope verified; package implementation not audited. Proposed quantile choices and state handling are our recipe, not a claim of exact paper reproduction. [Pinned README](https://github.com/yandex-research/rtdl-num-embeddings/blob/a8fc25025c83f2321c63ff127a3bcef83bb1bfb5/README.md).

## Random-library lens and negative transfer

A seeded random draw used seed537 over the sorted five EPUB files found under the user's Downloads library. It selected *Найди своё Почему* (Find Your Why), chapter `OPS/ch1-2.xhtml`, book SHA256 `61787bf0681a5466eda11cea463bf90ea1ccd8f26173eb356b55865b7521472c`. After selecting the book, the same RNG chose among long content chapters (excluding nav/toc/cover/title/copy/index names), then among 1,500-character chunks containing at least700 characters. The sampled passage included:

> Я согласился со всеми советами в теории, но я не знал, что должен изменить.

This motivates only an operational question: what concrete behavior would change in the next experiment? It provides **no scientific evidence** for memory, attention, market structure or profitability. The attempt to transfer a technical component yielded none; no more congenial replacement draw was substituted. [Selection record](RANDOM_SOURCE_SELECTION.json) lists the pool and procedure. The unconventional technical proposals instead draw from vision channel attention and rough-path ordered areas, with their separate primary-source basis.

## Source failures and limits preserved

An initially guessed arXiv ID `1901.03422` resolved to *Contour forward flux sampling*, not the nonlinear-ICA paper. It was excluded; the verified source is `1805.08651`. The Transformer Circuits framework site returned an internal error; its text is not used as supporting evidence. Search also surfaced modern Hopfield work, but no separate card depends on it. Secondary blogs, scraped summaries and social posts were not used to substantiate the proposed technical claims.

No paper's reported speedup/benchmark score is transferred to our setup. Runtime/API/library compatibility and the actual required tensor shapes remain for Luna's implementation/profile. No unrelated private documents, credentials, teammate weights or raw competition data were uploaded. Browsing queries contained only public method names and general modeling concepts.

## Tool and evidence scope

`web.run` provided primary-source title/abstract/full-text and author-code inspection; it is retrieval evidence, not an implementation verifier. `exec_command` supplied bounded filesystem/source checks and HTTPS raw-source hashing. `scripts/limited` bounded the library/source support commands to1 CPU/1.5GB/120s. `apply_patch` wrote isolated proposal artifacts. `functions.exec` V8 evaluated the small finite-distribution/area examples in [ALGEBRA_EXAMPLES.json](ALGEBRA_EXAMPLES.json); those confirm the illustrative arithmetic only. Neither examples nor source agreement establish competition quality. No source repositories were cloned, built or trained.
