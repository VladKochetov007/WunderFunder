# E519 weak-diversity cohort packet plan

Status: **plan only**. No packet has been built, no Kaggle submission/profile has been launched, and no model has been fit. This is a development screen on already exposed fold-0 validation groups; it cannot support a fresh generalization or public-score claim.

The proposed cohort is two scratch-trained, deliberately small models using the same fold-0 complete-chain exclusion, raw input view, clipped-label weighted MSE objective, and matched two-epoch budget:

| ID | Family and proposed configuration | Why it is diverse |
|---|---|---|
| `e519_tcn_s519` | causal TCN, hidden 32, 5 layers, linear encoder, no TCN mixing, dropout 0, seed 519 | finite local receptive field (32 rows), convolutional state update |
| `e519_structured_s520` | structured-state recurrence, hidden 96, 2 layers, multi-timescale decay, linear encoder, dropout 0, seed 520 | fixed scalar/rotation state dynamics rather than a plain GRU |

Both fit from scratch; neither consumes a teacher, teammate weights, or a prior checkpoint. Use `--raw-only`, `--loss wmse`, and `--loss-norm chunk`; the official evaluator still clips predictions and labels at ±2 and uses the original clipped-label magnitude weights. Do not substitute training clipping for metric clipping. Use one shared batch/chunk shape selected from the actual T4 profile, two epochs, and only epoch 1 for the registered prediction. Do not tune seeds, epochs, targets, or candidate selection after seeing the held-out score.

The static source/data identities and all unknown-at-plan-time outputs are in [E519_PACKET_PLAN.json](./E519_PACKET_PLAN.json). In particular, the two candidate checkpoint, provenance, and prediction hashes are `null` until a separately admitted fit and download; they must be filled from the terminal files, never inferred. The existing generic Kaggle bundle/runner/kernel path can carry a custom frozen cohort driver and the existing hashed fold assets. The specialized E510 builder is not a usable template as-is: its older E508 receipt contract, `cuda:0` spelling, and 6,300-second pair assumption do not match the current trainer/runtime evidence. No bundle, kernel source, or upload is prepared here.

## Dependency and command plan

1. **Controller freeze/review.** Recheck live Kaggle quota and actual T4, runtime, RAM, and input dataset identities. Freeze the reviewed code, data, split, recipe, resource caps, and packet source hash. The `vladkochetov07/wunder-funder` dataset identity below was observed for E508 v5 on 2026-10-07 and must be refreshed before use.
2. **Profile-only packet.** Mount `vladkochetov07/wunder-funder` and `vladkochetov07/wnn-c20261004-fold0-assets`; check both parquet full-file/footer identities, fold-0 membership, cache identities, and minimum RAM/headroom. For each model, profile the common candidates `(batch, chunk) = (16,2000), (8,2000), (8,1000), (4,1000)` using trainer profiling mode (`--profile-warmup 1 --profile-steps 3`). The profile process must exit before the fit loop and emit no checkpoint or predictions. Record actual-device allocated/reserved peaks, elapsed timed steps, RSS, and device identity. Select the fastest common shape only if each family is at most 2,000,000,000 allocated bytes and below 2,500,000,000 allocated **and** reserved bytes. If no shared shape passes, stop without fitting.
3. **Independent profile review.** The controller/critic checks the receipt, memory margin, throughput projection, current quota, and exact packet hashes. Only then may the separate fit packet be admitted. Profile GPU time is tracked separately and is capped at 1,200 GPU-seconds; it counts toward the 12,000 GPU-second cohort ceiling.
4. **Serial fit and prediction packet.** On one T4, run the two jobs serially with the selected common `BATCH` and `CHUNK`; no parallel workers. Command templates (the values in angle brackets are frozen only after profile review):

   ```sh
   python scripts/train_rnn.py --name e519_tcn_s519 --data-root /kaggle/input/wunder-funder/datasets --output-root /kaggle/working/e519 --arch tcn --hidden 32 --layers 5 --tcn-mix 0 --dropout 0 --enc linear --raw-only --loss wmse --loss-norm chunk --epochs 2 --seed 519 --batch-size <BATCH> --chunk-size <CHUNK> --device cuda --split-manifest /kaggle/input/wnn-c20261004-fold0-assets/fold0.json
   python scripts/train_rnn.py --name e519_structured_s520 --data-root /kaggle/input/wunder-funder/datasets --output-root /kaggle/working/e519 --arch structured --hidden 96 --layers 2 --decay-init multi --dropout 0 --enc linear --raw-only --loss wmse --loss-norm chunk --epochs 2 --seed 520 --batch-size <BATCH> --chunk-size <CHUNK> --device cuda --split-manifest /kaggle/input/wnn-c20261004-fold0-assets/fold0.json
   python scripts/predict_run.py e519_tcn_s519 valid --epoch 1 --output-name pred_e519_tcn_s519_valid --inference-precision checkpoint
   python scripts/predict_run.py e519_structured_s520 valid --epoch 1 --output-name pred_e519_structured_s520_valid --inference-precision checkpoint
   ```

   These are recipe templates, not verified runnable packet commands yet: before freezing a packet, resolve `--data-root`, split-manifest mount, output-root, and any required trainer flags against the pinned trainer/parser and actual Kaggle mounts. A command/parser mismatch is a pre-fit failure; correct it in a newly reviewed packet. Inputs must show 10,535 train groups and 1,405 validation-training groups in fit membership, with the 468 evaluation groups excluded, and the known corrupt train group 528 excluded. Expected prediction row membership is 1,873 validation groups, including the 468 held-out groups.

5. **Independent comparison.** Download all terminal model/checkpoint/provenance/prediction files and phase/resource logs; hash them. A grader (not the fit actor) fixes the C1 anchor to the equal mean of E511 seed-3 and seed-4 epoch-1 predictions, then scores only the fold-0 held-out 468 complete-chain groups with the frozen official masks/metric. Within 3 folds of the 141 connected components, choose the candidate with the lower absolute weighted residual correlation to the anchor on calibration components. Fit one pooled scalar `lambda = clip(sum(w*d*r)/sum(w*d*d), 0, 0.25)` on those calibration components, where `r = clip(y)-clip(anchor)`, `d = clip(candidate)-clip(anchor)`, and `w = abs(clip(y))*scored_mask`; apply that scalar to both output channels on the held-out components. Report anchor-only (`lambda=0`), both candidates separately, the selected candidate blend, and a matched-random candidate control chosen uniformly from the same two candidates by preregistered RNG seed `51920261007`, using the same shrink rule. Pool OOF predictions and use a paired connected-component bootstrap. Existing evaluator support for this exact anchor/control comparison is **unverified**; before fitting, the controller must validate it or assign an independent grader implementation. All data and fold-0 results are exposed, so this remains a development screen.

## Resource gates and stop paths

- **Live provider gate:** refresh Kaggle submission quota, active-session limits, remaining runtime, actual GPU model/count, RAM, and input dataset versions immediately before each packet. These provider values are unknown in this plan. Require exactly one T4 and adequate remaining quota/runtime; otherwise stop before profile/fit. Do not infer current caps from the historical E508 receipt.
- **Worker envelope:** one GPU worker; profile cap 1,200 GPU-seconds and 1,200 wall seconds; fit plus prediction cap 10,800 GPU-seconds and 10,800 wall seconds total; per-candidate cap 5,400 seconds. Absolute cohort ceiling is 12,000 GPU-seconds, including profile. Configure outer worker GPU memory limit 2,000,000,000 bytes and stop threshold 2,500,000,000 bytes; RSS limit 16,000,000,000 bytes; zero data-loader workers. Require at least 4 GiB and 20% RAM headroom after mounts/cache setup. Tighten these limits if live Kaggle limits are lower.
- **Before-fit profile gate:** abort the profile packet before any fit if actual GPU is not one T4; either family exceeds 2.5 GB allocated or reserved; worker RSS exceeds its limit; minimum RAM headroom is absent; the input/membership/checkpoint identities mismatch; or the shared profile shape is infeasible. No automatic OOM retry or shape growth. If a monitor observes >2.5 GB allocated/reserved during any later job, terminate the worker and mark the cohort failed; do not start the second candidate.
- **Runtime gate:** stop at the profile or fit/prediction wall/GPU ceiling, preserve phase logs and partial outputs, mark incomplete, and do not report a scientific negative. Do not retry under the same packet ID. Any repair requires a new reviewed packet/ID and remaining aggregate budget approval.
- **Identity gate:** fail closed on full parquet/footer mismatch, fold/split/cache hash mismatch, wrong group counts, unexpected input mounts, or missing C1 anchor files. Record expected and observed fingerprints before termination.

## Runtime estimate and evidence boundary

E508-v5's actual T4 profile observed 1,054,505,472 allocated bytes, 1,765,801,984 reserved bytes, and 14.98 sequences/s. Its projection for two 4-epoch GRU fits plus exports was 8,524 seconds, exceeding that older packet's 6,300-second cap. A crude equal-throughput estimate for two 2-epoch E519 candidates is about 4,262 seconds of fit/export work, plus prediction; this is only a planning proxy because TCN and structured-state throughput may differ. Profile GPU work is budgeted separately at up to 1,200 seconds; the hard 12,000-second ceiling dominates. The observed E508 profile is not evidence of E519 memory, throughput, quality, or a score gain.
