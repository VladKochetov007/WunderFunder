# E540 V4 bounded private warm cohort

V4 is a delivery correction to the explicit V3 AMP4096 paired screen. It preserves V3's clip2-target WMSE/chunk objective, disabled auxiliary/distillation/propensity paths, 512 complete fitting components, the fixed exposed 468 evaluation groups, 4096 initial AMP scale in both arms, fixed epoch-0 checkpoint, and zero-skip gate. The V3 card, recipe, subset and Kaggle packet remain unchanged.

The V3 profile projection used elapsed wall time measured after both profiles and then added both profile durations again. V4 treats gate-time elapsed as complete through profiling and adds only projected fit and prediction work plus the existing 300-second estimate margin. The separate worker timeout also leaves 300 seconds for runner finalization before the outer kernel deadline. A focused boundary test covers 20+30 seconds of profiles already included in 70 elapsed seconds (370 seconds total with zero projected fits/exports and reserve), and a 5,200-second exact-boundary case.

The bootstrap starts a 6,000-second kernel-process monotonic deadline at entry, covering bundle discovery, verification, extraction, input mounting, runner execution and runner completion. It dynamically writes a runtime copy of each recipe spec with timeout `min(5,200, remaining kernel time - 300 seconds)`. The worker independently recomputes the same reduced ceiling at its start after runner preflight. The finalization reserve lets the runner export receipts/artifacts and exit; the kernel bootstrap terminates only its runner process tree if the outer deadline expires.

The 6,000-second clock begins when the kernel process starts. Kaggle queue/cold start before process entry and provider transport after process exit are provider-controlled and are outside this deadline; this packet makes no hard provider-from-push 6,000-second promise.

The private packet is `kaggle_v4_20261008/E540_KAGGLE_PACKET_V4.json`; its generated `bundle/kernel/kernel.py` receives its own SHA-256 in the packet in addition to the opaque transport archive and kernel metadata hashes. Construction does not call Kaggle, fit, grade, hash the complete local parquet/target archives, or embed external data or model weights. The worker stream-hashes mounted inputs for byte identity before Torch; prediction does not parse labels or masks, and the feature reader requests features only for the frozen 468 groups. Root must independently review the source, hashes, actual live quota and provider headroom before any upload or fit.
