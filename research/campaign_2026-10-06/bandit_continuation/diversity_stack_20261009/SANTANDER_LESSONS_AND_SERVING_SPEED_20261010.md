## Inference-time plan (portal timeouts P1/P3 at 61m57s; P2 passed; portal up to 2x slower than local replay)
Budget rule going forward: gate a package only if local timed replay of the delivered ZIP <= 25 min (portal factor 2 plus margin), not 60 min.
Measured: ~74 us/row for width-256 2-layer GRU (i16), ~733 us/row/member for h384 on the current kernel (tuned for 256).
Per row MACs ~ 112*768 (input) + 3*256*768 (rec1, in2, rec2) ~ 0.68 M; 74 us ~ 9 GMAC/s, well below single-core AVX2 i16 peak (tens of GMAC/s): the loop is latency/dependency bound, so wins come from restructuring:
1. Exact, cheap: incremental input projection. Blocks update on 31/40/15/12/70/100% of rows; keep the cached W_x * x and add the delta only for changed columns (exact since the layer is linear). Saves a share of the 86k input MACs; expected -5..-8% time.
2. Exact: skip the readout/output head on unscored rows (rows < 99 and unmasked rows) while still advancing state.
3. Block-importance pruning (R3-9): remove input columns with zero permutation importance (exactness not required, score re-measured).
4. Kernel: profile with `perf stat` (IPC, L2 misses); fuse gate nonlinearities with the matvec, pre-transposed packed weights, 16-wide i16 madd accumulations, prefetch next layer weights; width-384 needs its own tile sizes (733 us/row means the 256-tuned kernel is mis-tiled; a tuned kernel could plausibly reach ~200-300 us).
5. Lower activation cost: piecewise-linear/LUT sigmoid/tanh (check we already use LUT).
6. If the portal permits batching sequences or threads (to verify in the starter pack API): interleave several sequences' recurrences to turn matvecs into small matmuls (big speedup); the DataPoint interface seems per-row, so probably not.
Next actions: (a) profile the P1/P3 kernels on this machine under `scripts/limited` and record where time goes; (b) implement 1+2 behind a bit-exact test against the current output; (c) time the delivered ZIP again with the 25-minute gate.

## Evidence added: the timeouts were not model-dependent
All three packages are the same 74 us/row class (width 256 / h230 students, one member). Portal: P2 finished in 34m01s (local estimate ~30 min, so portal factor ~1.1), P1 and P3 hit the 60 min cutoff (61m56s). So the portal run time varies by >2x for identical-cost models; suspected cause: concurrent evaluation of the three uploads / shared host load. Policy: (1) upload ONE package at a time and wait for its score before the next; (2) require local timed replay <= 25 min (leaves 2.4x headroom); (3) reduce per-row cost (below). The native kernel is already tuned (zero-column skipping in the projection = exact incremental input, i16 panels, AVX2 gates, prefetch, arena layout), so the remaining exact gains are mainly: skip head on unscored rows, fuse layers, and block pruning (R3-9); expect 10-20% not 2x. A 2x needs a smaller served net (e.g. h192, ~half cost) whose score loss is smaller than the timeout risk: measure a width-192/224 student on fold 1.

## BNP Paribas talk (writeups/semenov.txt, Russian ASR text) and linear-dependency EDA
BNP lesson: the winners de-obfuscated the columns (found exact linear relations such as va = vb + vc, saw 'discrete value + noise, rescaled to [0,20]', undid the transform) while the rest used generic ML; target-statistics encodings were the generic winners. `scripts/linear_dependency_probe.py` on 4 valid sequences (6,000 rows each): the 112 columns are strongly linearly redundant. Levels: 90/99/99.9% of variance need 33/66/82 components; 28 columns have R^2 > 0.999 from the others (39 > 0.99, 54 > 0.9); smallest singular values are 0, i.e. exact linear relations exist (pair corr 0.9996 for columns 1-2, 0.9989 for 53-54). Deltas behave the same (23 columns R^2 > 0.999).
Consequences: (a) input compression 112 -> ~80 channels is nearly lossless, cutting the 86k-MAC input projection by ~30% (serving speed) and removing exactly redundant noise paths; (b) the exact relations are the BNP-style key to the anonymous encoding (price/depth mixings, E-090 'full-rank mixings of depth' is only partly true); (c) a whitened/de-mixed input may help the GRU. Queue R3-3b: train on 82 PCA components (or pruned independent columns) and compare to default; falsifier fold 1 >= default mean - 0.001 for equal score at 27% lower input cost, or >= +0.003 for a real gain.
