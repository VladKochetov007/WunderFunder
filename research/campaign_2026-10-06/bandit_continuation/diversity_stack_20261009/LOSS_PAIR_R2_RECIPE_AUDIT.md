The parsed-cache arrays contain 112 raw float32 features per row. The existing `train_rnn.py` path runs `build_inputs()` unless `--raw-only` is passed. The model is `RNNModel(n_in=211, hidden=256, layers=2, dropout=0, n_out=2)`: linear input projection, exact GELU, two-layer PyTorch reset-after GRU, and a `Linear(512,256) → GELU → Linear(256,2)` head. The raw cache is not the model input tensor until feature construction is applied.

With these commands, fit loss weights are not the cached `is_scored` mask. `main_row_weights()` returns the default validity mask because there is no propensity checkpoint, `--mask-weight`, class, since-event or other weighting flag. `valid` is `row_index >= WARMUP`, and `WARMUP=99`; thus each chunk loss uses `abs(clip(y,-2,2)) * valid` per target channel. The `is_scored` mask is retained for the fixed official evaluation export/grade and has the first 99 rows removed there. The fit/evaluation membership remains the existing fold-0 cache contract: 350 `fit_train`, 28 `fit_valid` unused, 468 fixed evaluation sequences, membership SHA `dbd9ea6d7b0b752495745ea1ebd4bd858af9305c40f0ada7de7386c5359f3acd`.

Copy per-channel mean and `std.clamp_min(1e-3)` into the model. The fit order is the same sampler at epochs0 and1; parsed-cache mode uses `drop_last=False`, so all350 sequences are used. Do not claim optimizer parity from matching only `lr`, `weight_decay` and `beta2` flags.

The treatment is weighted Huber with `delta=1.0` in clipped target units. The arm commands differ only by `--loss wmse` versus `--loss huber`; `--huber-delta 1.0` is present for both. Each arm starts from the same Torch-seeded model parameters and same normalization values for cross-device pairing. ## Sol delivery continuation: worker and interface repairs

Owner: user-authorized Sol6.1/medium lead, isolated `codex/sol-diversity-delivery-20261009`; no provider dispatch or model fit authorized by this audit. The abandoned untracked GPU worker in the stopped Luna checkout is excluded.

The inspected worker already carried `next_state` across chunks through a misleadingly named `zero_state`; this was not an observed missing-carry bug. The revised worker uses a distinct `recurrent_state`, resets it once per complete sequence batch, and buffers ten update diagnostic scalar tuples before one synchronized boundary. Dispatch times are explicitly labeled enqueue times; synchronized batch time and fit wall time supply measured execution costs. Warmup updates are discarded.
