# Loss-pair R2: executable trainer semantics for GPU/TPU matching

Owner: Luna/max benchmark actor. This R2 interpretation supersedes the inaccurate architecture and mask descriptions in `LOSS_PAIR_R1.md`; it preserves the loss-only WMSE-vs-Huber scientific question, component membership, commands, seed and budgets. It is not a new fit authorization.

The parsed-cache arrays contain 112 raw float32 features per row. The existing `train_rnn.py` path runs `build_inputs()` unless `--raw-only` is passed. The frozen commands omit `--raw-only`, so the model receives 211 columns: the 112 raw values followed by the 99 causal event features from `event_features_torch`. `--raw-only` would still preserve the 211-wide projection and zero the event columns; it is not part of this recipe. Feature implementation SHA-256 is `284c119d150b74bff0ccc2628bc2a195ca61c351a628b085b7d9dd85512bfeee`.

The model is `RNNModel(n_in=211, hidden=256, layers=2, dropout=0, n_out=2)`: linear input projection, exact GELU, two-layer PyTorch reset-after GRU, and a `Linear(512,256) → GELU → Linear(256,2)` head. The raw cache is not the model input tensor until feature construction is applied.

With these commands, fit loss weights are not the cached `is_scored` mask. `main_row_weights()` returns the default validity mask because there is no propensity checkpoint, `--mask-weight`, class, since-event or other weighting flag. `valid` is `row_index >= WARMUP`, and `WARMUP=99`; thus each chunk loss uses `abs(clip(y,-2,2)) * valid` per target channel. The `is_scored` mask is retained for the fixed official evaluation export/grade and has the first 99 rows removed there. The fit/evaluation membership remains the existing fold-0 cache contract: 350 `fit_train`, 28 `fit_valid` unused, 468 fixed evaluation sequences, membership SHA `dbd9ea6d7b0b752495745ea1ebd4bd858af9305c40f0ada7de7386c5359f3acd`.

Fresh initialization runs the trainer's two-batch normalization prepass before fitting: use the same PyTorch `EpochOrderSampler` with seed `20261009`, epoch `-1`, batch size32, then compute inputs and accumulate every seventh flattened row from those first two batches. Copy per-channel mean and `std.clamp_min(1e-3)` into the model. The fit order is the same sampler at epochs0 and1; parsed-cache mode uses `drop_last=False`, so all350 sequences are used. This is part of the recipe and must be reproduced in any JAX adapter or bound as an identical initialization/normalization artifact.

The default AdamW path uses beta2 `.999`, epsilon `1e-8`, weight decay `.01`, global gradient-norm clip `1.0`, and OneCycleLR with 220 total updates, `pct_start=.05`, `final_div_factor=100`, default `div_factor=25`, and `cycle_momentum=true` (the first AdamW beta is scheduled). A TPU worker must consume the same per-step learning-rate and beta1 trace, or demonstrate an exact implementation of these defaults before the device comparison. Do not claim optimizer parity from matching only `lr`, `weight_decay` and `beta2` flags.

With350 fit sequences, batch32, no drop-last, ten 2,000-row chunks per sequence batch and two epochs, both arms perform220 update attempts. The control is weighted MSE. The treatment is weighted Huber with `delta=1.0` in clipped target units. The arm commands differ only by `--loss wmse` versus `--loss huber`; `--huber-delta 1.0` is present for both. Each arm starts from the same Torch-seeded model parameters and same normalization values for cross-device pairing. The fit saves epoch1 and the complete 468-sequence evaluation is causal with per-sequence state reset.
