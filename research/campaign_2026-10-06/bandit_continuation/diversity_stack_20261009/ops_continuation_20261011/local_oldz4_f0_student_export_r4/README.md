# Old-Z4 F0 student CP1 export handoff (R4)

This packet is a fixed-checkpoint consumer for the completed own-weight run
`oldz4_h230_student_f0_s3_r3`. It does not authorize export or grading by
itself. Root reviews the terminal fit, admits the one full-valid export with a
separate receipt, then owns execution and grading.

The fit used the exact frozen H230 trainer `09902e4b…a693bbb` and the admitted
R4 recipe: fold 0, seed 3, own `oldz4_h230_parent_f0_s3_r3@ep3` initializer,
own source-qualified family cache, two epochs with fixed epoch 1, fp16
training, and the source-qualified 1,405 fit-validation / 468 excluded-fold
membership. The exact split, recipe, source, cache metadata, propensity,
initializer and root fit admission hashes are pinned in
`STUDENT_EXPORT_CONTRACT_R4.json` and `SOURCE_BINDINGS_R4.json`. The actual CP1
hash is deliberately generated by the terminal gate after root verifies the
completed producer; it is not guessed or predeclared here.

## Checks and handoff

Run the checkpoint and export commands from the repository root after
confirming the parent limits and the current campaign aggregate. Use the
campaign's `scripts/limited` wrapper for each process; do not overlap support
jobs beyond the current aggregate budget.

1. Root runs the terminal checkpoint gate. It checks the admitted attempt,
   terminal exit, exact trainer and recipe, source-qualified memberships,
   finite CP1 model tensors, the saved optimizer state, and reconciled per-epoch
   optimizer / AMP-skip counters. The pass receipt includes the CP1 hash and
   notes that gradient finiteness is not independently reconstructed.

```sh
WNN_SLICE=wnn-campaign.slice WNN_CPU_QUOTA=50% WNN_THREADS=1 \
WNN_MEM_MAX=1200000000 WNN_RUNTIME_MAX=120s \
scripts/limited .venv/bin/python \
  research/campaign_2026-10-06/bandit_continuation/diversity_stack_20261009/ops_continuation_20261011/local_oldz4_f0_student_export_r4/validate_student_export_r4.py \
  checkpoint-gate --project-root "$PWD" \
  --receipt-out research/campaign_2026-10-06/bandit_continuation/runtime/receipts/oldz4-r4-f0-s3-student-export/CP1_TERMINAL_GATE_R4.json
```

2. Root writes `ROOT_EXPORT_ADMISSION_R4.json` only after reviewing that pass
   receipt and an actual export resource profile. The runner requires the
   admission to bind both the frozen contract hash and terminal-gate hash.
   It rejects output collisions before invoking the predictor.

3. The export runner imports the exact frozen trainer module, sets the actual
   imported module's `ROOT` to the repository root, checks the resolved valid
   data path, and verifies the imported loader budget returns zero workers and
   zero prefetch under `WNN_LOADER_WORKERS=0`. It then invokes the unchanged
   MAIN `scripts/predict_run.py` for the full valid feature set at CP1. The
   output validator checks the exact 1,873-group order from
   `valid_targets.npz`, shape `(1873, 20000, 2)`, float32 bytes, sidecar pins,
   file hash and finite values in bounded row chunks.

```sh
WNN_LOADER_WORKERS=0 WNN_SLICE=wnn-campaign.slice WNN_CPU_QUOTA=50% \
WNN_THREADS=1 WNN_MEM_MAX=1200000000 WNN_RUNTIME_MAX=600s \
scripts/limited .venv/bin/python \
  research/campaign_2026-10-06/bandit_continuation/diversity_stack_20261009/ops_continuation_20261011/local_oldz4_f0_student_export_r4/run_student_export_r4.py \
  --project-root "$PWD" \
  --checkpoint-gate research/campaign_2026-10-06/bandit_continuation/runtime/receipts/oldz4-r4-f0-s3-student-export/CP1_TERMINAL_GATE_R4.json \
  --root-admission research/campaign_2026-10-06/bandit_continuation/runtime/receipts/oldz4-r4-f0-s3-student-export/ROOT_EXPORT_ADMISSION_R4.json \
  --export-receipt research/campaign_2026-10-06/bandit_continuation/runtime/receipts/oldz4-r4-f0-s3-student-export/EXPORT_VALIDATION_R4.json
```

4. After export validation, root may invoke the frozen fold-0 scorer exactly as
   pinned in `STUDENT_EXPORT_CONTRACT_R4.json`. This is exposed fold-0
   robustness evidence; it is not a fresh holdout or public score.

`verify_cp0_one_row_r1.py` is a CPU-only feature-path producer smoke test using
the earlier same-run CP0. It reads one feature-only valid row and no labels; it
does not establish CP1 validity, full-export completion, or score quality.
R3 records the actual imported zero-worker helper result, trainer and helper
source paths/hashes, and the finite one-row output. R1 and R2 receipts remain
unchanged; any rerun must use a new receipt filename. The process `ru_maxrss`
field is a lifetime high-water value that exceeded independently measured
limited-scope peaks, so resource qualification must use the invocation's
systemd scope receipt.
