# Recent CPU sources and transfer to the WNN endpoint

Read 2026-10-12 Kyiv. Sources were discovered through recent forum discussions, then checked against the original developer reports, code and documentation. These are mechanism leads, not claimed speedups of our submission. No external competition teammate code or weights enter production.

| Primary source | Actual finding | Transfer decision |
|---|---|---|
| [llama.cpp Q8/Q4 repack, October 6 2026](https://github.com/ggml-org/llama.cpp/pull/30036) | VNNI-specific byte layouts greatly improve large-batch prefill in the author's tests; Zen5 decode remains about unchanged. | Our online batch1 GRU already uses VNNI-specific packing. Do not claim its prefill gain for our endpoint. Inspect layout/cache and whole-row cost. |
| [Q4 VNNI+VBMI, September 24 2026](https://github.com/ggml-org/llama.cpp/pull/29397) | GEMM arithmetic/staging improves; GEMV is unchanged and reported decode is unchanged. | More aggressive Q4 packing is not automatically a batch1 benefit. Current Q4-rounded weights still use Q8 computation and lose accuracy; genuine packed INT4 is a separate unrun arm. |
| [Q5/Q6 VNNI, August 23 2026](https://github.com/ggml-org/llama.cpp/pull/27590) | Two independent blocks share a ZMM. Faster inner dots did not measurably change the author's decode result. | Q5/Q6 need a native decode kernel and end-to-end evidence. A smaller bit width is not a corresponding speed increase. |
| [Batch1 attention/alignment, August 21 2026](https://github.com/ggml-org/llama.cpp/pull/27478) | Reuses query loads, changes block scheduling and optionally advises huge pages. It reports shape/layout-dependent regressions too. | Consider loop fusion and exact operand reuse. Its attention/KV algorithm is not our recurrent cell; small already-aligned matrices do not automatically benefit from huge-page policy. No system/host tuning is authorized or needed. |
| [Q2 VNNI, July 30 2026](https://github.com/ggml-org/llama.cpp/pull/26348) | A missing integer dot path was replaced by VNNI. Whole-model numerical drift remained until floating-point contraction was disabled. | We already have VNNI. Preserve integer overflow bounds and the floating epilogue's order; a kernel-local equality check is insufficient for whole recurrent trajectories. |
| [Q4 repack, May 19 2026](https://github.com/ggml-org/llama.cpp/pull/23309) | An optimized packed GEMV handles corrections/aliasing; the author revised an inflated speedup after detecting baseline noise. | Use alternating controls, actual shipped weights, complete sequences and resets. Avoid selecting from one favorable timing run. |
| [AMD small-matrix optimization, August 12 2025](https://www.amd.com/en/developer/resources/technical-articles/2025/aocl-blas-boosting-gemm-performance-for-small-matrices-.html) | Packing/dispatch overhead can dominate skinny matrices. The article considers internal microtile loops, independent accumulators and masked edges. Measurements use EPYC9755, not our9224. | Our fixed packed GEMV already avoids per-row weight packing and uses eight independent integer accumulators. Investigate actual remaining boundary/call overhead rather than rebranding existing optimizations as new. |
| [Small INT8 CPU models, August 18 2026](https://arxiv.org/html/2608.18182v1) | Graph fusion, scale/bias lowering and shape-aware kernel choice matter alongside quantization; static/dynamic calibration differs. BERT/Xeon/AMX results are not a GRU/Zen4 benchmark. | Audit separate passes and affine folding. Static scales or SmoothQuant change the quantized endpoint and require held-out-quality checks. No AMX path for the supplied EPYC. |
| [Rust PGO documentation](https://doc.rust-lang.org/rustc/profile-guided-optimization.html) | Representative execution profiles guide inlining/layout/register decisions. Profile generation/use must keep compilation settings consistent. | The bounded own PGO experiment uses the actual callback. Check shipped ABI, required GLIBC versions and prediction equality before release. |
| [LLVM machine-code analyzer](https://llvm.org/docs/CommandGuide/llvm-mca.html) | Scheduling models estimate instruction/resource behavior, with modeling assumptions. | Useful to challenge a loop schedule; not a replacement for an actual EPYC9224 timing. Rust's installed LLVM objdump/profdata are available; standalone llvm-mca/perf were absent. |

Forum discovery included [the late-August CPU PR discussion](https://www.reddit.com/r/LocalLLaMA/comments/1w1uu6d/llamacpp_open_prs_list_cpuramdiskhybrid_related/) and developer conversations above. Speculative aggregated forum forecasts were not used as measured evidence.

The official AMD57647 archive endpoint failed both web retrieval and bounded curl with an HTTP/2 stream error; no guide was claimed downloaded. AMD's [EPYC9004 toolchain tuning guide](https://www.amd.com/content/dam/amd/en/documents/epyc-technical-docs/tuning-guides/58020-epyc-9004-tg-high-perf-toolchain.pdf) and [target-selection documentation](https://docs.amd.com/r/en-US/57222-AOCC-user-guide/Target-Selection) establish architecture-specific compiler options. We will not assume an Intel `target-cpu=native` artifact is suitable for the scorer.

Immediate prioritization: profile actual callback stages; verify algebraic identity of potential shared subgraphs; test a bounded exact tile/fusion schedule; measure compiler improvements with paired controls; compare the complete endpoint. Low-rank factors, new students, packed Q4–Q7 and static quantization remain explicit quality/cost tradeoffs, not exact rewrites.
