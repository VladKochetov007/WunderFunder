## Profile-only implementation and source/path contract

The pinned parser accepts `--device cuda` or `--device cpu`; `--device cuda:0` is invalid. `profile_kernel.py` sets `CUDA_VISIBLE_DEVICES=0` and two-thread/zero-loader-worker limits before importing Torch; the trainer receives `--device cuda`. The trainer has no `--data-root` or `--output-root`, so the worker extracts the exact v5 archive to `/kaggle/working/e520_source`, discovers input mounts by content identity, and symlinks `datasets/`, `cache/`, the fold manifest and portable registry at their expected paths. `--name` writes only under `artifacts/runs/e520_profile_s3_f0/`.

The worker first validates a controller-issued external review receipt and all bound code/source hashes. Its fixed trainer call uses seed 3 and `--profile-warmup 3 --profile-steps 20`; the pinned trainer returns from profile mode before its checkpoint branch. The worker then refuses any `.pt`, `.npy`, or prediction artifact in that run directory. It retains the 20 timed batch spans and loader waits, reports p50/p90 separately, captures CUDA allocator peaks at the trainer report hook before its early return, actual process VRAM from `nvidia-smi`, RSS high-water, host/cgroup headroom, free disk and wall time. A missing process PID measurement is `unavailable` and aborts whenever CUDA is active; only explicit pre-CUDA idle may lack that measurement. The end-to-end throughput summary is based on the 19 inter-start intervals available from 20 timed starts; host spans and loader waits are reported separately and never added.

After the training profile, an exporter-shape probe reads only the first 4,000 raw feature rows from each of 16 actual target-order row groups, one parquet row group at a time. It applies the pinned trainer's `build_inputs` and `forward_chunk` path to a `16 × 4,000` chunk and fails unless raw/model inputs are float32 and actual output is finite float32 with exact shape `16 × 4,000 × 2`; it also measures allocator/RSS peaks. It does not concatenate full-sequence predictions, write prediction files, or retain a full prediction array. `e520_profile/environment.json` records the selected GPU name, total memory, compute capability, Torch/CUDA/cuDNN/Python versions and `nvidia-smi` identity; hardware identity is observed and is not hardcoded to a T4. `e520_profile/training_profile_peak.json` durably captures allocated/reserved allocator peaks before profile early return. `export_guards.py` contains synthetic-testable preconditions for the later streamed/memmapped fit exporter; it is not an exporter and is not called to score data.

Use `prepare_profile_packet.py --review-targets-only` to calculate the review hash map without producing a packet. A later packet build must receive an independently published review receipt path **and exact receipt SHA-256**; its reviewer must have role `independent-controller`, differ from the actor, and approve the exact worker, kernel, builder, plan and pinned archive hashes for `profile-only` scope. The builder only creates a private Kaggle script directory and metadata; it has no push/submit command. The current code has not received this review, so no packet build command is authorized.
