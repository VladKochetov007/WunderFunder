# E424 preregistration: prefix specialists and prefix-conditioned adapters

Execution resource correction after admission preflight: see
[`E424_RESOURCE_AMENDMENT.md`](E424_RESOURCE_AMENDMENT.md). The operative
specifications use a24-GiB host cap; the original30-GiB draft was rejected
before any worker was admitted.

## Question

Can causal information in the first99 normalized input rows help the recurrent representation specialize by local activity/regime? Test H093's learned prefix router and H094's rank8 conditional adapter end-to-end against each architecture's parameter-matched GRU control under the original combined training objective.

## Fixed arms and order

Eight independent seed3, four-epoch fits, all fixed to epoch3. Order is H093 learned, GRU96×2 control, H094 conditional, GRU128×2 control, then H093 hash and universal controls, then H094 unconditional and diagonal controls. Every arm uses the original train+valid recipe: Muon, chunk1000, stopped bootstrap8, alpha0.5, since-weight32, EMA0.999, propensity2/0.03, structural0.3, next-change0.3, batch32, seed3 and fixed epoch3. Structural/next objectives give23 outputs. The model itself uses only causal inputs. Holdout was excluded from fitting and is used only for the fixed evaluation.

H093 learned/hash/universal each have154,343 trainable parameters; its ordinary GRU control has152,855. H094 conditional/unconditional/diagonal each have265,755; its GRU control has261,143. The main paired contrasts are learned vs GRU96 and conditional vs GRU128; other route/mode arms are prespecified controls. Every candidate is also compared descriptively with the previous fold0 combo predictor.

## Decision reporting

Report Global WP and per-class results, all paired component-bootstrap intervals (2000 draws), exact fit/evaluation identities, route frequencies and actual scored/unscored sequence counts. A useful lead requires a positive paired interval against its matched control, with no class3 degradation worse than0.002. Intervals crossing zero stay uncertain and motivate a fresh component split/seed rather than a veto. Holdout is campaign-exposed, so no public-score or untouched-test claim follows.

## Resources and stop rule

Sequential local GPU worker only:8CPU,30GiB host cap inside the36GiB campaign slice,4.2GB VRAM allocator and4.8GB monitored stop on a6GiB RTX3060. One fit at a time; the parent retains4GiB support reserve. Each sealed job has a60-minute timeout. Stop launching arms by19:10 Kyiv to allow the latest fit/prediction/score to finish before20:00. Preserve interrupted jobs, never relaunch under the same run identity. Resource headroom takes priority over finishing all eight.
