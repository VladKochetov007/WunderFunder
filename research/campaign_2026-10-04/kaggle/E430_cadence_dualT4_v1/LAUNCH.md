# E430 cadence on dual T4: source-only package draft

This directory contains a portable remote runner and sealed-shape job specs for the three E430 cadence arms. It has not been uploaded, admitted, or run. The fold-0 external mounts reuse the mapping and immutable asset dataset from E419; no fold-1 W384 assets are referenced.

The package keeps the experiment fixed at fold 0, seed 3, H=256, two GRU layers, batch 32, four epochs, fixed epoch 3, and the E430 objective/teachers/optimizer. Only the three preregistered cadence topologies differ. The probe names are fresh and separate from the fit names. Each probe runs one batch in each of four epochs; none can be promoted. All probes must return zero and export every declared artifact before any full fit begins. Then `chunk1000` and `chunk2000_connected` run on the two distinct T4 UUIDs, and `accum2000_trunc1000` runs only after both complete. The runner binds each fit to the UUID used by its corresponding probe. It checks full-fit cardinality: 373 complete batches per epoch, four epochs, 20 attempts per batch for `chunk1000`, and 10 for each 2,000-row arm; successful updates plus AMP skips must equal attempts, with EMA advances reconciled separately. It checks that only fixed epoch 3 was selected and that all checkpoints, histories, provenance, training state, and exact step reports exist.

Resource limits are remote-only: 11 GiB PyTorch allocator target, 12 GiB observed operating target, 13 GiB sampled stop, 10 GiB RSS per worker, and eight CPUs per worker. The local 4.2 GB allocator / 4.8 GB stop is unchanged and does not constrain this remote bundle. Each probe has a 20-minute worker timeout; each full-fit worker has a provisional 3.5-hour bound. These are experiment/job bounds, not a claim that admission has occurred.

The worst-case sequence is about 7 h 40 min of pair/solo probe and fit stages. Since Kaggle allocates both T4s for a solo stage too, this is about 15.34 allocated GPU-hours before overhead, counting the idle companion GPU. The plan adds one hour for startup and repeated source/input verification, for about 17.34 allocated GPU-hours, then requires the campaign's separate 6 GPU-hour reserve (rough quota gate: 23.34 GPU-hours). Admission is still contingent on W384 completion and a fresh quota check.

The remote output path in every `kaggle_sequence` plan exactly matches the artifact path in its spec, including `reports/<worker>_steps.json`; this avoids the W384-v2 `/plans/` versus report-root mismatch. `bundle/source_inventory.json` records source/archive identities, exact external input mapping, run identities, counts, and the conservative device-hour model. The bundle builder is standard-library-only and copies/hashes source files and metadata; it does not load training arrays or checkpoints.
