# E427 / H-108 implementation proposal — awaiting scope approval

This is a source-design proposal only. No H108 implementation, fit, or score was started. The original registered question is whether causal endpoint-relative volume history can modulate recurrent update strength, with aligned, previous-cycle-stale, and same-parameter zero-modulation arms. The independent critic added the requirement that the stale fallback be the TRAIN-fit mean, that the endpoint window be recorded before fitting, and that the exposed panel remain exploratory.

## Proposed state-gate mechanism

Use the frozen E424 seed-3 combo checkpoint `c20261004_combo_s3_final_r1/model_ep3.pt` as the common initialization and preserve its 112 raw input channels, input projection, 256-wide, two-layer GRU, and 23-output auxiliary head. Add a separate `volume_gate` architecture overlay in `staging/e427`; do not change the root trainer or model. At each row, construct the existing causal 28-channel `volume28` vector from raw inputs only: current 22 volume offsets and the six within-cycle path/change/net summaries. Apply a shared rank-8 projection to this vector, then append its eight coordinates to the encoded input of the **first GRU layer only**. Expand that layer's input matrix with zero-initialized columns whose only active learned block is the update-gate (`z`) rows; keep the reset and candidate columns for those eight coordinates fixed at zero. This represents an additive low-rank term in the first layer's `z` logits while preserving the original PyTorch GRU gate equations and fused sequence kernel. With the added `z` matrix initialized to zero, all three arms begin with exactly the parent predictor's recurrent output. Parameter layouts remain common across the three arms; the code must report the exact added/effective trainable counts.

The aligned arm supplies the per-row `volume28` vector using observations through the current row. The stale arm supplies the terminal `volume28` vector from the immediately preceding completed endpoint cycle and holds it constant until another endpoint starts a new cycle. Define cycles using the existing `ENDPOINT` equality at raw channel 110: the marker row starts the new cycle and the preceding row is the previous cycle's terminal observation. Before two endpoint markers have appeared, use the fixed train-fit feature mean. The no-op arm runs the same gate module and carries the same parameter tensors, but forces the projected context contribution to zero. It is a capacity/no-op control, not a learned placebo. These definitions use no targets or future rows.

To keep the recurrent path fused, the isolated model would consume a 28-channel causal gate side stream computed for each full input sequence before TBPTT slicing. The model uses the original 112 channels for normalization and encoding and keeps the added context separate until the first GRU input. A stored, content-bound gate fallback mean is calculated by streaming raw `x` from the exact fit membership (TRAIN plus the 1,505 fit-VALID groups; never the 368 excluded groups) without reading labels. Record its value, fit membership identity, input-cache hashes, and deterministic endpoint-window sample before optimization. Proposed sample rule: independently sort eligible TRAIN and fit-VALID row groups by `SHA256("E427-window-v1:<split>:<row_group>")`, take the first 32 from each split, and save the first four endpoint indices per sequence plus raw-volume rows from `[endpoint-8, endpoint+8]` (clipped to the sequence), with sequence IDs and source/cache hashes. The stale side stream is defined by a causal prefix scan: at row `t`, find the latest endpoint at or before `t`; only after at least two endpoints may it read the preceding row's volume summary. Tests must prove a changed future suffix cannot alter any earlier gate vector.

## Proposed fit and score controls

All three arms use one immutable data/teacher/source closure, seed, sequence order, checkpoint policy, optimizer schedule, original combo targets and losses (`--aux-struct 0.3 --aux-next 0.3`, including the same distill, propensity, SBD-8 and EMA settings), and exact fit/evaluation memberships. The intended reference is the E424 seed-3 combo provenance: `ab67_final_since_s3,ab67_final_since_s4`, distill alpha 0.5, bootstrap horizon 8, `prop_v1` with power 2 / epsilon 0.03 / true-mask epsilon 0.03, since-weight 32 / floor 0.25, EMA teacher 1 with decay 0.999 and eval-EMA, Muon scope `rnn`, batch 32, chunk 1000, seed 3, TRAIN plus all 1,505 fit-VALID groups, with the 368 excluded groups held out. The fixed endpoint is epoch 3. The score uses the frozen paired component scorer on the historically excluded panel, with the preregistered `aligned − stale` and `aligned − no-op` contrasts, 95% paired component intervals, and the −0.002 per-class harm guard. Intervals crossing zero are inconclusive; no score-based selection occurs.

Before any fit, CPU-only synthetic tests should check zero-gate equality against a parent-width PyTorch GRU, exact parent tensor transfer, z-only gradient support, causal prefix/cycle-boundary behavior, endpoint reset semantics, fallback use before a complete prior cycle, full-versus-chunk parity, sequence reset, and output/auxiliary shape. Then a resource-bounded real-input throughput smoke must exercise the custom feature path and one full-length batch; stop if it exceeds the admitted time/memory limits or is materially slower than the fused parent. Only after correctness and resource checks pass would root seal three sequential single-GPU fits under the existing 24-GiB RAM, 4.2-GB allocator, and 4.8-GB stop limits.

## Open choices requiring root approval

The registry and follow-up note do not specify which GRU layer receives the gate, the low-rank dimension, or whether the three fits start from the E424 epoch-3 model or repeat its four-epoch recipe from a fresh common initialization. This proposal recommends a rank-8 gate on the first layer and a common continuation from the fixed E424 epoch-3 checkpoint; choosing one versus four continuation epochs changes the scientific claim and cost. One epoch tests adaptation on the strong trained representation, while four epochs tests longer co-adaptation. These are new recipe choices and should not be silently inferred. Root should choose the intended initialization/schedule before implementation.
