# E464 durable queue staging

`checks/run_e464_sequence.py` is a source-only queue controller draft. It waits for the exact E425 service handle to become inactive with exit 0, requires `checks/e425_sequence_v1.json` to say `fits_and_exports_complete`, and independently verifies the three E425 fit/export attempts and teardown records.

The controller requires root-sealed identities for all eight existing E464 fit execution drafts. It never changes or seals those drafts. It runs each unique fit attempt sequentially and refuses a changed spec, failed attempt, stale/disappeared service handle, pause marker, or blind retry. After all eight jobs succeed, it rechecks every fixed-epoch-0 audit and checkpoint identity together before sealing any export. `scripts/build_queue_specs.py` converts the rich review designs into separate exact-schema, path-only runtime drafts under `execution_specs/`; these contain the current source paths and future checkpoint/audit input paths. The controller seals those runtime drafts only after the actual audited checkpoints exist. Each prediction sidecar is checked for the right child and parent, fixed epoch 0, FP32, matching model/audit hashes, 23 model outputs, two exported values, and the exact ordered integer domain `0..1872`. Runner terminal artifact descriptors are rechecked against current file sizes and SHA-256 hashes before any audit or sidecar is trusted. The all-16 paired score is sealed and launched only after all eight exports pass.

The head-fit recipe is 1,505 unique fitting groups, batch 16 with drop-last (94 batches), ten 2,000-row updates per 20,000-row sequence (940 optimizer attempts). The queue requires fixed epoch-0 audit counters to reconcile and every non-head parameter/buffer and head layout to pass the wrapper audit.

Every GPU attempt retains its sealed worker timeout. Before reserving a new GPU job, the controller requires cumulative terminal E464 GPU charges plus that next job's full sealed timeout to fit within the preregistered three-hour reserve. The limits are never raised. Root must still reconcile the unchanged per-job timeout envelope with cumulative campaign budget before starting the controller. No retry is automatic: an interrupted live attempt may be observed by explicit resume only if its exact runner identity and systemd handle remain live; stopped controller snapshots, failed jobs, and disappeared handles require review.

The controller service has a 12-hour startup deadline, 25% CPU, and 512 MiB RAM. A separate CPU-only draft under `execution_specs/e464_queue_source_checks_v1.draft.json` runs eleven stdlib fixtures for absent predecessor handling, rich-schema rejection, path-only manifests, exact row-group typing/order, full next-timeout budget admission, and artifact-record coverage/hash drift. Root review, E425 completion, eight sealed fit identities, current campaign authorization, no pause/orphan condition, and budget reconciliation are still required before admission. Nothing from this staging package has been sealed or launched.
