# Scalar input embeddings: independent novelty and cost critique

2026-10-01. Read-only scout requested by root while allocated Q3 OOF producers run. No new data, targets, diagnostic, fit, quality query, or implementation. All cited internal outcomes were already exposed. This is not an allocation or frozen experiment specification.

**Decision: worth a short independent proposal, with a low-to-moderate prior; not enough evidence to allocate another architecture run automatically.** The operator is distinct from the recorded encoder negatives. The credible claim is easier optimization of a particular scalar representation before mixing, not new information, physical price decoding, or a demonstrated missing nonlinearity in the current GRU. I would keep it behind delivery and the already allocated Q3/CTX work. There is no evidence here supporting a promised large gain.

## What the primary paper licenses

Gorishniy, Rubachev and Babenko construct numerical embeddings independently for each feature before mixing. Their quantile PLE uses training-set quantiles, removes zero-width bins, and linearly extrapolates beyond endpoint bins. A following linear map is a sum of bin embeddings. Their benchmark concerns conventional tabular tasks and is explicitly biased toward problems favorable to boosted trees; it does not establish a benefit for this recurrent competition. [Primary paper, sections3.2 and4](https://arxiv.org/html/2203.05556v4).

The useful concrete operator is a continuous piecewise-linear scalar map. A learned linear combination of the cumulative PLE basis can be precomputed at knots, making serving a binary interval search and interpolation of two vectors. This avoids a full expanded feature vector. Keeping the original raw linear path makes the branch a residual representation rather than a lossy discretization.

## Root's restricted 44-coordinate version is computationally plausible

Illustration only:44 raw price-code coordinates (`0:22`, `52:74`),16 knots, rank16, final rank16→128 map, residual before the existing input GELU. These numbers are root's feasibility example, not a selected configuration. “16 knots” must later be distinguished from16 intervals/17 knots.

With16 knot vectors, the table has44×16×16=11,264 values; projection adds2,048. Combined FP32 weights are53,248bytes (52KiB), or26KiB in FP16; the table alone is22KiB in FP16. Add2.75KiB of FP32 knots, biases if used, alignment and interpolation metadata. FP16 table storage is a numerical decision requiring parity/quality treatment, not free exact compression.

After knot precomputation, the extra work per row is about44 interval searches,704 vector interpolations,704 summation additions,2,048 projection MACs and128 residual additions. Searches involve data-dependent accesses; extrapolation and duplicate knots need specified behavior. This is small beside the backbone's arithmetic, but does **not** substantiate a1–2µs timing promise. Native code currently serves the plain linear encoder, so a new serving implementation and complete-callback measurement are required. The fixed3 baseline has roughly5.5min margin to50min on the measured host; three changed members consume that margin cumulatively.

GPU training must avoid the `(batch,time,44,16)` float tensor: at16×2000 it is22.528million elements, about43MiB FP16 or86MiB FP32 **per materialized activation**, before saved tensors and gradients. A fused two-neighbor weighted embedding sum can reduce this substantially. Indices, weights, saved activations and framework kernels still need a measured peak; an index-count estimate is not an8GiB/5.5GiB memory proof. Backpropagating an input adapter through a frozen GRU still requires its input gradients; it is not as cheap as the existing frozen-backbone head fits.

## The main unresolved experimental issue is the control

A same-parent continuation with the original encoder is necessary to separate the new branch from additional training. For the competition's utility question, that paired ordinary-training baseline is a valid efficacy comparator: identical source parent, data order, RNG and updates, with the new branch as the intervention. A positive result would establish the package of capacity, representation and optimizer effects, rather than uniquely attributing the gain to PLE geometry. No third arm is necessary for that narrower, useful claim.

If mechanism attribution is desired later, a low-rank **linear** residual control with the same initialization and optimizer isolates nonlinear function class from linear reparameterization, but cannot honestly match effective capacity merely by allocating redundant table parameters. A comparable-parameter smooth nonlinear encoder control would address capacity, at the price of a third arm. These are optional research controls; inventing a redundant pseudo-linear table solely to match parameter count may itself change optimization. Even the paper finds benefits from a redundant linear embedding, so this attribution limit is material.

One practical future proposal could compare a scalar PLE branch with an equally sized scalar smooth-basis branch using the same trainable coefficient tensor, low-rank output projection, raw skip and training recipe; that would test localized piecewise structure versus generic extra scalar nonlinearity. It would not test “nonlinearity versus linear,” and serving costs must be reported independently. I do not select that experiment here.

Any continuation must preserve source-parent identity, data ordering and RNG, use a separate RNG for new parameters, and zero only the final residual projection so initial predictions match while gradients can learn. Quantile knots must use eligible training chains only, with repeated quantiles collapsed; no held-fold distribution fitting, target-aware split search, hidden masks, or per-sequence future normalization. Extrapolation versus clipping must be frozen prospectively. Parent drift, extra optimization and native numerical changes cannot all be charged to the embedding.

**Recommendation:** permit an independent written proposal if the root wants one, but do not treat a cheap theoretical serving path or the tabular paper as sufficient grounds to spend the remaining fit budget. For utility, use the ordinary same-RNG/update/data continuation anchor and explicitly limit the causal claim; do not require optional mechanism controls. Account for backbone-gradient memory, two-fold/paired-seed fits, final head adaptation and native parity. A stronger mechanism-specific prior has not been established by this read-only scout.
