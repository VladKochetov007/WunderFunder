# Baseline3 fallback ISA runtime supplement — preparation only

Root must supply a hash-bound allocation after the full-valid audit has ended and explicitly released CPU18/58. The allocation binds that audit's final launch receipt and this plan. The exact argv template is in plan.json; root preserves command, UTC start/end, and return status for each outer launch. Each independent scorer process gets one CPU18, 100% cgroup CPU quota, 4GiB memory, no swap, compute libraries set to one thread, and an external TERM at178s/KILL after2s. Total maximum for the two traces is360s. No retry, including noise, assertion failure or timeout.

Each fresh CP311 process extracts the exact9471821e ZIP, forces its existing ISA selector only while importing solution, then invokes its actual PredictionModel.predict for five complete20k-row sequences from the already-frozen raw-only fixture. No target, scoring mask, WP report or training code is loaded. This is descriptive fallback coverage, not an experiment or a delivery-artifact change.

Full fixture hashes and finite checks before timing warm inputs; this is not a cold-read test.
