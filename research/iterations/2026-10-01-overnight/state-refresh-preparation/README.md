## Exact source and hypothesis

The reference is `training/train_aux.py` inside the overnight directory, SHA256 `f13e61b4d43f011c132f6b7f88df3f62775d0a43189776437c42cc484ac0f39f`. Its incoming student state is `h` immediately before lines949–951; line950 overwrites it with the current chunk's outgoing state, and line951 detaches it. AdamW/scaler/scheduler then run at1083–1085. EMA is updated afterward at1093–1094. Source hashes and exact frozen ordinary-parent argument lineage are in `plan.json`.

Let `u_b` be a detached copy of the *incoming* state, `X_b` the already constructed causal input chunk, and `F` the student's recurrence. The current carry is `s_b=F(theta_b,X_b,u_b)`, used after the optimizer changes parameters to `theta_(b+1)`. The candidate carry is `r_b=stopgrad(F(theta_(b+1),X_b,u_b))`. This reuses the incoming state from before the first forward—not `s_b`, which would process the same chunk twice. It preserves resets (`u_b=None` at sequence start) and chunk2000. It does not reconstruct earlier history: `u_b` itself may be stale. A full-prefix reference instead starts at `None` and replays rows0 through the current boundary under the single current parameter snapshot.

There is no inference change and no new state dimension. This differs from SAM's perturbed-weight loss, previous inference resets, chunk-length tests, and the closed CTX additional-memory features. R2D2 motivates checking staleness but concerns replay-based reinforcement learning; this supervised, one-update-lag situation is different. [Primary R2D2 paper](https://openreview.net/references/pdf?id=Hy7PKCFCQ).

## Update contract and prototype limits

Before the original forward, save `u_b=detached_copy(h)`. Preserve the original loss, one backward, unscale/clip, AdamW, scaler, scheduler, step counter and EMA calls. After those calls, a successful student update permits one no-gradient same-chunk replay in the original training mode and same AMP dtype. The candidate retains its detached state; the eventual matched control performs the same replay and discards it. The EMA teacher's forward/state and update schedule remain exactly as before. In particular, the reference trainer calls scheduler and EMA updates even when GradScaler skips the student update; this proposal does not silently correct that behavior. On a skipped student step, carry `s_b` and do not replay in either arm.

The helper accepts an explicit `update_applied` boolean and has no optimizer/scaler/EMA/loss reference. For a future default GradScaler adapter, compare its scale before `step/update` and afterward: a decrease signals an overflow skip under the declared default backoff policy. Equal or increased scale indicates no such skip. This must be verified with the exact fused AdamW/AMP wrapper, finite and injected-overflow cases, before any pilot; an optimizer post-hook alone is insufficient as proof of a parameter update. Do not use the optimizer's return value (`None` is ordinary). Scale observations may synchronize the GPU; include their cost in both arms and the480s diagnostic cap. The current prototype does **not** validate CUDA or fused update detection. [Official PyTorch AMP documentation](https://docs.pytorch.org/docs/2.14/amp.html).

`refresh.py` uses `no_grad`, cloned detached incoming/outgoing states, an explicit autocast context factory, and RNG isolation. It rejects stochastic or buffer-mutating replay and restores buffers/RNG on normal return or exception. It does not switch to eval mode. The intended architecture has dropout0 and fixed normalization buffers; dropout, training BatchNorm, parameter-writing forwards, new buffers, hooks with external side effects, compiled CUDA graphs and arbitrary state objects are unsupported. Source review must exclude such effects; the helper is not a general transaction around any module. Registry replacement/addition/deletion is rejected and the original registered-buffer references are restored. Unchanged buffers are not copied and retain their version counters; detected value mutation is restored but may increment a counter, so any such mutation aborts and no retained graph may depend on rollback. Buffer shape/metadata mutation and dynamically added modules remain unsupported. Replay belongs after the original backward. Tiny CPU tests prove the limited generated contract, not original-GRU CUDA determinism or AMP bit parity.

## One prospective diagnostic fit

The future pilot is one **counted ordinary-parent diagnostic training run**, seed3, at most256 optimizer attempts and480s total process wall. It is not a two-arm quality experiment. Student training always keeps its ordinary stale carry; refreshed/full-prefix states are temporary probes and never enter the continuing training trajectory. This prevents probe choice from changing later data/gradient history.

Reuse the exact256 distinct train-only chain/row-group records from `renewal/selected-chains.json` and its existing metadata-only purity receipt; no new chain, class or outcome selection. `plan.json` copies their ordered IDs and binds both prior hashes. Each pass deterministically shuffles these256 row groups using a dedicated CPU generator seeded `3+pass_index`, batch32, with10 consecutive chunk2000 attempts per batch. Normalization uses the first two seed3 batches, raw inputs only, and does not consume the training sampler's generator. Four passes supply at least256 attempts; stop immediately at256. This restricted, class-stratified train-only subset is a deliberate diagnostic distribution, not a claim of full-parent data-order parity.

Architecture, losses and optimizer conventions follow the bound ordinary H128 parent:2 layers, dropout0, auxiliary structure/next coefficients0.3, original propensity/age weighting and EMA-teacher coefficient1.0, AdamW lr1e-3/wd0.01, FP16 and norm clipping1.0. The historical `prop_f0` checkpoint hash is bound as an input; loading it is future-only. No student checkpoint initialization. Use a separately declared fixed OneCycle total15000 attempts, pct_start0.05/final_div_factor100, and the source defaults for other scheduler values. This avoids compressing the entire schedule into the small subset's320 possible attempts. It is a fixed diagnostic schedule, **not** an assertion that every historical fold had exactly15000 attempts. The first256 attempts sample early training only; a negative diagnostic cannot exclude late-training staleness. No validation loader, validation targets, output cache or score is opened.

The16 probe attempts are exactly `1+16*j`, `j=0..15`:1,17,…,241. None is the tenth chunk of a batch, so every boundary has the next128 input rows available within its sequence. At each probe, use the first two output channels from three next128-row forwards under identical post-update student weights: stale carry, local-refresh carry, and full-prefix carry. Compute the full-prefix state with the **same2000-row chunk boundaries**, not a differently sized monolithic GRU call. All three continuation predictions are discarded. Earlier prefix and next128 inputs come from the already built input tensor; they cannot affect the training loss or carried state. No target or prediction mask enters these comparisons. After a skipped probe update, retain its designated slot as a failed half-reduction test; never replace it with a favorable later probe. Missing/nonfinite/incomplete16 probes cannot pass.

For each probe, let `scale=max(RMS(reference),1e-3)` across batch,time,and2 targets, with float64 reductions. Define `e_stale=RMS(stale-reference)/scale` and `e_refresh=RMS(refresh-reference)/scale`. The fixed spending gate is **median(e_stale)>=0.01 AND e_refresh<=0.5*e_stale in at least12/16 probes**, requiring `e_stale>0` for a half-reduction success. Report all16 values and skip flags, including zeros. No floor, threshold, output horizon, rank, probe timing, seed or subset sweep is permitted. Passing indicates a potentially meaningful representation mismatch; it does not establish lower forecast error or warrant automatic fitting.
