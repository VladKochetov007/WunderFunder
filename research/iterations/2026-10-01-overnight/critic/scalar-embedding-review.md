# Independent scalar-embedding feasibility critique

Scope: read-only paper/source/history review. No input arrays, targets, predictions, nuisance fit, forecasting fit or metric query. This is not an execution allocation or a frozen proposal. CTX training review retains priority.

The proposed residual scalar spline before the first cross-feature projection is distinct enough to justify a written proposal, with a low prior of useful gain. E-168 tested a learned MLP after the existing 211-to-hidden projection and GELU; its +.0011 ± .0014 on one fold and a two-epoch recipe is weak, correlated evidence rather than a confirmed win or a direct refutation. E-181 refuted a temporal convolution on the stronger EMA recipe. E-106's symbolic partial-dependence agreement is evidence that the GRU already exploits many easy main effects, but neither partial dependence nor E-100/101's overlap proves sufficiency of the current scalar representation. The source/history search found no executed per-input quantile spline; that is a bounded novelty claim.

The [primary numerical-embedding paper](https://arxiv.org/html/2203.05556v4), sections 3.1–3.2, supports featurewise embeddings, training-quantile boundaries, removal of zero-width bins, and endpoint extrapolation. Its tabular benchmark results are not evidence of recurrent forecasting improvement. A free knot-value interpolation plus a low-rank output map should be described as a constrained residual scalar spline, not necessarily the paper's exact model. A shared rank-16 bottleneck restricts all 44 scalar maps to one output subspace; it does not recover arbitrary feature interactions before the downstream GELU/GRU.

For the competition utility question, an ordinary same-parent continuation with exactly matched examples, order, seeds, steps, optimizer, losses, EMA and checkpoint rule is a sufficient primary efficacy control. The result would identify the entire added representation/parameterization intervention, not establish that local knots rather than capacity or optimization caused the gain. A redundant pseudo-linear table is not needed. If previously completed SAM-control or ordinary runs are proposed as reusable controls, exact recipe equivalence must be shown before outcomes, including initialization RNG and evaluation-loader seed consumption; shared architecture or parent names alone are insufficient.

The minimum specification must settle these issues before any empirical preparation:

1. Choose one coordinate list, rank, knot count, knot-fitting population/weights and extrapolation policy. Distinguish 16 knots from 16 intervals. Quantiles must use only eligible training chains, fixed sampling, no held-fold distribution, targets or masks. Constant features and duplicate quantiles need an explicit lower-dimensional fallback; near-equal knots after float32 conversion need strictly positive denominators. Serialize the final deployment knots and dtype bytes.
2. Define raw versus normalized spline coordinates, nonfinite/sanitized input behavior, endpoint tie convention and out-of-range behavior. Preserve the raw linear path. The spline is a nonlinear numeric representation of opaque codes, not a proven reconstruction of physical prices. Apparent numeric adjacency may have no useful semantics.
3. Construct the original model first; use a forked/independent RNG for new parameters and restore global RNG. Initialize the knot table nonzero and only the final residual projection to zero. Initial predictions and existing-parameter gradients should match the ordinary control; zeroing both matrices would create a dead branch. The table can receive its first useful gradient only after the output projection moves.
4. Keep the actual recurrent input-gradient path. Updating an adapter before a frozen GRU still requires autograd through that GRU; the frozen-head CTX `no_grad` path cannot be reused. Frozen parameter equality alone does not prove the adapter learned. Test nonzero finite table/projection updates, input-gradient propagation, chunk/state behavior and AMP/fused-AdamW semantics on generated tensors before resource allocation.
5. Freeze dtype and arithmetic at export. Collapsing cumulative PLE coefficients into knot values, interpolation, summing 44 vectors and projecting a shared rank are algebraically equivalent alternatives with different floating rounding. FP16 tables or reordering sums are numerical changes to test, not free compression. Native scalar/AVX2/v3 correctness, causal prefix/reset behavior and actual package dispatch need a serving contract before fits.

For the illustrative 44 × 16 × 16 table plus 16 × 128 output map, the new coefficients occupy 53,248 FP32 bytes, plus knots/metadata. Each row adds 44 searches, about 704 interpolation components, their sum and 2,048 projection MACs. Cache locality and branching make FLOP counts a poor runtime proof. A materialized 16 × 2000 × 44 × 16 training activation alone is about 86 MiB FP32, before autograd and recurrent workspace; several such tensors are plausible. These estimates justify a bounded native prototype and generated-tensor memory/step benchmark, not an inference or GPU-capacity promise.

A prospective test should first fix the deployed composition and require measured complete-callback cost to fit the existing 50-minute delivery gate; then use matched controls on both exposed folds and paired seeds, with fixed joint replacement and no favorite-slot rescue. The existing .0003 pooled improvement/both-fold-nonnegative rule is a reasonable utility threshold if root chooses it before execution, but is not an independent-holdout significance claim. Failure closes this one specification; no knot/rank/coordinate/extrapolation sweep under the same allocation.

Recommendation: permit one concrete proposal, not automatic training. Distinctness is adequate; stronger empirical promise is not established. Account for the complete continuation/finalist/native workload under the unchanged global fit, query, resource and deadline limits before granting a prospective amendment.
