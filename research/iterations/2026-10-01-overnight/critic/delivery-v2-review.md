# Fixed-member delivery v2 handoff

Use critic/native_order_v2, not the original frozen runtime-optimization/native_order. Source and CP311 binary hashes are in native_order_v2/FREEZE.json. The old recovered engine, transition engine, first order prototype, original packager and fallback V1 ZIP remain unchanged.

The reordered engine executes independent members in alternating forward/reverse schedules to reuse an endpoint's weight cache, but stores each output by its original member index and accumulates in original index order. The largest model can move to an interior execution position; this never changes its coefficient association. Every Predictor owns its recurrent, normalization, event and optional transition state. Reset restores every Predictor and the schedule direction. No future row or timer enters prediction.

The first frozen order prototype was not generally bit-exact: on four heterogeneous members with coefficients .125/.275/.35/.25, its bulk run differed by 1.19e-7 from its streaming step and original scalar-FMA oracle. The original loop calls Predictor.step between terms, whereas the scratch-only reduction permits different compiler contraction/vectorization. The exact failing arrays and original binary hash are preserved in order-checks/original-frozen-counterexample-v3.*; the first assertion failure logs also remain. Equal-third fixed three-member streaming results were not affected by this counterexample.

The v2 fix explicitly uses std::fma on FMA builds. On v2 it rounds each product through a volatile float before adding, preserving the original non-FMA arithmetic. No predictor/kernel or scientific feature code changed. Independent archived-baseline and scalar-oracle tests pass for all three ISAs, six compositions, nonbinary coefficients, permutations, duplicate h256 members, and 1, 2, 3 or 4 members, with 795 rows per composition. Bulk/stream equality, odd/even resets and prefix/future invariants all pass. The other actor independently reviewed this tiny fix and replicated separate 1,001-row cases on all three ISAs; its receipts are runtime-vnni-opt/independent-order-v2-*.json.

Complete raw-only PredictionModel.predict timing uses the five predeclared 20,000-row raw sequences, all warmup calls, original FP16-weight format, static ISA dispatch and CP311 scorer userland pinned to CPU18. All 16 complete 100,000-row outputs have the same hash as the archived baseline. Guarded final two pairs record CPU58 sibling busy 0–0.7%: baseline 77.88/78.87 us per row (51.14/51.79 minutes for 39.4M rows), v2 order 72.23/73.90 us (47.43/48.53 minutes). Earlier unmonitored runs reached 103–107 us for the candidate and 113–120 us for baseline. Thus feasibility is conditional on an otherwise idle physical core; process CPU time ≈ wall time alone does not establish that condition. All raw measurements, including slow results, remain in order-runtime-results/ and the structured order-runtime-summary.json. Organizer hardware can differ.

package_fixed_v2.py accepts an explicit fixed composition of 2, 3 or 4 members, checks endpoint 1 and plain-GRU representation, stores FP32 arrays consumed by native FP16-weight mode, keeps optional feature metadata in double JSON, includes fresh x86_64 CP311 binaries for all three ISAs, and enforces 20,000,000 bytes. It preserves package_fixed.py. Smoke builds from one randomly initialized synthetic checkpoint produced all three ensemble sizes and loaded in fresh CP311 processes without torch. Warmup None, finite predictions and exact sequence-reset repetition pass. No trained checkpoint or final composition was packaged. package-v2-test-result.json consolidates the build and smoke receipts.

The final chosen package still needs its exact fresh-ZIP parity and complete-callback runtime check, final checkpoint/composition/provenance verification, and root's selection decision. This handoff performs no fits, WP queries, GitHub actions or submission, and does not replace the unchanged fallback V1 ZIP.
