## Sole candidate and numeric contract

Ordered V1 members: `find256_s3h2`, `fin128_s3h2`, `finc500b_s3h2`, each `model_ep1.pt`, coefficients exactly Python `1/3` converted to float32 at the native boundary. No alternate seed, omitted member, coefficient, quantization scale, calibration data, or changed kernel is considered.

The existing `runtime-vnni-opt/native_block128` weight quantizer and block128 VNNI operator are preserved on their valid numeric domain. A pre-data guard rejects a nonfinite or non-normal computed scale for a nonzero input/weight vector (scale must be >=FLT_MIN), without clamping or rescaling; the independent pre-guard subnormal failure is retained. Only GRU input/recurrent matrices and the first head matrix are quantized. Per-row weight scale and per-vector input scale are float32 `max(abs(v))/127`, or 1 for an all-zero vector. Division precedes nearest-even integer rounding to the symmetric range [-127,127]. The initial floating environment must be FE_TONEAREST with MXCSR FTZ/DAZ disabled; constructor rejects other modes. The host must leave this environment unchanged after construction; arbitrary mid-stream floating-mode mutation is unsupported. Projection, normalization, activations, GRU elementwise update, biases and final head remain floating point. No fast-math is enabled.

VNNI uses unsigned input `q+128`, signed int8 weights and exact `-128*sum(q_weight)` correction. AVX2 uses signed8-to-signed16 widening, `madd_epi16` and nonsaturating int32 accumulation. Scalar uses signed int32 multiplication/accumulation. All three produce identical integer dots, the same float32 product `weight_scale*input_scale`, and a single `std::fma(float(dot), scale_product, bias)` equivalent rescale. Width is divisible by64 and at most512; the maximum dot magnitude is 8,258,048, below int32 overflow. No `maddubs` saturation and no FP16 substitution.

The VNNI projection retains the original input-ordered FMA recurrence. Portable projection evaluates that same recurrence with explicit `std::fma`. Within a given compiled floating engine all three integer backends must produce byte-identical complete-model outputs on fixed synthetic streams. The ensemble reduction follows critic's reviewed policy: explicit float FMA under `__FMA__`, otherwise an explicitly rounded volatile float product followed by addition, always original member order. Execution order may reverse for cache reuse, and resets also reset its parity.

## CPU and qualification boundary

Package selects the same CPU levels as the validated fixed-three package: v3 requires `avx avx2 bmi1 bmi2 f16c fma abm movbe xsave`; AVX2 requires `avx avx2 fma`; otherwise the x86-64-v2 binary is used. x86-64-v2 is the minimum supported CPU contract. Inside each binary, auto selects VNNI only with runtime AVX512VNNI/BW/DQ/VL support, else AVX2+FMA, else scalar. An unavailable explicitly requested test backend throws. The served member set and quantization do not change with ISA.

Different compiled floating engines may differ through their pre-existing FMA arithmetic and later quantization ties. Cross-ISA compatibility tests therefore report errors against v3/VNNI rather than claiming byte equality. For each target, both pooled post-warmup rows and each sequence separately, require p99 absolute error <=.05, RMSE divided by `max(population_std(reference),1e-8)` <=.03, maximum absolute error <=.5, and finite outputs. The same inherited numerical screening gates apply to Q3 versus same-composition FP16 for runtime-fixture diagnostics. No result-dependent tolerance or new metric query is permitted.

The primary amendment runtime and WP gates qualify the measured v3/VNNI path. The prospectively added AVX2 branch below can separately qualify its runtime and audit held-fold output identity. Until those steps pass, AVX2/v2 are compatibility fallbacks with runtime and WP unqualified; shipping them requires root's final readiness decision. A compatibility tolerance cannot establish WP noninferiority. They never silently become FP16 or a different ensemble.
