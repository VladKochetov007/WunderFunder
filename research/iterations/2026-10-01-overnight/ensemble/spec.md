# ENSHEAD-01 frozen reserve protocol

This protocol implements the controller/critic amendment in hypothesis.md. It replaces that file's preliminary affine description with a **scale-only** control. No ensemble empirical run or candidate WP readout has occurred while defining this specification. AUX02's negative result arrived after this mechanism and amendment were already specified; it does not change this recipe.

For each fold0/1 and each ordinary seed3/4 slot, initialize from exactly ref_f{fold}@ep3 or refs4_f{fold}@ep3. The named other three slots are the matching fold's original H2 controls, model_ep1: on_ctl128s4/128s3, on_ctld256, on_ctlc500. They remain fixed across both candidate capacities. Generate their predictions using their own-fold checkpoints on every valid row-group outside that fold. Never use another fold's checkpoint to fill missing training predictions. Cached main predictions are fp32 storage from the same base fp16 causal predictor, chunks4000, batch16; hashes and source row order are fixed. Existing held-fold predictions remain untouched. Four training prediction arrays per fold are shared between two own-slot objectives and capacities. Cache generation performs no target or mask column read and computes no score.

Full-head arm trains the original nonlinear head only, inp/gru frozen. Scale arm freezes every original parameter and trains two zero-initialized log-scales, p=exp(a)*p_parent, with no offset parameter. Both arms use batch16, chunk2000, two epochs from the original parent, seed3/4, AdamW lr5e-4/wd.01, unchanged OneCycle, fp16 fast path, exact training scoring masks after row99 warmup, auxiliary structure/next coefficients .3/.3. Dataset targets stay in columns0:2; fixed partner sum occupies training-only columns2:4 and never enters inference features. Data order and skipped-eval RNG advance are unchanged. Original auxiliary losses remain present; in scale arm they are constants with respect to the two trainable parameters. Full versus scale therefore changes shared auxiliary adaptation as well as flexibility.

Main objective is `4 * gcorr((p_own + p_partner_sum)/4, target, mask)` with the unchanged existing gcorr function. Targets are clipped to±2 and weighted by their absolute clipped value; predictions remain unclipped in this **minibatch×chunk surrogate**, as in the original recipe. Scaling the main loss by4 restores the standalone own-output gradient in the identical-partners limit, preventing an incidental fourfold weakening against auxiliaries. It does not make minibatch training equivalent to the globally pooled score. The scorer separately clips the final aggregate exactly as required. No clipping or objective variant is searched.

Training partner cache validation checks manifest schema and fold, exactly three distinct named partners, checkpoint/prediction hashes, epoch1, source-order and chain-map hashes globally and per partner, exact unique in-range cache positions mapping to their declared row-group IDs, all expected eligible training groups and no held group. Every accessed prediction must be finite. The fixed recipe requires an explicit parent initializer and refuses an existing nonempty output run. Per-epoch score computation is suppressed; only the original DataLoader CPU RNG draw is preserved. Numeric zero in history is tagged as a placeholder, not a readout. Final endpoint is model_ep1.pt, and model.pt is saved from that endpoint for safety.

Scale exports multiply the first two original output weight/bias rows by exp(a), leaving every other parameter and inference operator unchanged. The checkpoint includes the learned log-scales, fixed-zero offsets and immutable partner provenance. Float32 synthetic export parity is tested; actual CUDA/native fp16 parity must still be validated before packaging. CPU kernels can differ at ~1e-8 when requires_grad flags differ, so initial forecasts are compared with equal frozen flags and exported-function parity uses an explicit tolerance. The failed initial overstrict comparison and its diagnosis are preserved.

## Fixed comparisons and stopping rule

Primary serving system simultaneously replaces both ordinary slots at unchanged quarter weights. Each slot was optimized against the **original** H2 version of the other slot, so this is independent simultaneous replacement rather than joint ensemble optimization. Report its result even if the single-slot effects are better. No favorable seed/slot rescue is allowed.

Full-head promotion: pooled≥+.0003 versus the original H2 four-member blend, both folds nonnegative, and full-head minus scale nonnegative in pooled and each fold. Scale promotion: independently pooled≥+.0003 versus original with both folds nonnegative. If full-head fails its comparison to scale and scale passes its own gate, prefer scale. Otherwise a failed primary gate stops that exact recipe. These are budget/deployment decisions, not significance or claims of hidden-test transfer.

Report three combined contrasts (head/plain, scale/plain, head/scale), four single-slot replacements (head and scale each seed), and four paired standalone comparisons. Maximum11 evaluator calls for these fixed analyses, including combined comparisons. Report both folds and whole-chain paired uncertainty within each query. All pure chains/folds are exposed; seed slots and chain resamples estimate different uncertainty sources, and neither establishes unseen superiority.

Resource proposal: eight training-cache prediction passes (~2.4GB), eight head/scale fits, eight held-fold prediction arrays (~2.4GB), no new parent training. Budget35GPU-minutes estimated plus shared-host overhead; root hard per-job limit600s subject to resource occupancy. At most2 jobs, ≤5.5GiB GPU/job,4 torch CPU threads/job and2 workers. Root allocates and launches after independent review and source freeze. If feature branch consumes shared capacity, queue this reserve; do not kill unrelated work. All artifacts stay local/beleriand; no GitHub or public leaderboard submission.
