No model, competition data, checkpoint or prediction was opened, and no SSH or empirical command was run for this preparation.

The existing frozen `overnight/training/train_aux.py` is used directly, SHA `f13e61b4…`. Its `parents[4]` resolves to the creative checkout. Set `PYTHONPATH=src` and use that checkout as cwd. ## Fast-path decision

Keep the historical `--fast` setting. It enables sync-free reductions, fused AdamW, pinned loading/CUDA prefetch and propensity caches. Removing all of it also changes EMA implementation, masking reductions and optimizer execution, so it is not a neutral memory switch. If a future prospectively approved resource variant disables only prefetch, it must omit `--fast` while explicitly retaining `--sync-free --fused-adam --prop-cache`; that variant is **not included** here and is not promised trajectory-equivalent.

The previous generated prefetch diagnostic exceeded its GPU cap before completing an epoch; it did not establish a production stream-leak cause. Preserve the ordinary source and use existing allocator/resource guards rather than infer a fix from that failure.

Changing layer count consumes different initialization RNG before `fit_normalization` and shuffled DataLoader iteration. Thus seed3 alone does not fix the normalization sample or training order relative to the old d256 anchor. This is a competition-recipe screen, not a clean depth-only causal ablation; no silent reseed or initialization wrapper is proposed.

Local validation is limited to syntax, source/argument hashes and default dry-run. Linux systemd/cgroup/timeout behavior and real resource availability remain unverified until SSH access and root allocation. No allocation file granting execution has been created.
