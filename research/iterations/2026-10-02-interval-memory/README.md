# Interval memory: generated readiness only

No forecast fit, dataset read, checkpoint load, WP readout or GPU execution is authorized by these files. This is a queued child of the temporal family. Production source is `interval_memory.py`; `check_generated.py` uses only generated ordinary-model weights and inputs.

Both arms have the same fast GRU256x1, learned tanh projection32, event GRU64 and extra readout. The accumulated arm maintains sum/count of projected fast states; the instantaneous arm substitutes the current projection. The current i0 event contributes to and closes its interval. Its updated slow state and completed mean are available to that row's output; the accumulator is then zero for the next row. Row0 never closes an interval. The slow input is `[summary32, log1p(inclusive_interval_count)]`. All211 causal inputs and the event flag at index178 are read before normalization. No target or scoring mask is used by this module.

The ordinary head remains structurally unchanged. `extra_weight[256,96]`, initialized exactly to zero without a random draw, adds the fast-summary/slow-state contribution to its preactivation. This retains the original512-column head GEMM and avoids arithmetic changes from widening a zero-padded matrix. `load_plain_baseline` requires every ordinary state key with exact shape/dtype, finite values and positive std, loads all shared tensors strictly, and zeros the extra readout. It never accepts an unexplained partial checkpoint load. Candidate/control constructors consume identical RNG and produce identical initial tensors; extra modules still consume draws relative to the original ordinary constructor, so only the paired arms are RNG matched.

`forward(x,state)` is compatible with the original ordinary `forward_chunk` call, with no special architecture-type branch. Returned state is a tuple of four tensors: row hidden, slow hidden, interval sum and integer count. Original recursive `detach_state` therefore cuts every carried graph at the unchanged outer boundary while preserving values. Normalization is carried over from the warm-start parent and must not be refitted. Parent adaptation must train all modules. For H2, `freeze_trunk()` freezes `inp`, `gru`, `interval_proj` and `event_gru`; only `head.*` and the separate `extra_weight` are trainable. The latter is a readout parameter, not part of the frozen projection/trunk.

The production path has no per-row Python loop: full-chunk ordinary GRU, vectorized inclusive interval sums, stable event packing, event GRU and gather. One event-count host synchronization per chunk remains, as in the old dual-clock implementation. Padded event outputs are discarded and cannot influence earlier real events. FP16/BF16 projected values accumulate in FP32; FP32/FP64 inputs retain that accumulation dtype. Prefix subtraction and literal streaming additions need not be bit-identical; generated tests report the drift separately. A future native path must implement current-event closure and sequence resets exactly and measure precision/runtime before delivery.
