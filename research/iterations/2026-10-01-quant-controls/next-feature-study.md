# Proposed next feature study — not yet preregistered or executed

The two controls establish that the strong original mark-prediction gain is not reproduced by the particular prior-matched mark/raw-run surrogates. They do not establish incremental value to the existing forecasting GRU. The next useful question is practical: **can an explicit causal transition summary improve a fixed serving ensemble beyond a comparable marginal-history summary?** No physical flow interpretation is required.

## One bounded contrast worth implementing next

Use an existing h128 backbone with its original preprocessing and causal recurrent state frozen. Add the same small, fixed-size feature block to the head in both arms. Initialize new input weights at zero while copying existing head weights, so each arm begins with exactly the same original predictions. Use the same head training schedule, masks, auxiliary losses and paired sampling. This cheaply tests accessibility of extra history at a fixed representation; a negative result would not reject every end-to-end use of the feature.

Both arms should receive common encodings of current/previous emitted category and simple count/age information. In the control arm, additional probability/residual/surprise channels derive from adaptive marginal F. In the candidate arm, the corresponding channels derive from adaptive conditional T. Freeze equal dimensionality and scaling before training. Including the common mark/history inputs avoids giving only the candidate a trivial category or lag feature. Residual `one_hot(mark)-p` is an algebraic transform when its operands are already available; any utility would be an optimization/representation benefit rather than new information.

At a detected row, compute the categorical distribution from past marks, observe the current code, construct the feature, predict the price target, and then update transition counts consistently. The feature is legal for price prediction after current raw input is observed; it must not use future prices or future raw rows. Non-event holding behavior, neutral/invalid handling, row0, per-sequence reset and age units must be fixed explicitly. Encoding centers and nuisance priors must be fit on allowed training chains only for each held-out fold. Never infer serving class from full-sequence target labels or use evaluation sequences to fit their own future centers.

The preregistration should use paired seeds3/4 and folds0/1, equal two-epoch head budgets and a fixed checkpoint rule. This implies eight head fits for the two treatments before any additional serving anchors. Inspect which V1-like two-epoch OOF partner/control artifacts actually exist before finalizing cost: one-epoch C is not a substitute for V1's two-epoch recipe. Auxiliary coefficients remain equal between arms; combining aux-off with this feature would confound the first comparison. No context-size, κ, detector or center sweep belongs to this first allocation.

Primary comparison: candidate versus matched history control inside the same declared four-member serving blend, with the intended h128 slots replaced consistently. Report both folds, each paired seed and the combined-serving estimand; distinguish training-seed variation from chain resampling. A concrete materiality threshold, query count and stopping rule still need to be frozen against the actual comparator and runtime budget. Do not select weights or a favorable seed from the control-study readouts.

Before real fitting, verify identical initial forecasts, causal prefix/stream/chunk equivalence, nuisance-fit chain provenance, count reset, dimensions and numerical range. A CPU/native prototype should bound extra work: online16×16 context counts are small, but per-row feature/head work and serving implementation are not automatically free. The current runner/exporter may need explicit support for the extra head input; no claim of a submission-ready artifact is made here.

A successful nuisance-code predictor is only motivation to try this bounded comparison. If the matched control captures the same gain, retain the simpler implementation. If a price gain appears on exposed folds, treat it as exploratory until a prospective permitted external evaluation; the paused GitHub preference does not change automatically. This proposal allocates no GPU job, feature fit, WP query or submission in the completed control round.
