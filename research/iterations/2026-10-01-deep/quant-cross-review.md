# Independent quant-side critique of the architecture branch

Reviewed `architecture.md`, the frozen plan, its reported audit results and the relevant `features.py`, `ticks.py`, DualClock/EventAttn call paths already inspected in this research cycle. This is a specification and interpretation review, not another data probe.

**The strongest result is a material intervention, not an accuracy improvement.** Removing 35.67% of class3 proxy writes makes the mask change substantive. Prefix/chunk tests support causality of the particular direct lookup. Neither result says that suppressing those writes improves recurrent-state estimation: a book-shape update without a quote move may still contain useful information. The original row GRU remains active, but the auxiliary event history may benefit from precisely those shape snapshots. A future candidate must preserve the matched proxy-clock control.

**The failed decoder gate must remain failed, but it is not the correct physical error estimate for a binary mask.** The 44/237 discrepancy compares signed delta pairs on unique shared keys. A sign or magnitude disagreement can leave `any(delta != 0)` unchanged, and rare keys get equal weight to common ones. Similarly, a modal target-jump purity below .95 can arise from several future-reference outcomes without making the most frequent quote delta wrong. Do not call either quantity the event mask's error rate. The dossier now makes these distinctions correctly. A future amended plan could separately freeze row-weighted binary-mask disagreement, chain stability of zero-versus-nonzero decisions and confidence in competing modes; doing so would be a new exploratory recipe, not retroactive passage of the present gate. A larger table alone need not cure common-key impurity.

**A1 is a coherent, narrower alternative, with an optimization caveat.** Changing event input from instantaneous projection `z_t` to row-GRU output `o_t` keeps the event-clock, shapes, parameter count and serving arithmetic fixed. It gives each stored event token an already accumulated causal row history, so it is distinct from merely increasing event capacity or renaming code events. However, it also makes the event-branch training loss backpropagate through the row-GRU trajectory instead of directly through the projection. Any observed effect combines the token representation with this new gradient route. Do not claim that a gain would prove long-memory information was missing. An `o_t.detach()` comparison could later distinguish those mechanisms, but should not be bundled into the first allocation without an explicit extra trial budget.

**The negative controls are decisive for practical interpretation.** Beating the historically negative dual model is insufficient; the candidate must also improve the ordinary row model and the fixed serving ensemble replacement. A1's event state is a deterministic function of row history already available to the row recurrence. Its rationale is finite-model representation/optimization, not new observable information or guaranteed longer TBPTT credit. The documented ordinary row and proxy-dual controls, fixed epochs and paired seeds are appropriate. Comparing both parent and head stage without a declared primary would add checkpoint selection; the proposed fixed head-stage serving comparison should stay primary.

**Serving is a genuine additional gate.** Equal A1/R6 arithmetic is not equal A1/current-C cost, since C presently contains plain GRUs and the production engine lacks DualClock. The recurring widened head cost survives even on rows with no event. The architecture dossier correctly counts that cost and requires a full native replacement benchmark. Its apparent public time margin must not become a promise. The quant branch has a similar issue: small feature-state size alone does not imply free callback/input-layer latency.

**Allocation recommendation, corrected after training-side cross-review:** keep main-only head-loss investigation first on low cost and clean comparability, without requiring a gradient-conflict gate. TDIAG found positive combined alignment in both inspected windows, so that mechanism is not supported there. A1 history-token versus proxy-dual is a more coherent second architecture treatment than calling the failed decoded table production-ready. The current decoded-clock result warrants further semantics work only if that is judged worth an additional CPU investigation. The quant sparse-dictionary result supplies no reason to jump ahead of these controls into a GPU queue-model study.
