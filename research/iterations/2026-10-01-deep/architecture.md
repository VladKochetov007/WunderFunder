# Quote-clock architecture: first establish what clock we are changing

The narrow clock-replacement proposal is **not ready for a GPU allocation**. The earlier scout identified a real difference in definitions, but did not establish its frequency, its decoder provenance, or whether the proposed direct transition lookup is the same quote clock used by the historical reconstruction. Those are distinct questions. The registered diagnostic measures them on training-side inputs; it does not measure forecasting quality. An unchanged clock would close this exact proposal immediately. A substantially different clock would only establish that an intervention exists.

This dossier follows the creative-research skill and its empirical-validation reference. All competition folds have been exposed. The fresh decoder's fit/audit chain separation protects this calculation from fitting its own audit observations; it does not create fresh competition confirmation. The public artifact remains V1, 0.6641 with two-epoch head tuning; C is a different one-epoch-head local discovery reference.

## What the implementation actually does

`features.py:44–55` defines `EV_I0PX` as **both x[0] and x[11] changing**, using exact feature comparisons. `ticks.py:33–46` instead enumerates any change in all 22 encoded price coordinates, rounds those vectors to four decimals, and estimates a pair's quote delta from the most frequent quantized **target jump**. Neither definition is automatically an observable best-bid/best-ask change. The feature documentation records that the original proxy was chosen because labels changed on those rows; it is not a decoded-market identity.

`train_rnn.py:365–366` passes that proxy to both DualClockModel and EventAttnModel. DualClock keeps a normal two-layer row GRU; its additional one-layer GRU advances only at selected events. Its input is **the instantaneous projected row `z`, plus log elapsed rows**, not the row GRU's accumulated state `o` (`nn.py:224,238–242`). Between events, its recurrent state is held unchanged. The final head sees `[row GRU output, held event state, instantaneous projection]`. Padding event batches to their maximum count does not leak future padding into selected earlier outputs: the event GRU is causal, and the saved state is gathered at each sequence's own last valid event. Chunk gaps are explicitly carried. Existing deterministic tests cover prefix, future-mutation and chunk equivalence (`tests/test_dual_clock.py`).

Event attention writes the same instantaneous `z` plus the **gap before token creation**, rather than an interval summary (`event_attn.py:57–67`). Its logits have no explicit current relative token-age term; simultaneous permutation of fixed key/value pairs leaves an attention sum unchanged. The full model is nevertheless order sensitive through the row GRU query, the causal token window, and the content/gap values. The retained token ring is detached across chunks (`event_attn.py:95`), as carried recurrent state is detached by TBPTT. More event memory therefore does not imply long-range gradient credit.

**Fine-tuning trap:** the default `fold_ft.sh` freezes only parameter prefixes `inp,gru`. For a dual model that leaves `event_gru` trainable; for event attention it leaves token/query/context modules trainable. Calling that stage “head-only” across architectures would be inaccurate. A future true head-only dual comparison must explicitly freeze `inp,gru,event_gru` in both candidate and dual control and log trainable parameter names. Any experiment retaining the default must be described as row-trunk-frozen adaptation, with its extra trainable modules counted.

Replacing only the event mask leaves 99 existing event features, `since_i0px` main-loss weighting (`train_rnn.py:906–908`), row recurrence, and target-defined next-change auxiliary unchanged. That is a valid narrow treatment, but the model would then contain two deliberately different notions of age. It is not a wholesale repair of “the market clock.” `a0..a7` are anonymous inputs; no physical timestamp or interarrival duration is invented here.

## The decoder has two distinct semantic/provenance problems

1. **Labels are used to fit the decoder.** `ticks.learn_moves` divides training targets by the class-3 scale 0.65687, rounds to integer units, and assigns the modal target jump to each rounded feature transition. A target jump can also reflect a changed future reference or stopping boundary; a modal assignment is an estimator, not an exact physical proof. Rare edges need counts, competing outcomes and purity. A high modal agreement on training examples is not independent quote truth.
2. **Direct moves and reconstructed paths are not identical definitions.** `reconstruct(x,moves,spreads)` integrates direct ask moves, then overwrites the current bid with `ask - learned_spread[code]` whenever a spread entry exists (`ticks.py:81–89`). This can make the bid move even when the direct move table says `(0,0)`. A concrete two-code counterexample has direct deltas `(0,0)` but spread narrowing 2→1: reconstructed bid rises one tick. The proposed direct clock must be compared to this spread-consistent clock before claiming to implement the historical “honest quote” event.
3. **Without a spread table, absolute reconstructed bid is not prefix causal.** The fallback anchor uses the modal spread over the entire supplied sequence (`ticks.py:91–93`). Adding future rows can change all preceding absolute bid levels. A constant anchoring shift cancels in within-sequence quote differences, so this observation alone does **not** prove that a clock based solely on those differences leaks. Serving should avoid the ambiguity entirely: direct causal edge lookup, explicit state initialization, and prefix tests.
4. **The existing pickle's instance provenance is incomplete.** The current hash is `117f97e41389526ffb5e9c1f5fa4b1ad34b2af622226dc4cd0674590564a90a2`. `eda_ticks.py:64–72` can build it from 1,500 class-3 train sequences, but skips fitting whenever any cache already exists. The pickle lacks source hash, fit IDs, counters and label/split identity. Earlier journal numbers and this builder's existence do not certify this exact instance. It is retained only as a descriptive comparator.
5. **Class routing cannot use test labels.** Training metadata identifies class from target quantization (`data.py:111–121`). That label-derived class can stratify this audit; it cannot route test recurrence. A class-3-fitted edge mapping must not silently claim all-class quote semantics just because a rounded key happens to match elsewhere. Unknown edges use the unchanged proxy, but *known, semantically wrong* edges remain possible. All-class row and event denominators are mandatory.

The fresh diagnostic table is therefore fitted on 96 explicitly frozen class-3 training-only chains, one sequence per chain, with full support counters and spread counts. The 32 audit sequences are eight per class from disjoint training-only chains; every chain containing any validation member is excluded. Audit reads request `targets=False, mask=False`. Fresh and cached lookup results are both reported. A small-table coverage failure does not disprove a full-train rebuild; it does prevent using the small table as a production decoder.

## Registered falsification, not a proxy leaderboard

`architecture-plan.json` was written before any diagnostic and contains exact fit/audit IDs, hashes, denominators, fallback, cuts and stopping rules. `architecture-diagnostic.py` is a single ≤480-second, ≤2-thread run. It reports all selected sequences, known/unknown events, known shape-only proxy updates, missed decoded moves, fresh support/purity, direct-versus-spread disagreement, event gap distributions and deterministic prefix/chunk/stream checks. It does not load prediction caches, query WP, tune a threshold or select a favorable sample.

Close the narrow clock-repair proposal if neither independently fitted nor descriptive cached known class-3 transitions change at least 1% of proxy events or recover at least 1% of decoded quote events. These are materiality/spending cutoffs, not a statistical equivalence test. Direct-versus-spread disagreement above 0.1% of known events, or fresh/cached disagreement above 1% of overlapping edges, blocks this exact semantic implementation pending explanation. Complete online admission also needs supported class-3 coverage ≥99%, a verified table manifest, defined all-class behavior, rounding parity in the native engine and correctness at reset/chunk boundaries. The 96-chain sample may be insufficient to supply that coverage; report that honestly.

**Observed execution:** the single frozen run completed in **24.965 seconds**, peak RSS **1.12 GiB**, all 96 fit and 32 audit sequences processed. Raw outputs and the provenance-bearing fresh table are in `architecture-output/`; code/plan/input hashes are in `architecture-result.json`. No fallback run, resampling or follow-up probe was used.

The key finding survives scrutiny: in class3, the fresh direct clock removes **35.67% of proxy updates**, changing **7.28% of rows**; 21,002 known decoded quote events were all already proxy events, so there is no observed missed-quote recovery. Known-transition coverage is **99.982%**. The descriptive cached table removes 11,651 proxy updates, a similar *aggregate rate*. We did not register or compute rowwise fresh-versus-cached binary-mask agreement; similar counts must not be presented as proof of identical individual event decisions. The proposal would predominantly suppress class3 writes, not discover a hidden high-frequency event stream. Classes0–2 have zero known transitions in both decoders on this sample: the candidate is exactly the old clock through fallback there, not a validated all-class quote decoder.

The direct-versus-spread concern is real but **does not trigger its registered numeric blocker** here: 4/32,657 fresh known edges (0.0123%) and 8/32,663 cached known edges (0.0245%) disagree, both below0.1%. The inconsistent-spread toy behaves as predicted. All fixed-cut prefix, streaming and chunk checks pass for the fresh direct mask. This supports causal implementation on these inputs, not validity of the inferred physical quote moves or native rounding parity.

The separate decoder gate **does fail as preregistered**: the 96-sequence fit yields384 keys, of which237 overlap the cached table and **44 differ in their signed move pair (18.57%, above1%)**. This is an unweighted unique-key statistic, not an18.57% row error rate and not necessarily a binary-clock difference: signed movements may disagree while both are nonzero. Also only **18,611/32,657 known audit events (56.99%)** meet the predeclared support≥20 and modal-purity≥.95 descriptive rule; **14,029 (42.96%)** occur on lower-purity keys. Training target-jump impurity can arise because the future reference changes, even when the modal quote move is right. It is not proof that42.96% of quotes are decoded incorrectly. More data might stabilize rare modes, while common multi-outcome target jumps may remain impure; these require different explanations.

**Gate-faithful disposition:** material clock distinction **supported on this train audit**; prefix causality **passed for the implemented mask**; semantic/production admission **failed/insufficient**. Do not train the exact decoded-mask proposal under the current gate. Do not call all event-clock architectures refuted. A future, separately registered investigation could adjudicate high-frequency conflicting edges using train-only transition/spread consistency and distinguish signed-delta accuracy from binary-event accuracy; it must retain this failed unique-key gate rather than retroactively replace it. For the present allocation, the label-free A1 treatment below avoids this specific decoder dependency.

## Two alternatives that change the state mechanism, rather than rename the clock

**A1 — Store a row-history summary at each event.** Keep the existing proxy, event_hidden128 and all R6 settings. Change only the first 128 components of the event GRU input from `z_t` to `o_t`, the already computed top-layer row-GRU state at the current row; retain the same log gap. Thus `e_j = GRU_event([o_t,log(1+gap)],e_(j-1))` at event rows, with held state between events. The current implementation only stores instantaneous event snapshots. This change could retain information accumulated between events in an event-indexed history, without requiring quote decoding or a new feature family. It adds no parameters, MACs or serving state relative to R6. It is still redundant information relative to the row GRU, and long-horizon credit remains TBPTT-limited; no gain is presumed. The exact comparator is existing R6 with `z_t`, with initialization shapes, data order and seed paired. Do **not** simultaneously change the event mask. A benefit in this control isolates the event-token source, not a claim about true market clocks. If implemented after this round, this is the more credible architecture study than an uncertified decoder-clock change.

**A2 — Let the event state's readout age between events.** Keep the recurrent event writes identical to R6. Read a scalar-decayed state `e_read(t) = (1 + age_rows(t)/32)^(-lambda) * e_last`, with one shared nonnegative learned scalar lambda, not a separate clock, width or horizon sweep. Initialize near identity; compare to an explicit identity-readout control with lambda fixed zero and the same architecture. Never overwrite `e_last` during readout, which would make decay depend on chunking. This distinguishes “event memory never changes in quiet rows” from the event-memory contents. The row GRU and existing age features can already represent such modulation, so this is a weak inductive-bias hypothesis, not missing information. It adds one scalar exponentiation and E multiplies per row; a native implementation can benchmark that directly. The horizon32 is inherited from existing since weighting, not fitted from this audit. Do not allocate it alongside A1 without a separately bounded comparison: otherwise architecture/model selection multiplies silently.

A1 addresses *what crosses from row time into event time*. A2 addresses *how that memory is used as row time elapses*. Neither supplies actual wall-clock timestamps, assumes quote events alone are sufficient, or hides a new queue-dynamics feature study. The decoded clock is a third, separate treatment. A combined treatment cannot tell which mechanism mattered.

## Training and native-cost contract for any subsequent allocation

A follow-up must declare **one** treatment before training, two paired seeds (3,4), folds0/1, original R6 hyperparameters, fixed parent epoch3 and fixed head-FT epoch0, explicitly freezing `inp,gru,event_gru` for a true head-only dual stage (and the ordinary row trunk in its row control). It needs the matched dual control and ordinary row control, then a fixed replacement of one predetermined plain-h128 C slot at weight .25; other members and weights stay fixed. Report every seed/fold, pooled clipped absolute-target-weighted Pearson, whole-chain conditional uncertainty, seed variation separately, and retained/unknown decoder coverage if applicable. Require positive pooled paired signs in both seeds, positive C replacement signs in both folds and pooled C lift ≥.0005 to justify more spending. It remains discovery, and cannot be described as V1 improvement without a matched two-epoch-head V1 comparison. Beating the old negative dual model alone is not sufficient.

For H=E=128, the event GRU adds `3*128*(129+128)=98,688` weight MACs **per event**, and the wider first head layer adds `128*128=16,384` MACs **every row**, plus biases/nonlinearities. It adds roughly 116k parameters and 128 floats of event state plus a gap counter. The extra mean MAC cost is `16,384 + event_rate*98,688`; report event-rate distributions and worst case1, not just average class3. This does not convert to a reliable latency estimate. A1 has exactly the same arithmetic/state as the dual control. Decoder lookup adds rounding/quantization, table storage and branch/cache behavior; Python tuple lookup is not a native runtime plan. Event attention instead carries 32*128 float values plus validity (~16KiB per stream), and performs query/context work on every row.

Existing native export rejects non-GRU architectures (`scripts/export_onnx.py:47`), and the deployed C++ engine does not already implement this DualClock state machine. Native export, variable event/no-event paths and reset/chunk parity are required work. A one-step recurrent wrapper must compare every emitted row against batch PyTorch, including no-event sequences, first event after a long quiet prefix, unknown edges, rounding boundaries and adversarial future perturbations. Preserve the exact warmup semantics.

V1's observed 2502 seconds over approximately39.4M rows is ~63.5μs/row; the nominal 3600-second limit is ~91.4μs/row. The apparent 27.9μs difference is **not a guaranteed budget**: public timings for similar C-family artifacts varied substantially. Benchmark the complete replacement ensemble, same host and native CPU path, against the actual C/V1 baseline; include worst event density and decoder misses. Prefer ≤5% ensemble latency increase and retain an absolute deadline margin on the slower measured host condition. If that fails, do not add a member or assume the organizer CPU will rescue it. Distilling an expensive architecture would be a separate candidate and additional selection budget, not an automatic escape hatch.
