# Fixed ensemble-objective implementation

`training/train_ensemble.py` is the frozen `train_aux.py` (SHA f13e61b4…) with the complete derivative in `training/trainer.diff`. The model, target/weight construction, optimizer, scheduler, EMA, auxiliaries, epoch endpoints and skipped-evaluation RNG draw remain unchanged. `validate_recipe` accepts only the eight commands derived from the original shallow-student recipes; unsupported original trainer branches cannot be selected.

Both arms append a dedicated `[T,3,2]` float32 partner field after any propensity tensor. Existing target columns remain labels plus their original distillation teacher. The same generic prefetcher transfers both arms' payload. The control returns its original output tensor and loss unchanged. The candidate uses `(((p.float()+a1)+a2)+a3)/4` with detached anchors and no prediction clipping, then multiplies **only** its supervised main loss by four. Own-output EMA consistency and all auxiliary terms follow afterward unchanged. Four restores the local main output gradient when all anchors equal the detached own prediction; it does not make the Hessian or the subsequent optimizer trajectory identical.

`PartnerPayload` checks the assembled fold/order/checkpoint/receipt identities, target row-map metadata and held-fold exclusion. Prediction files are lazily read-only-mapped in each worker; full-sequence selected values must be finite. Large prediction bytes were hashed by cache assembly and are stat-bound during fits. Target NPZs may have no whole-file hash; their recorded stat and exact row-group-array hash are checked. This is not a claim that every large input is cryptographically rehashed for every fit.

`trajectory-proof.jsonl` records initial model bytes, post-normalization/load bytes, source row-group orders and CPU RNG state before each epoch iterator. Hashing consumes no RNG. Matched parent initial and post-normalization states should agree; matched H2 initial random construction should agree, while loaded trained parents deliberately differ. These receipts establish initialization/sampler prerequisites, not deterministic CUDA execution. `check_checkpoint.py` checks all105 resolved arguments, fixed EMA-parent ep3/head ep1, finite211-input state and eight unchanged H2 trunk/normalization tensors.

The payload adds 15.36MB per parent batch32×20000, plus one prefetched batch; H2 uses half that. No211-feature cache is created. Main-loss arithmetic is three additions and a division per two-target row. Actual GPU memory, loader throughput and predictive benefit still require the allocated run.

`test_generated.py` reads source and generated fixtures only. It checks extracted actual old/new loss blocks, control loss/gradient/two AdamW-step identity, candidate main-gradient scaling, detached anchors, ordered float32/no-clipping witnesses, unchanged auxiliary/EMA source, original normalization and sampler-RNG parity, dedicated payload positions and mmap/fold/finite guards. CPU proof is not AMP or runtime qualification. No model training or metric execution is authorized by running `build_plan.py` or these tests.
