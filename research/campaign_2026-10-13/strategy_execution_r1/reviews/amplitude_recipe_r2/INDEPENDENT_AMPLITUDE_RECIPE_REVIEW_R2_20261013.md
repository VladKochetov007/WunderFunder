## Blocking execution defect

The P1 worker failed at `train_rnn.py:1672` while calling `load_campaign_split(args.split_manifest, ROOT)`. The command supplies `--split-manifest research/campaign_2026-09-29/artifacts/splits/fold0.json`, but `src/wnn/splits.py` calls `path.resolve()` on the supplied path instead of joining it to `ROOT`. Since `bandit_resources` sets the worker cwd to `source_overlay_r2`, the attempted path was:

`.../source_overlay_r2/research/campaign_2026-09-29/artifacts/splits/fold0.json`

That file is absent. The fix is to pass the absolute MAIN split-manifest path in the fit command. The export command also passes a relative `--campaign-split-manifest`; `predict_run.py` calls the same loader and will fail from overlay cwd, so that argument must be absolute too. Other relative inputs used here are explicitly rooted in MAIN by the trainer (`distill_cache_root`, initializer, propensity model, and datasets); P2/P3 resume paths are already absolute.

The read-only shared runtime record for attempt `clean-t3-f0-amplitude1-s3-a9-r1-p1-20261013` confirms status `failed`, exit 1, and no completed fit. The terminal log is a `FileNotFoundError` for the overlay-relative split path. This failure occurred before `configure_torch()` and before the output directory is created. Recorded peak observed VRAM was 79,691,776 bytes, worker RAM peak 363,032,576 bytes, and OOM/max-event deltas were all zero. Classify it as an execution-path failure, not negative model evidence. That attempt ID is consumed and must not be retried.
