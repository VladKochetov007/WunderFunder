# Independent review of initial domain-stress panels

Reviewed the frozen implementation at commit `8940db0d` and source snapshot hashes recorded by `research/campaign_2026-10-13/strategy_execution_r1/DOMAIN_PANELS_R1.json` (artifact SHA-256 `3fdf85bac3c5e19387357b08d449f173f1a24a28a4d9f25511d427b7160471ac`). I did not inspect or grade any new candidate outcome.

The panel builder reads only the whitelisted input-feature change rates and distinct-value counts from `cache/seqstats_valid.parquet`; it does not select target, scoring, or target-derived summary fields. It verifies that the summary row groups match the frozen validation-source component map, separates fit and evaluation components, and uses median component-mean cutoffs from the outer-fit valid groups. The thresholds are applied to evaluation component descriptors, so every sequence in a connected component stays in one domain. The artifact is explicitly limited to the available valid-summary source; it does not pretend that this cache covers train-source sequences. The recorded code hashes match the checked-in builder, evaluator, and summary producer.

The mixture weighting and scoring math are coherent for the declared sensitivity. `mixture_counts()` assigns each complete component a common multiplier within its domain so the requested high-domain component frequency is 25% or 75%; this preserves all rows and label-magnitude weights within the component. `paired_mixture_scores()` pools centered target/prediction moments and recomputes the two global pooled correlations before averaging targets. It does not average within-domain correlations. The focused tests passed (`3 passed in 0.19s`), including comparison against actual repeated complete-component arrays. My independent artifact check found four folds, three panels per fold, all panels marked available, minimum evaluation stratum size 60, and exact matches for the three code hashes recorded in the artifact.

One guard does not establish the property claimed in its comment. `paired_mixture_scores()` compares per-sequence label mass, mean, and M2 between candidate and reference moments and describes equality as establishing identical rows and weights. Those moments are not an identity digest: two different masks can select different rows yet have the same label moments. I demonstrated this with two masks selecting the same `[-1, +1]` labels in each sequence, while candidate and reference predictions have different alignment to those rows. The cross-mask pair passes the equality check and returns both mixture scores as 1.0 with a zero delta. Thus callers must not rely on the current equality test to validate pairing.

The safe use is to construct candidate and reference moments together from one `paired_component_moments()` call using the frozen official mask and the same row/component order, and to bind the mask/source identities in the grading receipt. During this review, root added a worktree wrapper `evaluate_domain_mixtures()` that computes both sides in one call and made the low-level moment scorer private. I inspected that wrapper (current source SHA-256 `d6f7ac1ce7c96b8095d53de91ae862f3fee2fbcb76d1e2e84cd5302f7af9ff31`) and independently reran the focused tests (`3 passed in 0.23s`); it closes the demonstrated cross-mask mismatch at the public API boundary. It still relies on the caller to bind sequence order, component IDs, source identity and the supplied official mask; no score should be calculated until a new receipt binds those inputs and this exact wrapper hash. Keep the frozen R1 panel immutable. This is a grader input-integrity condition, not a reason to tune or refit the frozen cutpoints.

The panel coverage is partial by design. `DOMAIN_PANELS_R1` includes activity, instrument-1 update frequency, and feature support, while quiet/transition, source similarity, and cross-fitted propensity panels remain pending. All local folds are exposed and the domains are constructed sensitivities, not evidence from a fresh future distribution. The current helper reports point scores only; paired component uncertainty and fitting-repetition variation remain separate. These panels can support partial sensitivity comparisons, but not a claim that the contract's complete private robustness ranking is available.

**Disposition:** pass for frozen panel construction and mixture arithmetic; conditional pass for the current wrapper once its exact source and grading inputs are bound by a new receipt. The original commit's public moment-pair API was vulnerable to mismatched masks. Report the three-panel result as partial sensitivity until the remaining frozen panel families are completed.
