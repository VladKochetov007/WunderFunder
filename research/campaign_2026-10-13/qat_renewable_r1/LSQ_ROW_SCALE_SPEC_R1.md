# Learned row-scale QAT prototype — specification R1

This is a gated, code-only LSQ-inspired extension to the fixed row-scale W4 QAT policy. It does not change the default QAT mode, any frozen fit recipe, or the native archive format. Implementation is behind `--qat-learn-scales` and is valid only with `--qat recurrent_w4` or `--qat input_w4_recurrent_w8`.

## Method and matched-arm invariant

The primary source is [Esser et al., Learned Step Size Quantization (LSQ), arXiv:1902.08153](https://arxiv.org/abs/1902.08153). LSQ quantizes `v` using `round(clamp(v / s, Q_N, Q_P)) * s`. Its step-size derivative is `Q_N` below the lower bound, `round(v/s) - v/s` inside the range, and `Q_P` above the upper bound. LSQ scales the step-size gradient by `g = 1 / sqrt(N_W * Q_P)`, where `N_W` is the number of values sharing a step size.

Here each output row has its own step, so `N_W` is that row block's input width. The implementation uses symmetric bounds `[-Q_N,Q_P]` with `Q_N=Q_P=7` for Q4 and `Q_N=Q_P=127` for Q8, matching the transport's valid code ranges `[-7,7]` and `[-127,127]`. The represented forward retains the current exact nearest-even row quantizer. Weight gradients use the existing identity STE, without LSQ's clipped weight gradient. This is an LSQ-inspired scale-gradient component, not a full reproduction of the paper.

Learned steps initialize from the exact fixed-arm absmax steps (`row_absmax / Q_P`, with the existing smallest-positive-float32 handling for nonzero rows). The learned arm therefore starts with the same codes and represented weights as its fixed-scale control. The paper's mean-absolute-value initialization is deliberately not used because it would confound scale learning with the starting representation. Both arms retain the same latent-weight STE and all other recipe controls; optimizer updates to scale parameters are the intended treatment.

Scale steps are direct FP32 parameters in the existing optimizer and scheduler. They follow the matrix's freeze status and use the base-rate non-Muon vector group, including AdamW under Muon. The current trainer has no vector/no-decay exception: the scale group receives the configured `--wd`. AdamW and Muon's vector group apply decoupled weight decay; SGD applies coupled weight decay. Checkpoint provenance records the optimizer, exact decay value, group and decay semantics, and the exact-export consumer validates these against checkpoint arguments. Nonfinite steps raise an error. A negative step after an optimizer update is reset to the current row `absmax / Q_P` with the same positive min-subnormal floor as the existing fixed quantizer (zero for an all-zero row); `torch.finfo(float32).tiny` is min-normal and is not used. An all-zero latent row has step zero. If that row later becomes nonzero, its first forward initializes the step from its current `absmax / Q_P` using that same floor. Inference export excludes the learned parameter names and emits only effective weights plus exact represented codes and scales. Epoch continuation stores raw learned steps and optimizer state with the latent model.

The trainer registers scales from the selected QAT preset before strict continuation-state loading. `resume_contract` includes `qat_learn_scales`, so a changed arm fails contract comparison; the model, optimizer slots, EMA and SWA states are then restored through the normal epoch-state path. `FastEMA` deep-copies the registered parameters and updates all model parameters; PyTorch `AveragedModel` likewise wraps the configured model and therefore carries the row scales. Inference export is performed from the selected raw/EMA/SWA model and uses that snapshot's scales, while the raw continuation state retains the trainable scales and optimizer state. The focused actual-trainer integration check targets FastEMA resume/export; the unit check covers parameter cloning for both FastEMA and `AveragedModel`. Independent review should verify these call paths and add an SWA-continuation integration check before scientific promotion.

The inference metadata has its own versioned `scale_learning` block and training rule. The exact-export consumer accepts only matching metadata and arguments; fixed-scale and learned-scale checkpoints cannot be mislabeled as one another. Existing fixed-scale checkpoints and CLI invocations retain their prior path.

## Evidence status

Focused numerical, archive, and continuation tests are specified in `tests/test_training_qat.py` and `tests/test_evaluate_qat_deployment.py`; their execution remains pending the controller's test window.
