# Independent pre-GPU audit of the quote-clock auxiliary screen

Read-only code/doc review of `clock_reproduction/REPORT.md`, `GPU_SCREEN.md`, `replay.py`, `build_aux_cache.py`, `aux_class_index.py`, `verify_cache.py`, and current `scripts/train_rnn.py`/`scripts/predict_run.py`. No dataset scan or GPU run was made here.

## Algebra and leakage judgment

- `replay.event_index` keys each change in the 22 i0 price-code columns. `path` maps those code transitions with a decoder fitted on TRAIN labels only. A decoded quote event is an accepted transition with nonzero inferred ask or bid displacement. `midpoint_mean(..., "code", 8)` includes the next eight code-event midpoints; `midpoint_mean(..., "quote", 8)` includes the next eight accepted nonzero quote-event midpoints. Both start **strictly after** the current code event. The prefix-sum indexing is consistent with that definition and with the stated same-current-midpoint displacement.
- Eligibility invalidates any interval crossing an unknown code transition and requires an accepted current spread. The matched first-channel mask in `build_aux_cache.label_pair` is `code8_ok & quote8_ok`. Both arms receive the same code-clock horizon-24 channel and same fit row groups; `np.isfinite` equality is asserted before writing and independently rechecked by `verify_cache.py`. Non-class-3 cache entries are zero, and `train_rnn.py` multiplies their quote loss by a class-3 gate. The original main targets and masks remain present.
- The decoder learns spreads and transition directions from **fit TRAIN target labels**. It is a supervised training-label transformation, not a feature-only identification of physical quotes. That is allowed for an auxiliary training target. It fits no evaluation target or scoring mask. The `replay.py` diagnostic does read fold-2 validation targets **after** an eligibility gate to assess target-law alignment; fold 2 therefore contributed to choosing the 8-event head and cannot be claimed as fresh confirmation. The reports disclose this.
- The class-3 four-event reconstruction improves on the selected panel but still fails 36.54% of eligible clipped-target mass. It is a plausibility screen, not evidence of a score gain. The proposed GPU comparator uses the corrected 8-event clock against a same-decoder code8 control, with the 24-event auxiliary and finite masks fixed; that isolates clock definition better than comparing directly to historical E-251.

## Blocking conditions before the first clock GPU run

1. **Completed cache artifact absent at audit time.** `cache_f0_v3/metadata.json`, `aux_class_index_f0.json`, and `cache_verification_f0_v3.json` did not exist when checked. The class index and both paired caches must finish under the campaign resource cap. Run independent verification, confirm all fit row-group masks equal, all evaluation groups zero, horizon-24 arrays byte/equal-value identical, and compare recorded split/script/cache hashes before training. An earlier cache build exited 1 and another was interrupted; neither is usable.
2. **Trainer cache-root interface absent at audit time.** `scripts/train_rnn.py` currently reads only `cache/quote_path_{split}.npy` inside `Sequences.__getitem__`; the proposed `--quote-cache-root` argument is not parsed. Without an explicit path, both GPU commands would read the same historical cache and the experiment would be invalid. Add a narrowly scoped flag, pass it into both dataset instances, reject missing metadata/arrays, and persist the exact cache-root plus metadata and array SHA-256 hashes in each checkpoint. `predict_run.py` should copy that provenance into its prediction metadata even though prediction itself does not read auxiliary labels. The control and candidate must reference distinct verified roots.
3. **Batch-32 observed VRAM is near the limit.** The clean parent reached 4.563 GB device-wide. The additional auxiliary output head is small, but a monitored same-recipe batch-32 smoke or the first tightly monitored train steps must show total VRAM below 5 GB. An OOM or monitor stop is a resource failure, not a score result. Do not change batch size without a matched accumulation control.
4. **GPU runs must wait for shared CPU/cache pressure to clear.** The prior cache attempt was stopped as file cache approached the 36 GiB campaign cap while a GPU parent ran. Complete the cache and metadata checks with aggregate headroom before launching either 4-epoch arm.

## Nonblocking interpretation limits

- The fold-2 target-law panel and the choice of horizon 8 are adaptively selected diagnostics. Treat fold 0 as a screen and the next clean fold as a reproduction, with the existing chain/bootstrap and public-transfer discounts. All folds were historically inspected to some degree.
- The `class_and_ticks` lattice exception at TRAIN group 2315 is class 2. The proposed auxiliary builder excludes it only from the decoder/cache; the main model still trains on it in both arms, so paired training row provenance is intact. Preserve the exception and corresponding verification output.
- The current `predict_run.py` stores checkpoint/prediction/split hashes but no cache hashes. This is a lineage gap, not an inference leakage path, and is addressed by blocker 2.

**Verdict:** the mathematics and train/evaluation information boundary support a matched screen **after** the four blocking conditions are resolved. At the time of this audit, starting either GPU command would invalidate the comparison because the trainer lacks cache routing and verified cache files are absent.
