# Training throughput: measured fixes (2026-09-27)

Setup: fold-0 recipe (train+valid, prop_v1 weights, aux heads, true valid masks), batch 32 x chunk 2000,
GRU-128, RTX 3060 Laptop (sm_86), 4 loader workers, one job on the GPU. `scripts/perf_ladder.sh`:
5 warm-up + 20 measured batches per run, CUDA-event stage times, median, two runs per rung.

Cumulative: 1.48x vs the single-job baseline; ~6.6x vs the 15 seq/s observed with two duty-limited
jobs sharing the GPU (WNN_GPU_FRACTION 0.48 each). Loader wait at V5: 0.1-0.3 ms/step (not binding).

## Correctness (deterministic cuDNN, same seed, 4 batches = 40 optimizer steps, EMA recipe)
| check | loss max rel diff | weights rel L2 | verdict |
|---|---:|---:|---|
| reference run twice | 0 | 0 | deterministic floor |
| --sync-free | 6.6e-7 | 3.1e-6 | pass (summation order) |
| --prop-cache | 4.7e-7 | 3.3e-6 | pass; cache vs fresh on 16+16 random sequences: max abs 0 |
| --pin-memory (no persistent workers) | 6.6e-7 | 3.1e-6 | pass |
| --fast (all above + fused AdamW) | 5.7e-7 | 3.4e-6 | pass (tolerance 1e-5) |
| --precision bf16 | 1.0e-4 | 7.6e-3 | rejected (2000x larger drift, slower) |
Unit tests (tests/test_perf_parity.py): branchless true-mask weights = reference (rtol 1e-6) for
no/all/mixed/one-row masks; FastEMA bitwise equal to AveragedModel; stack+transpose loader bit-identical.
Pitfalls found: persistent DataLoader workers change the shuffle order (disabled); the propensity cache
must be built at batch >= 8 (cuDNN uses an fp32-like GRU path at batch 1-4, max diff 0.09); remaining
hot-path syncs were torch.tensor(QUANTA, device=...) per call (cached) and AveragedModel's
bool(n_averaged == 0) (FastEMA). Sync check: WNN_SYNC_DEBUG=error raises on any synchronizing op.

## Remaining bottleneck (V5)
GPU compute: GRU forward 132 + backward 158 = 290 of 321 ms per step (90%), cuDNN persistent RNN
kernels running 10 sequential 2000-step chunks. Input features 18 ms, labels/loss 8 ms, optimizer 1.6
ms, H2D hidden, loader not binding. Next levers change the recipe (batch 128 x chunk 500) or the
cell (parallel-scan RNN) and need a quality check.

## Usage (fastest single-GPU run)
    WNN_GPU_FRACTION=0.9 WNN_LOADER_WORKERS=4 WNN_CPU_PCT=60 WNN_MEM_MAX=20G \
      scripts/limited .venv/bin/python scripts/train_rnn.py ... --fast
(--fast needs cache/propcache_<propensity>_{train,valid}.npy: scripts/cache_propensity.py <name>;
set WNN_GPU_DUTY < 1 only to deliberately share the GPU.)
